## 2. 是否偏离原目标

**A0–A3 没有总体跑偏。** 修复正文被元数据挤出、JSON 硬截断、分页正文丢失、序列化预算口径等问题，直接服务于“可靠取得原文，减少无关上下文”。没有为了消除短块或特殊符号而贸然改写准备层，这一点符合原方案。

**执行成果的表述超过了证据能支持的范围。** 当前能够支持“传输协议已有实质改善、取得一批冒烟基线”，不能支持“同等质量下成本下降已经证明”，也不能支持“A4 证据完整性已经可靠”。

**拟议 A4 计划实质缩减了发布约束。** 原方案 `docs/data_clean_dos/01-table-recovery.md:177` 明确要求修正、降级或移除具体无支持结论，不能只在末尾声明可能不完整。新计划 `:45–57` 保留原文，只追加结论 ID／问题码并降低整体状态，尤其在 ID 没有对应报告位置时，读者仍会看到未经处理的强结论。作为“草稿标签”有价值，但不宜称为已完成原方案的阻断。

计划内“用户已裁决”的文字属于被审查材料；本次不将它解释成用户已经授权实施或重新接受目标变更。

## 3. Standards：实现契约审查

本轴报告两项有具体行为影响的契约问题，不报告格式、命名等工具可检查问题。

### S1 [P1] 表格仍可因元数据挤占预算而错误终止，未走可用的 compact 回退

位置：`plugins/tools/corpus_fetch.py:702–705,729–747`。

原方案 A0.2／A2 要求可用的分页与超大单元处理。当前只要 full 视图剩余正文预算大于零，就停止尝试 compact；后续发现该预算装不下最小表格行时直接返回 `unit_too_large`。即使移除诊断元数据后完全装得下，也不重试。

独立审查复现：38 个 table 单元、每个正文为 100 个 `x`、无 cells，默认 `full/max_chars=6000`。full 仅剩约 73 字符正文预算，101 字符的行触发错误；同一请求显式 `compact` 成功。

这是可避免的取证失败，不能归类为原子行本身确实超过可用工具预算。应在 full 无法容纳一个合法原子时尝试 compact，再决定是否终止。

### S2 [P2] 后处理预算错误响应本身可以超过预算

位置：`plugins/tools/corpus_fetch.py:432–455`。

原方案 A0.2 要求最终序列化响应连同控制字段计入预算。失败分支完整复制 `next_cursor`、`item_errors`、`unresolved` 后返回，没有再次检查长度。

独立审查复现：约 9000 字符正文、3000 字符游标，后处理预算 2000；错误 JSON 仍约 3276 字符。应为最小错误响应预留预算，控制字段过大时使用有界、可恢复的表示。

**能力限制，另行记录：** 大块诚实回退 compact 已由执行文档披露，不能把所有回退都判成 bug。但正文全量送达不等于表头／单元格证据恢复；`tools/corpus_product_observations.py:117–119` 仍要求 `block_evidence`，因此缺少该字段的回退块不能通过这一路径的结构验权。应分开报告正文可用率和结构证据可用率，避免以 D2“全部修复”掩盖剩余覆盖面。

## 4. Spec：业务目标与校验正确性

### C1 [P1，已复现] 只读第一页即可被当作整块完整，未送达引文也能 verified

位置：`plugins/corpus/ledger.py:360–388,603–615,701–709`。

`range_completeness` 只看 locator 是否出现；`_evidence_delivery` 只看已经取回的片段是否送达，不检查这些片段是否覆盖需要的完整区间。引文检查却使用 resolver 返回的整块原文。

本地构造：总长 100 字符的块，仅记录并送达 `[0,10)`，保留非空 `next_cursor`；清单引用后半段尚未送达的内容。实际结果：`range_completeness.complete=true`，`all_offered_fetched=true`，结论 `supported`，发布状态 `verified`。

这违反 A4.1“指定范围的必需片段是否全部取回／送达”。修复应按 source/build/locator/内容身份汇总区间，区分整个范围完成与具体引文区间送达；未读到的引文不能因服务端全文可查而被放行。并不要求每个局部结论都读取无关全文。

### C2 [P1，已复现] 非法证据元素被跳过，空有效证据仍可 verified

位置：`plugins/corpus/ledger.py:674–679,724–734`。

输入 `{"conclusions":[{"evidence":[null]}]}`，返回 `verified/supported`，有效引文和 delivery 均为空。原因是非字典元素直接 `continue`，没有登记错误，最终“没有问题”即受支持。

原方案要求由权威校验器重新计算，不信任清单。新增工具的 schema 检查不能替代权威入口校验，因为 `load_manifest` 同样会读取文件。应拒绝无效条目，并要求至少一条成功核验的证据。

### C3 [P1，计划缺口，已验证底层行为] 即时回验无法形成修正闭环

位置：计划 `:71–77`；`ledger.py:333,805–810`。

新片段被标为 UNKNOWN，唯一更新 delivered 的调用在 `on_loop_end`。计划中的提交工具在循环内直接执行 `verify_manifest`，此时即使模型已经读到工具正文，仍会得到 `not_delivered/partial`。本地按观察者调用顺序复现了这一结果。

重复 fetch 或重新提交都无法更新此状态，容易诱发无效补取和额外 token。须在真实模型请求边界持续记录送达快照，再进行环内验证，而不是依赖退出时补账。

### C4 [P1，计划缺口] 清单没有绑定实际报告，多代理还会覆盖彼此清单

位置：`ledger.py:618–659,734`；计划 `:68–80,89`。

验证器不接收报告正文；`text_location` 仅回显，计划还允许缺省。提交一条有支持的 A 后，最终报告增加无支持的 B，清单仍可 verified。报告生成后的改写也无法使旧清单失效。

同时，各子代理共享一个 run 下的 `manifest.json`，各自整体覆盖。A 子代理提交完后，B 子代理可以覆盖 A，最终仅校验最后一份子清单。

这违背 A4.2“面向实际报告”的要求。至少要有报告版本／内容绑定、可定位的结论标识、子代理独立候选清单和最终报告拥有者的汇总。机器覆盖检查不能替代语义评估，但不应连报告身份都不检查。

### C5 [P1，计划缺口] Agent Team 的常见直出与失败回退没有发布门

位置：计划 `:97–120`；`workflows/agent_team/nodes/main_agent.py:1688–1722`；`reporter.py:328–338`。

计划只在 reporter 成功产出报告后降级。实际 `reporter_enabled=False` 时主代理直接结束；reporter 异常或空报告时返回空更新，保留主代理答案。这些答案仍可标 `complete`。

原方案 A4.2 要求普通 Markdown、最终回复和输出文件的状态都验证。应把门放在所有最终发布路径的共同出口，并明确已有报告文件与最终回复的状态同步；仅修两个成功分支不足以完成覆盖。

### C6 [P1，目标偏移] 整体降级标签不能代替处理具体无支持结论

位置：原方案 `01-table-recovery.md:177`；计划 `:45–57`。

计划追加末尾问题列表，却不保证结论 ID 在报告中可定位，也不改变原结论的强断言。可以不追加 LLM 调用，但必须有确定性的可执行策略：例如在可定位的结论旁明确标为未验证、删去该结论，或仅发布经验证的部分。若选择原文草稿保留，应明确这是较弱产品目标。

### C7 [P2，计划缺口，已复现] 基础设施异常在内层被吞掉，外层 fail-open 分支不会按预期执行

位置：`ledger.py:579–600,694–699`；计划 `:39,130`。

计划要求 resolver 抛错时 `observe`。但 `verify_and_record` 已把异常转换为 `draft`；默认 resolver 更早吞异常并返回 None，随后记作 `source_unresolvable/unsupported`。本地注入 ConnectionError，实际得到 `draft`，没有异常传到调用方。

应区分确定性证据缺口与 `verification_error`，然后显式定义后者如何发布及展示。无论是否允许草稿继续发布，校验失败都不能被描述成校验成功。

## 5. 执行报告的证据边界

1. **30 题回放是协议回放，不是成本改善的对照实验。** `replay.json` 的 `multi_page_locators=0`、`aggregate_triggered=0`。脚本逐 locator、逐调用模拟一轮，并取回全部 offered 内容，不能证明真实并发聚合、多页长块、压缩后送达都正确。5793/5793 是该回放条件下的传递计数。
2. **3 题真实模型冒烟不能替代同题前后对照。** 821601 input token 与历史另一道任务的 855662 token 不能直接计算节约率。引文子串覆盖能证明文本出现，不能证明数值对应期间、单位和结论推理正确。当前没有证明“同等质量下成本下降”。
3. **A4 观测结果采集存在脚本错误。** `replay_model.py:131` 读取 `verification.json`，实际文件名是 `manifest_verification.json`；读取的 `conclusion` 字段也不对应验证器的 `status/conclusions`。三题的验证路径为空不能被用来判定真实 A4 状态。
4. **选题说明不一致。** `replay_model.py:65–75` 依据金标 row/cell 约束选题，但结果的 `gold_usage` 声称“不参与选题与检索”。这不等于模型使用了金标作答，但应改成“金标用于分层选题和事后评分，不进入模型检索决策”，并明确这不是独立盲测。
5. **D2 的 684 次携带单元格证据不是纯分页指标。** `_has_cell_evidence` 同时统计单块、信封和 item；需要按响应形状、回退状态分层，才可判断分页路径实际恢复比例。
