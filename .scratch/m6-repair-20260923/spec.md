# M6 修复范围与重验口径

授权：用户在本线程要求“根据你的方案，执行修复计划”。本轮修复上轮审核报告的三项 P1；不代替业务放行签认。

1. 所有加入权威正文的上下文单元必须验证内容哈希；不同消费者共用校验和正文/spans装配。
2. 正式 chunk fetch 与 band fetch 使用同一结构上下文投影，授权检查、主单元、补充单元取自同一REPEATABLE READ只读快照。返回 authority_rev=authority-context-2、context_unit_ids；source_ranges仍指原chunk投影，不伪造补证区间。未知句柄、撤销、跨build、坏哈希继续拒绝。
3. 观测采集只接收query_id/text，调用实际注册 corpus_search/corpus_fetch；默认limit=10，最大20。搜索/取证失败记FAILED；仅真实空hits记NO_MATCH。不向采集层提供正负例标签，不为评分添加工具未返回的块、文本或行列标签。

评分器、金标、阈值、索引版本、拒答开关默认值不修改。统一执行三种清晰分开的配置：

- **产品默认验收**：原题干、limit=10、abstain=off。正式主结论取此配置。
- **显式OR诊断**：所有30题同样按zhcfg词元OR改写、limit=20、abstain=off。只衡量工具接受显式OR查询的效果，不冒称默认效果。
- **既有限制复验**：原题干、limit=10、abstain=on。保留已签认的正例误拒限制；负例真实执行。

三套输出均不据标签选分支，原评分报告保留为历史实验，不覆盖。低分原样报告；实现缺陷关闭不等于95%业务门达成。本轮不扩大为检索策略重新设计、模型语义测试或留出调参。
