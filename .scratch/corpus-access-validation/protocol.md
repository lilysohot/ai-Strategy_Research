> 版本：v1 · 2026-09-29。状态：E1 产出，**待确认后冻结**（E5 开始后不可修改，修改须走 §9 变更记录）。
> 从属：[总览 §主目标](../../docs/data_clean_dos/README.md#主目标完成判定的唯一依据)、
> [03 §2 执行顺序](../../docs/data_clean_dos/03-end-to-end-validation.md)、[03 §5 收口条件](../../docs/data_clean_dos/03-end-to-end-validation.md#5-总任务的收口条件)。

## 1. 支持范围声明

以下维度在本节声明后，作为全部验证的唯一判定范围。范围外文档、版式或配置
**不计成功、不移出分母**；数量是采集起点，覆盖不足不得声称普遍性已验证。

| 维度 | 声明 |
|---|---|
| 研报类型 | 公司点评／行业景气／宏观叙述（与开发集三类一致） |
| 机构 | E2 定稿冻结（采集起点：≥3 家机构；具体清单以 `samples.jsonl` 为准） |
| 版式（高风险项） | 单栏／多栏、首页信息框、正文与标题混排、单格真实表格、合并表头、跨页续表、单位／脚注、风险文字、特殊符号；每项声明支持的版式 ≥2 份独立文档 |
| 运行配置 | 主部署模型 × `stateful-react-agent`（主验收矩阵）；若声明支持 `agent_team` 则两条路径分别验收；候选每题 3 次独立运行 |
| 语料版本 | 固定 build 对比：基线 build（当前生产）vs 候选 build（含 B1 reader-pdf-7 + B3 chunk-4）；build 身份逐题记录 |
| 不支持项 | 扫描／图片区域无法提取的，记录为支持缺口，保留数量与原因，产品可见提示 |

范围外与暂不支持项在验收报告中单列，不计入分母，也不从分母移除。

## 2. 目标（target）与证据字段

每个目标从**源 PDF 页**建立，字段构成评分侧证据集（E2 产出，执行侧不可读）：

| 字段 | 含义 | 约束 |
|---|---|---|
| `target_id` | 目标唯一标识 | 稳定、可复核 |
| `doc_identity` | 文档内容身份 | 内容哈希，非文件名 |
| `source_ref` | 页码／区域 | 精确到页与区域描述 |
| `verbatim_quote` | 源页原文逐字引文 | 非空白字符逐字；含必要空白变体记录 |
| `subject` / `metric` | 主体／指标 | 无数字的关键风险／假设同样建目标 |
| `period` / `unit` | 期间／单位 | 作为独立依赖目标进入九层链路 |
| `header_refs` / `row_labels` / `footnotes` | 表头／行标签／必要脚注 | 缺失即目标依赖不完整 |
| `acceptable_evidence` | 可接受的证据组合 | 允许跨块组合；逐字引文或等价可核验引用 |
| `question` | 对应任务问题 | 正常用户口吻，不注入 locator／证据 |
| `required_dependencies` | 回答所需依赖目标 id 列表 | 判定 `answer_supported` 前置检查 |

对照源页核查旧提取与新提取；**不能仅以二者字符数相等判定完整**。
`chunking_impact` 历史统计字段保留，不重写历史归因记录。

## 3. 九层判定链路

每个目标在每次预定运行中逐层标记，附 `evidence_ref`（源页/单元 id/账本记录/trace 消息序号）：

| 层 | 判定 | 机器判定方式 | 失败归属 |
|---|---|---|---|
| L1 `source_present` | 源页存在目标内容 | 证据集逐字引文与源 PDF 页对照 | —（前置） |
| L2 `extracted` | reader 产物包含该内容 | 清洗前 unit 原文与源引文按非空白序列对齐 | reader |
| L3 `clean_retained` | clean 后可检索视图仍保留 | clean 产物中可定位到引文；误排除记失败 | clean |
| L4 `tool_reachable` | 离线定点查询可取回 | 定点诊断脚本命中；**诊断用，不计模型自然检索成功** | 检索索引 |
| L5 `offered` | 正常流程检索提供了含目标候选 | 账本 `offered` 集合含目标所在 locator；**不得以整篇文档计入 offered** | 检索 |
| L6 `requested` | 模型实际请求该范围 | 账本 `requested` 含该 locator 或其覆盖区间 | 模型使用 |
| L7 `fetched` | 服务实际取回 | 账本 `fetched`；分页须游标走完或显式 `unresolved` | 工具/预算 |
| L8 `delivered` | 最终模型输入含目标及必要依赖 | 解析 trace 最终模型请求，目标引文与依赖（表头/期间/单位/脚注）逐字或等价片段实际在输入中 | 送达/截断 |
| L9 `answer_supported` | 回答正确且引用可核验 | 数值、主体、期间、单位与引用依据逐项核对；允许正确释义 | 回答/使用 |

L8 是硬性层：**账本或 A4 `verified` 不能单独替代评分**；内容已送达但答错归因使用环节，
不能冒充数据通过。L4 失败但 L5–L9 通过的情形照常计成功；L4 通过不计入 L5。

## 4. 预算约定（冻结值）

每题独立会话，以下预算在运行前固定；**预算耗尽记 `failed(budget_exhausted)`，
不自动追加直至成功**。数值在 E5 冻结前可调整，调整须记入 §9。

| 项 | 冻结值 | 依据 |
|---|---|---|
| LLM 轮次 | ≤ 40 轮/题 | 冒烟基线 27 轮/3 题，留余量 |
| 墙钟 | ≤ 30 min/题 | F4：thrashing 案例 1240.7s 无进展 |
| input token | ≤ 2,000,000/题 | F4：1.45M input 已属异常重提 |
| output token | ≤ 100,000/题 | 冒烟 27k/3 题 |
| 工具调用 | ≤ 60 次/题 | 冒烟 32 次/3 题 |
| 每题工具有效预算 | 沿用产品默认（ReAct 后处理 6,000 字符、单轮聚合 200,000 字符） | 不得为验证改写预算路径 |

模型冒烟与正式实测均从并发 1 开始。

## 5. 样本与隔离要求

- 开发回归集：现有 6 来源／30 题；留出集：≥12 篇未参与调参研报、≥3 家机构。
- 同模板、同报告修订版、重复 PDF 按同组划分；修规则只允许用开发集，留出内容不参与。
- 留出失败导致修规则时：该批转为开发回归集，另补新留出批；保留首次失败结果、
  数据集版本与修改原因。
- **评分隔离**：证据集由评分进程持有；执行代理不可经文件、shell 或工具读取评分答案。
  运行时设置可验证的文件访问边界（参照 FrontierSearchBench 的 OS 级读边界）并留记录；
  仅提示词要求"不看答案"不满足隔离。受保护评测答案继续不参与本任务。
- 模型只接收正常用户问题与产品默认检索流程；评估侧不注入 locator、引文、答案或定制查询。

## 6. 成功标准（对应 03 §5，不得事后放宽）

1. 范围与矩阵冻结（§1），各声明支持类型均有独立验证与逐题源页证据。
2. 已知关键内容误删、结构损坏和映射失败在支持范围内修复（E3 清单闭环）；
   开发回归无新增关键失败。
3. **独立验证中，所有预先指定的关键目标及其必要依赖，在每次预定运行中 L1–L9 全通过**；
   超时、未运行、缺数据、`unknown` 均不计通过。其他目标逐项报告；
   支持范围内未解决的获取或正确使用失败阻止总任务完成。目标分级只用于排修优先级。
4. E4 分层判定能解释所有失败；不存在「源页有、清洗产物无、模型仍自信作答」的未处理情形。
5. 质量达标后比较成本与预算，给出基线／候选取舍及生产发布建议；
   隔离回滚证据（B4.3 五项契约）可复用，后续修改影响其契约时补跑。
6. 成本报告包含所有尝试的调用、token、延迟与失败；chunk 数下降只作辅助指标。

阶段状态可记录：`计划完成`／`开发回归通过`／`独立验证未通过`。
文档签认、文件存在、工作移入 backlog 均不构成总任务完成。

## 7. 产物与复核

| 产物 | 产生步骤 | 复核方式 |
|---|---|---|
| `protocol.md`（本文件） | E1 | 判定均可由源页 + 运行记录复算 |
| `samples.jsonl` + 覆盖矩阵 + 证据集 | E2 | 来源去重、源页核验记录 |
| 缺陷清单 + 最小回归用例 | E3 | 每条修复有 revision 与候选 build |
| 分层评分器 + 失败轨迹 | E4 | 在开发集上能发现漏提取/误清洗/漏检索/截断/错用结构 |
| 逐题轨迹 + 冻结清单 + 独立实测结果 | E5 | 基线与候选同题同预算对照 |
| 验收报告 | E6 | 含样本量、覆盖范围、剩余限制、失败全量 |

运行工件沿用 `<APODEX_RUN_DIR>/`（trace.jsonl、corpus/ledger.json、manifests/、
manifest_verification.json）；评分脚本与逐题判定结果放本目录。

## 8. 与 A4 的关系

清单机制（`corpus_submit_manifest`／`publish_boundary`）的环内 `verified` 是观测信号，
**不替代本契约的 L8/L9 评分**。报告锚点 F3 与行为方差 F4 继续跟踪；
A4 默认阻断是独立产品决策，在 E6 之后评审。
