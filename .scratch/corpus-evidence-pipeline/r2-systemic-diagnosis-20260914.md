# R2 系统性诊断：失败节点、证据边界与设计决策

日期：2026-09-14。范围：只读检查、内存反例与已有 development 产物回放；新增模型调用 0。
未修改生产实现、金标、历史评分或预算；不读取 holdout 原文、不入库。

## 判断

建议保留 EvidenceRun、来源版本与坐标、结构分段、JSONL、逐项容错和有限义务路线，对 R2 的抽取契约、
字段决策和验收编排做有边界的重设计。证据不足以支持取消材料理解需求或推倒整个项目，也不支持
“只补评级即可完成 R2”。v13 停止条件继续有效；本诊断不构成新模型轮次授权或历史放行。

最深层问题是职责与验证错位：系统已经知道来源范围，却要求模型重新选择证据；有些无法确定的
语义被规则直接补成确定值；评分器验证了引文命中及字段标签，却没有充分验证内容忠实度。开发中的
评分改善因此不能直接等同于完整业务能力改善。

## 1. 历史链路与错误节点

| 阶段 | 关键现象 | 归因与当前状态 |
|---|---|---|
| 整包 JSON | 枚举非法、截断导致整包失败 | 传输协议与容错粒度；JSONL 和逐记录处理有证据支持 |
| 结构分包 | 更换分包后分数仍波动 | 包完成不等于命题完整；结构保留必要但不充分 |
| 候选槽位 | 成功包仍漏项，槽数超过输出容量 | 缺少有限且容量可行的义务；小批次改善了协议完整性 |
| v11 | 6 条有效 item 因漏槽 ID 丢失 | 语义已生成，结构标识校验丢弃；唯一引文回绑可恢复 |
| v12 | 37/37 终态，旧 scorer 33/35 | 短引文身份匹配与评分口径不一致；新口径可定位 35/35，但字段仍失败 |
| v13 离线 | 同一 v12 原始响应重放达到 v2 门 | 证明对这些已知响应的规则修正有效，不证明泛化 |
| v13 实测 | 36/37 终态，34/35 item | 重复短引文在槽位解析前被拒；另有铜箔总结语义退化 |
| 本次复核 | 内容错误与台账错误能绕过 item scorer | 验收基座存在独立缺陷，不能只处理最后一个丢项 |

来源未入库、没有“专家”标签、文档不可读，均不能解释最新失败。最后一次缺失发生在公司研报，且
对应内容已出现在模型响应中。

## 2. 直接卡点：定位域与校验顺序不一致

真实路径为 `_packet_records` → `_align_quote` → 读取 candidate_slot_id → 检查槽位边界。
`material_semantics.py:1500` 先执行 packet 级引文定位，下一行才读取槽位 ID。

对 v13 的评级响应做最小复现：只保留这一条 item 和一个冻结槽位，连续两次结果相同：

```text
input_items=1, output_items=0, discarded=1
packet_occurrences=2, slot_occurrences=1
ValueError: evidence quote is not uniquely aligned
```

仅在内存中把对齐域限制到已指定槽位、再换算回 packet 坐标，原始响应即可保留 1 项，且坐标逐字
回取正确。未改模型响应、未调用模型、未改文件。

但是旧 v2 scorer 仍将该恢复结果判为证据失败，因为 `evidence_is_unique` 额外要求引文文本在整个
packet 中只能出现一次。**只修抽取器还不够，证据身份契约与评分器必须一起澄清。**

需要区分“坐标能唯一定位一段原文”和“某个字符串在整包仅出现一次”。固定 source_rev、packet、
start/end 可以定位重复文本；字符串重复本身不等于出处不明。若维持旧字符串唯一契约，则系统需
预先生成带足够上下文的唯一锚点。任一方案都应版本化，不能追溯改写 v13。

## 3. 更优先的卡点：评分器不能充分否证错误

本次使用原 scorer、原 policy、原微型金标进行内存变异检查，未改任何历史产物。

| 检查 | 实测结果 | 意义 |
|---|---|---|
| 将所有 item.text 改成原文不支持的陈述，重新计算合法 run hash | scorer 仍 passed，未支持陈述 precision=100% | `text` 忠实度未被评分；该指标只是 matched/predicted |
| 将全部槽位台账改为 partial，重新计算合法 run hash | item scorer 仍 passed | item 门本身不检查终态；需要真实可执行的组合门 |
| 注入 35 个证据错误，只隔离考察 critical_errors=0 这条阈值 | 该阈值仍通过 | 所有阈值均使用“小于则失败”，错误数量上限方向写反 |
| 完整策略下相同 35 个证据错误 | evidence_unique_alignment 将结果拦住 | 本次 v13 失败未被上述错误数量漏洞放行，不能误报为历史验收已被绕过 |

代码：`verify_material_item_contract_v2.py:136`（字段评分）、`:329`（unsupported precision）、
`:333`（统一阈值方向）。

此外，unknown_fields 只考察所需未知轴是否被列出，不检查多列的未知是否合理，也不充分核查字段
已填值与 unknown 的矛盾。仅有未知轴 recall=100% 不能证明“未知诚实率=100%”。

因此此前“其余核心字段全部通过”应严格理解为这些已匹配条目在冻结标签评分下通过，不能解释为
全文内容忠实、无臆测、条件文本保留或全部语义已经可靠。

## 4. 字段归一化越过了证据边界

对当前真实函数输入最小反例，得到：

| 原始输入 | 系统输出 | 风险 |
|---|---|---|
| claim 极性 unknown，文本表示暂时无法判断 | affirmed | 未知变成肯定 |
| risk 极性 negated，文本“不存在流动性风险” | affirmed | 否认风险被直接改成肯定 |
| 无日期复盘行为，时间 unknown | contemporaneous | 单凭材料类别赋予行为时间框架 |
| 数值 999 亿元，证据只说收入增长 | 保留 999 亿元 | 正则未识别时接受模型值，没有通用证据核验 |
| 专家说开场欢迎语 | speech_role=answer | 说话人角色被当成话语功能 |
| 投资者作事实陈述 | speech_role=question | 陈述被当作提问 |

位置：`material_semantics.py:1149`、`:1187`、`:1224`、`:1277`。
这些是实际可复现的边界反例；尚未声称它们已经在未访问的其他研报中造成错误。

系统可以拥有坐标、身份约束和经过验证的值转换，但语义判断仍需证据或显式保持未知。用确定性
代码实现一个猜测，并不会把它变成确定性事实。

## 5. “原子义务”目前仍只是有限文本槽

输入三家公司的三个并列陈述，当前结构器仍生成一个槽；一槽最多一个 item 因而不保证一槽恰好
一个命题。强制一对一只能避免输出重复，不能证明来源中其他命题没有丢失。

当前开发来源范围共生成 549 槽：公司 41、行业 51、个人复盘 15、铜箔 442；v13 只选择其中
7+14+6+10=37 槽。该缩小范围是合法的微实验，但 35 个金标 item 的命中不能外推为整页、整份材料
的覆盖。还有“一个较长总结算一个 item”与“每个独立命题各算一个 item”的粒度差异需要明确。

下一版需要独立衡量来源范围覆盖、候选命题覆盖、每个义务终态，以及有效产物的忠实度。

## 6. 跨类目保护尚未闭合

同一 item v2 scorer 重算 v12 与 v13：

| 范围 | v12 | v13 | 变化 |
|---|---|---|---|
| 公司推荐段 item recall | 7/7 | 6/7 | 退化 |
| 铜箔总结 semantic_type | 1/1 | 0/1 | 退化，被总体语义分掩盖 |
| 行业问答 semantic_type | 12/14 | 12/14 | 未改善 |
| 个人复盘 semantic_type | 3/4 | 4/4 | 改善 |

381 个 corpus 测试通过只能支持其实际覆盖的工程行为稳定。之前将测试通过概括为“其他已验证
类目不受影响”，证据不足，应予纠正。

原非回归策略绑定旧 scope/旧评分版本，不能直接替代当前 item v2 的逐类比较。执行器也没有调用
`check_non_regression`；v13 预算写入的 extractor/policy/scorer SHA 并未都被执行器代码强制验证。
预算记录与门禁执行应成为同一条可审计链路。

## 7. 关系：有可保留的进展，也有尚未验证的边界

本次在已有 v13 零模型回放的完整 35-item 产物上，按实际 packet 范围运行候选对生成器：17/17
已标注正关系均进入候选集合。因此“候选生成目前根本无法覆盖关系金标”这一假设被否证。

该结论只证明候选可达，不证明模型能正确判断 present/absent，也不证明误建率或其他材料泛化。
这 17 条金标只有 answers、supports、challenges 三种，而 R1 定义了八种关系。当前生成器的
allowed_type 只有四种（另有 motivates）；conditions、invalidates、attributes、elaborates 尚无
对应候选生成路径。应明确先验收哪些关系，避免把未支持类型放入完整验收承诺。

尤其不能将引用词或相邻位置直接当作作者论证关系；候选只能是待判问题，不能作为已证实关系。

## 8. 推荐的有边界重设计

保留：EvidenceRun、source_rev、locator、结构分段、JSONL、逐记录容错、有限批次、审计记录、
开发与留出隔离、失败保持 partial。

重设计以下接缝：

1. **证据身份**：系统为义务提供稳定 source span/anchor；模型输出 obligation_id 和语义字段。
   坐标定位与引文显示分开。选错、越界、来源漂移仍须拒绝。
2. **义务粒度**：来源片段和语义命题分层。对尚不能确定原子粒度的片段显式标记未解决；增加
   合并、拆分与遗漏反例，不把规则切出的一段自动宣称为完整原子命题。
3. **字段来源**：区分直接观察、规则转换、模型判断、未知。规则转换不得凭材料类型、说话人身份
   或单个词给出未经支持的语义。
4. **验收组合**：分开身份完整性、协议终态、内容忠实度、字段语义、关系、跨类目非回归；每层
   独立可失败，所有必要层通过才放行。修复阈值方向与绕过反例，先证明 scorer 能拒绝错误。
5. **降级产物**：证据可读但语义/归属不明时，保留可回取片段与明确未知供研究读取，完整语义
   验收仍保持未通过。若采用这一产品交付方式，需要前瞻定义其独立验收，不能据此降低旧 R2 门槛。

## 9. 下一步应如何投入

先完成零模型的评测与接口方案：上述故障反例必须能被自动拒绝；重复引文在稳定坐标下能正确
回取；改变顺序、增加前文、换角色标签、缺失日期、增加并列命题时，结果不会偷偷变成确定值。
将 v10—v13 已知失败作为开发回归资产，同一评分器和相同范围逐类比较，保留历史结果。

只有这些门通过后，再决定是否冻结新的、有限模型实验，并预先约定成功标准和终止条件。新材料
可改善格式覆盖，但应在规则冻结后作为新的验证样本使用；目前无需靠不断新增电话纪要来解释系统
校验问题。现有证据不能给出“再优化几次必过”的可靠承诺。

最终选择：继续 R2 的业务目标和证据驱动路线，重新设计局部语义协议与验收闭环。停止现有的
“发现一个样本错误—增加一条规则—再跑同一批模型”迭代方式。
