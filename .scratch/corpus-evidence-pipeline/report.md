# Corpus 证据链实现与小范围可用性试验

后续更新：本文件保留首次试验时的结论。正文 0/2 与通用 preflight 入口问题已在任务 07 定点修复；最新验收见 [正文修复报告](prose-repair-report.md)。全库覆盖与宏观自动计算仍未放行。

日期：2026-09-12。结论：受控财务表格已跑通源文件→证据→事实→校验→存储/取回→推导的影子闭环；正文真实模型试验未通过，不能宣布全库已具备自动推导能力。任务清单见 [spec.md](spec.md)。

## 1. 已构建的链路

`源文件 → 版本化解析 → EvidencePacket → ClaimRecord → 质量门禁 → 可计算投影 → 版本存储/取证 → Calculation`

| 模块 | 本轮落地 | 合理性边界 |
|---|---|---|
| ingest | 不再删除孤立整数；MD 标题与 Word 表格保留 | 旧库未重建，修复只影响后续解析 |
| evidence | 源/解析版本、完整 PDF 文字层、MD 原文偏移、DOCX 元素定位、PDF 表格行列 bbox/单位来源 | 几何表格适配面向年度财务预测表；不是通用 OCR/表格理解 |
| claims_v2 | 单一输出契约，完整数值 token，金额数值与单位同步归一，反算检查，真实单元格引用验证 | 准确引文不自动证明金融语义正确 |
| evidence_pipeline | 表格确定性抽取、正文可注入模型、failed/deferred/unknown 台账；指标/单位/主体/期间门禁与冲突隔离 | 只有受控指标进入计算；未知口径不猜测 |
| service | 独立 corpus_evidence_runs，内容 hash 验证、幂等保存、按版本与证据 ID 取回、备份恢复 | 不接管生产 blocks/claims，也不是大型分布式任务调度器 |
| derivation | 七种 Decimal 公式、输入事实 IDs、来源版本、期间与公式版本；可比性/除零检查 | 计算证明内部关系，不证明源报告本身真实或预测准确 |
| pilot CLI | 冻结字段核对、数据库往返、数值复算、来源比率差异提示、分项与总体验收门禁 | 非随机小样本，不外推总体准确率 |

新路径保留原始材料与处理结果，按来源 hash/解析版本/运行内容寻址；不会用“文件已经入库”阻挡新解析版本。源 PDF 文件仍保存在原位置，当前不是不可变原文件仓库。哈希是完整性校验，不是数字签名。

## 3. 金融推导结果

以下仅为所提供研报 2025A/2026E 数据的复算，全部标为 `source_forecast`，不是对公司实际业绩或投资价值的判断。源表金额单位百万元，内部归一为元；比率计算不受倍率改变影响。

| 公式 | 原表输入（百万元） | 结果 |
|---|---|---:|
| 营收增速 | 178657 / 172054 − 1 | 3.837749% |
| 归母净利润增速 | 84679 / 82320 − 1 | 2.865646% |
| 经营现金流变化 | 25756 / 61522 − 1 | −58.135301% |
| 现金利润比（此处定义为经营现金流/归母净利润） | 25756 / 84679 | 30.416042% |
| 净利率（此处定义为净利润/营业总收入） | 87841 / 178657 | 49.167399% |
| 资产负债勾稽残差 | 340489 − 55048 − 285441 | 0 |
| 利润归属勾稽残差 | 87841 − 84679 − 3162 | 0 |

七项结果均匹配独立数值预期；比率容差 0.000001 个百分点，两项残差要求严格为零。每个计算结果含 run_id、输入 fact IDs、输入 Decimal 值及公式版本，可从数据库按 ID 回取对应页/行/列证据。

有一个有价值的质量发现：原表 2026E 净利率列为 **50.2%**，而上述明确公式得到 **49.1674%**，差约 **1.0326 个百分点**。系统保留两者并输出 `review_definition_or_source`，没有自动修正源值。这可能是口径不同或源报告不一致，尚未裁决；不能仅凭提取正确就把源比率当作可信事实。

## 4. 正文试验与失败诚实性

配置模型为 glm-5.3-flash，使用项目已有端点，没有更换模型/账户。

1. 初次试验：2 个正文调用、0 条事实，暴露“空响应当空成功”的状态漏洞。已修正；这次报告的成功退出不能作为整体通过依据。
2. 简化 v2 契约、输出预算 8192、每次超时 60 秒复测：2 个正文调用均 APITimeoutError，整体退出码 1。
3. 缩为 600 字完整覆盖的证据包、预算 4096、只调用 1 包：仍是 response_incomplete；记录 prompt_tokens=937、completion_tokens=4096，其他 3 包 deferred，整体退出码 1。
4. 最终代码另做零模型调用的确定性重放：表格仍 57/57、公式 7/7；正文 deferred，整体通过标志仍为 false。没有用跳过正文来制造全通过。

已返回用量合计至少 prompt=6015、completion=8959 tokens；超时调用是否产生费用/用量未知，所以不是总成本统计。不能仅凭 completion 达上限断言全部花在 reasoning。更细的供应商诊断与真实正文验收已列入任务 07。

常规环境准备好后，在仓库 Linux 根目录执行：

```bash
uv run python scripts/corpus_evidence_pilot.py \
  --manifest .scratch/corpus-evidence-pipeline/pilot_manifest.json \
  --out data/corpus/.evidence/pilot --persist --prose-calls 0 --packet-chars 600
```

该命令不调用模型；由于正文目标未验收，预期退出码为 1。去掉 `--persist` 则不写数据库。模型测试需显式增加 `--prose-calls`，该预算按文档计。

业务调用的最小接口是 `build_evidence_run(path)`、`CorpusService.save_evidence_run(run)`、`load_evidence_run(run_id)`、`fetch_evidence(run_id, packet_id)` 与 `derive(run, formula, input_ids)`。例如最终茅台 run_id 为 `db03ebd071a4eff8ad96094c105bc0910eff245afd0b3d4c1f4f981ba5ddc157`。

## 7. 放行结论

可以继续用于受控财务表格的证据化研究试验：保留原值，按明确公式复算，主动暴露不一致。

暂不能用于无人复核的全库自动研究或回测：正文供应商链路、复杂版式、指标定义/报表口径、跨来源冲突、公开可知时间尚未通过充分验证。filename 日期是 known_at 候选，不是完整的时点可得性证明。后续先做任务 07 与 08，再扩样；本轮没有通过“提高召回率”掩盖这些限制。
