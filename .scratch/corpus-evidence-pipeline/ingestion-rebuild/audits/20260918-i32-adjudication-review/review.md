## 需要先修正的问题

### A1 / P1：第293行承诺的完整性门可跳过未决项

实际位置：`i3s2_verify_candidates.py::run_completeness_gate`。

1. 仅把30题 `adjudication.status` 改为 approved，保留全部36项 pending_human、原有缺标注、空 reviewer 等内容，结果仍为 ready=true、unresolved_decisions=[]。
2. 仅把原来列入 blocked_questions 的24题改为 approved，另6题保持未批准，也返回 ready=true、unapproved_questions=6。这6题包括3道 machine_ready 正例和3道没有“需全文确认”提示文字的负例。

原因：approved 分支直接 continue，跳过全部实质核验；最终 ready 只看 blocked 是否为空，没有要求批准覆盖完整。当前原始候选未误放行，但门的关闭条件不成立。

应改为独立核对：完整审批覆盖、各项裁决已经解决、有效锚点/补标、负例覆盖、人工状态冲突、审批者与依据；approved 不得免除这些检查。新增反例应覆盖空审批人、仍有未决项、缺题批准和负例未核实。

### A2 / P1：决策 JSON 尚未接入，模板不能表达全部裁决

文件第278—294行称另存 decisions.json 后由验证器复核。但当前验证器 main() 只读 QUERY_GOLD 和 CANDIDATES，没有读取/合并 decisions.json 的实现；目录内脚本搜索到的该文件名只用于生成文案与冻结说明。

此外示例只有 `item_id/decision/chosen/reason`，没有明确表达以下内容：

- machine_ready 三题的整题批准；其待裁决项为0，但不等于无需人工审核。
- §3六道负例覆盖结论、审阅范围与依据。
- §4 source-gold 人工状态矛盾的澄清。
- 无承载 item 时的新标注引用及其版本。
- 审批所针对的 candidates/source-gold/query-gold 内容哈希、题目/目标最终集合。

必须提供经校验的独立审批件→批准投影→完整性门路径；不能要求用户修改冻结候选来使状态通过。“驳回候选”不等于删除原题要求，“改选”也必须重新检查来源和覆盖范围。修好后新建冻结修订，不覆盖 r23。

### A4 / P2：36项清单仍不是完整语义覆盖账

生成器只有在 `if not strong` 时才为子句建立 qualification。因此一条子句既含数字又含限定时，限定可能不进入裁决队列。

实证：macro-003 原要求“报告称非农公布后市场预期概率超过60%，必须区分附条件判断、市场预期和正式决定”，当前该子句只有60%的 value facet；最后的区别要求没有独立 facet/answer_constraint。company-001 也只有4个数值 facet，没有独立列出“年度对应、维持强推、标明预测”等要求，尽管其当前完整引文支持其中部分内容。

这不表示每个数值题的引文一定缺内容，但意味着“36项都签了”不足以证明原要求都核验了。数值与定性要件应并行提取/登记，不应二选一；人工整题审核须对照完整冻结 requirement。

答案侧约束可以与取证指标分开，但要明确其后续核验落点；纯检索证据评分不应被表述为已检查生成答案的所有语义。

### A5 / P2：裁决材料展示和角色定义仍不够明确

- company-008 三个 source_coverage 项要求指定 item，裁决单却没有在这些项下展示两份来源的评级锚点。候选中已有，应直接显示完整 quote/source/locator，不能让 U 再去 JSON 中找。
- `supporting=可替代` 当前容易误导：验证器只把 required+suggested 放入模拟金标，没有替代关系。company-005 的型号列表不能替代商业化阶段句；company-001 的表格 EPS 不能替代目标价/评级。应称“补充/非必需”，真正可替代的目标需明确同一要求下的等价证据组。
- 表单首段仍用“60条”旧数，当前是54条候选目标；分母规则已经修正，建议同时清除旧批次数字。
- 页面应明确“36项要件裁决 + 24题正例整体验收 + 6题负例覆盖 + 1项来源状态澄清”，不能误以为总共只填36项。
