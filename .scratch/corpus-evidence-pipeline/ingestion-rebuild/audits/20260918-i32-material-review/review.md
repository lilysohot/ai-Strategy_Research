# I3-2 补料完整性审核（2026-09-18）

## 判定

**候选包可供复核，但尚不完备，不应作为正式金标冻结。** 不能仅处理台账列出的三道定性题与一个数值格式差异便放行；20 道 mapped 中也存在漏条件、错粒度与多余目标。

方向仍符合项目：从已冻结人工 source/query gold 补机器可读目标、零模型、不先看候选业务结果。缺陷位于“人工要求 → 机器验收目标”的转换，尚无依据推倒清洗/入库架构。

## 主要缺口

### F1 / P1：mapped 只证明数字 token 覆盖，不证明题目要求完整

定位：`i3s2_evidence_targets.py:217`、`:247`。

| 题目 | 既定要求中遗漏的部分 | 当前情况 |
|---|---|---|
| macro-003 | 通胀下行有限的条件、强就业语境 | 只映射“概率超过60%”，合成 EvidencePass=true；条件原文已在 macro-038-claim-001#3，却未选入 |
| macro-005 | 财政收入端两个堵点 | 只映射 -0.5% 预测，合成 EvidencePass=true；需补足两个堵点的原文依据 |
| macro-006 | 偏头部发债企业的样本边界 | 只映射四个增速，未包含完整样本限定 |
| macro-008 | 样本代表性、偏差与其他路径的风险限定 | 只映射投资增速；macro-060-claim-001#4 已有风险原文却被漏掉 |
| industry-001 | 表格三列分别对应及注2的期间口径 | 仅三个裸值目标，脚注未纳入 |

这些不是新增要求，而是冻结 query-gold 的 evidence_requirement 已经明写的要求。不得把“不含数字的必需部分”当作可忽略。mapped 应只作为机器候选标签，正式接受必须逐条证明原要求被覆盖。

### F2 / P1：从 expected_items 到 target 时丢失表格身份

定位：`i3s2_evidence_targets.py:115`、`:120`、`:226`；评分匹配接口 `EvidenceTarget.matches`。

source-gold 已有 row/col/cell/unit/period，生成器却只把它们用于“搜索 token”，输出主要保留 quote+页码。industry-001 的两个 0.0% 分属价格分位和价差分位，但 target 在评分器眼中没有可区分的单元格身份。

**实测**：删除其中一份 0.0% 观测，只保留同来源、page:10 下的 `0.0%` 与 `82.9%`，EvidencePass 仍为 true。无法证明分别取得两列，也无法证明产品/期间/单位配对。company-003 的各预测年度、industry-002/003 的表格目标有同类风险。

修正应保留完整 cell/row/col/period/unit 约束，并让真实 fetch/verify 的观测可验证这些约束；不能让适配器直接从金标复制行列字段到观测。一个完整表格证据可支持多个目标，但必须证明相应单元格都存在，不是按条数强制一对一。

### F3 / P2：数字/日期 token 带来无关强制目标，造成假失败

定位：`i3s2_evidence_targets.py:115`—`:117`、`:217`—`:225`。

- company-005 本来由第3页两段正文完整回答四种型号的用途和阶段；候选还强制第2页列表及第11页 8230CF 订单句。只返回第3页这两段，实测 EvidencePass=false（缺 e1/e4）。8230 的数字边界匹配也没有排除型号后缀 CF。
- industry-004 只问统计窗口，注1+注2已经能支持要求；日期碎片 01/07/27/26 在各行 period 元数据命中，把六个产品数值变成额外目标。只返回两条正确脚注，实测 EvidencePass=false（缺 e1—e6）。
- industry-002/008 同样混入纯碱/R134a 等非必要数值。

建议把“可选支持段”与“必需目标”分开；对同一事实的等价证据明确可替代关系，不把一切 token 命中结果并成必需 all。无需靠放宽槽位通过率补救错误映射。

### F4 / P1（契约）：EvidencePass 分母不是 item 数或槽位数

总台账 `claims-market-closed-loop-plan.md:481` 提出让 U 选择“逐 item 60条 vs 槽位聚合”。这与架构 §12.3（第621行）的**满足全部证据的题数/证据题数**不一致。

当前批次是 24 道有答案证据题、6 道负例；每类分母8。60是候选目标条数，只决定每题内部是否全部满足，不能拿来替代 EvidencePass 分母。“槽位聚合”若只是展示无妨，若降低必需证据要求则是在改验收合同。

建议删除这个错误的分母二选一，继续既定按题计分。每类8题时≥95%仍要求8/8。可以额外展示 item 覆盖统计，但不得冒充 EvidencePass。

### F5 / P2：往返自检不是补料完整性验证，partial 缺口没有独立阻断门

`i3s2_verify_candidates.py:63` 的合成记录不带裁决状态；`:136` 附近把 mapped/partial 同等预期为三项全过。候选自己生成 gold，再用同一候选生成 verified=True 的观测，只证明数据结构自洽，不能发现漏掉的目标。

当前报告已诚实注明不代表真实链路，这点应保留。但“30/30”不可解释为30道题材料完整。需要独立的冻结门检查所有正例均已审定、无未决语义要求、无 partial/needs_human、basis 与人工批准同版本；人工审核不能仅针对有缺口标签的题。

1. **company-004**：现有 target 已有 `9.38/13.4/18.09`，query 写 `13.40`。这是数值格式差异，不是缺失这个数值。映射可按数值等价核对并记录批准，但原文 quote 仍保留 `13.4`，不能改写成 `13.40`。此处不需要增加新材料。
2. **company-008**：要分别绑定两份材料的具体评级与“维持/首次覆盖”。目前 preview 只取全池前12项，全部是财务表数字，不能帮助裁决评级；应先修人工复核材料，提供相关完整条目和来源定位。
3. **industry-006**：industry-057-claim-001#2 的完整 quote 已包含用途及预计2027年推出，60字符预览截断了后半。可作为目标候选；“供应链消息”出处也需在引用上下文中覆盖，不可只把人工解释 text 当原文。
4. **macro-004**：已有五主体条目，但当前 source-gold 目标列表未完整编码四条路径的全部原文依据，需要补定位/引文并复核，而非只选择某个已有主体句就算完成。

## 推荐收口方式

不需要换模型，也不建议再无限调数字匹配启发式。30题规模足够小，应把候选收敛成可审核的固定映射：

1. **每题建立要求覆盖账**：冻结 requirement 中的数值、对象、期间、单位、条件/否定/归属，各项分别指向 source-gold item 或人工补充的精确原文依据；缺项显式 pending。
2. **保留结构身份**：表格不丢 row/col/unit/period；正文保留需要的上下文。候选可来自规则，但批准不能仅依据 token 命中。
3. **全量审核24道正例**：mapped 不等于 approved；区分必需、可选及可替代证据。6道负例另核覆盖依据。
4. **补变异测试**：漏条件/漏脚注、错列/错期间、同值不同单元格必须失败；完整最小证据应通过，不能要求无关段落。保留本轮两类反例。
5. **正式冻结前**：确认评分器版本、阈值、关键题、负例、旧基线映射、逐题裁决和输入哈希；候选与批准件分开存储。当前 r22 是候选包冻结，不等于 I3-2 正式完成。
6. **冻结后再 PG 联测**：执行隔离 PG search→fetch/verify→观测→score，特别核查文档聚合、真实 cell/版本身份及失败状态。此次补料审核不提前运行业务结果，以免用结果反向改金标；PG 联测不会替代人工确认预期是否完整。

需要 U 参与的是最终语义映射、缺少引文的补标与负例覆盖确认；程序补字段、生成完整复核清单、修正分母文案与反例测试应先由执行方完成，不应让 U 在不完整预览中盲选。
