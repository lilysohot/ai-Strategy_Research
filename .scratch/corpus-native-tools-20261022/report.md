# 原生正文策略接入真实工具链：更新、降级与回退验证

2026-10-22。已完成用户指定的“把已验证策略接入真实工具链，以可关闭的开关试用，并验证更新、降级和回退”。新代码进入现有`CorpusService.search_with_coverage → corpus_search → corpus_fetch`路径，默认关闭。本次没有切换生产默认检索，没有运行OCR或回答模型。

## 接入结果

- `CORPUS_NATIVE_RETRIEVAL=pilot`启用；`off`恢复原服务策略。另要求一致的`CORPUS_NATIVE_TARGET_DB`和`CORPUS_NATIVE_INDEX`，错误目标或旧读链不静默兼容。
- 运行数据移至`data/corpus-native-pilot/20261021/`，项目实现不读取实验题号、金标或排名。范围包提供允许来源和可复用向量；正文、活动版本、准入及日期从PG当前快照读取。
- 排序仍为已验证的原首条保护＋全局块级RRF，最多20块／16,000实际原文字符。搜索默认最多10条命中，同一build的多个正文块合并成一条取证计划；未调整排序权重或按题目设置分支。
- `chunk:native1/`句柄绑定build、原chunk、返回正文及原文坐标／哈希。关闭开关不会把这些旧句柄扩成整段长文；它们继续按原范围取证。
- 原文坐标放入`native_slices`，取证分页同时计算JSON元数据占用。新句柄使用有解压长度上限的压缩游标；旧游标格式保持可用。

首轮发现搜索句柄重复占用消息预算，12,000字符下10题有命中被省去；原文坐标也增加了分页开销。保留 [首轮审计](first-pass-audit.json) 和 [首轮逐题记录](first-pass-cases.json)。修复取证计划重复字段及分页预算后，重新执行全部57题；最终 [审计](audit.json) 的`search_budget_elisions`为空。

这次测量含搜索及全部fetch，使用缓存查询向量：中位数2,570ms，p95为3,182ms。不含供应商embedding网络等待或Agent阅读／作答时间，也不是吞吐压测。983页说明“16,000正文字符”不等于总工具消息开销或调用次数；本轮不宣称减少了Agent回合或费用。

## 更新、降级和恢复

真实PG生命周期测试在一个明确回滚的事务中进行。入口借用该事务连接以观察未提交的测试版本，其余查询、保存点、向量SQL与原文读取执行实际代码；没有把fixture当作正式资料发布。

1. **活动版本变化：**换到同来源另一build并增加代次后，新候选只使用新活动版本，旧快照拒绝继续检索。另一真实连接仍看到已提交版本。
2. **新正文缺向量：**构造一个新的原生正文输入，返回`native_vectors_pending`并在同一范围关键词降级，旧build不被召回。
3. **增量同步恢复：**同步只请求缺少的一个输入；模型返回使用测试向量，未调用供应商。再次同步请求为0，之后恢复混合检索。
4. **向量SQL故障：**注入真实除零SQL错误，保存点回滚后关键词结果仍可返回，数据库事务继续可用。
5. **查询embedding故障：**真实工具路径模拟供应商错误，返回明确的降级原因；所有fetch仍限定原生正文范围。
6. **历史句柄与撤销：**换版后旧句柄返回旧正文并标`active=false`；来源撤销后，候选排除且历史句柄拒绝取证。
7. **日期漂移：**元数据、文件名和准入日期重新读取；单测覆盖未增加发布代次的准入日期变化，不能沿用旧日期继续查询。

生命周期fixture的版本、正文、向量及撤销变更全部回滚，见 [生命周期记录](lifecycle.json)。

另外执行了真实`native-sync --max-requests 0`命令，将102条已经生成、哈希匹配的向量写入当前隔离库衍生缓存；复用575个唯一输入，对应585块。重复执行新增导入0、请求0、缺口0。这102条是本轮实际保留的PG衍生缓存写入，不能把本轮描述为“数据库完全零写入”；资料发布指针及代次未改变。
