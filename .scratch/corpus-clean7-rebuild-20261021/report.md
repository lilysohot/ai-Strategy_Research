执行日期：2026-10-21。结论：**模板干扰明显减少，既有正文证据覆盖保持；尚未证明整体准确率或召回率提升。** 本次完成用户授权的隔离库重建、向量增量更新及原 32 题对照，不包含主 agent 消费或回答评测。

后续原因核验：两个旧 build 的质量报告已有相同缺口，旧版均有人工缺口凭证。茅台第 2 页为分季度拆分图表，原所需证据在第 1、3 页；光力第 7 页为组织架构图，原所需同页文字与图区不重叠。凭证绑定旧 build、指纹和证据范围，新 build 的对应记录为空，因此发布受阻。不是本次清洗新增图像缺失；原复核也不能证明整篇任意提问均有完整覆盖。正式主文档已回填此边界，跨版本复核复用尚未实施。

10 份资料复用当前 schema 的解析检查点；8 份旧 schema 检查点沿正式引擎重新解析，其中 6 份发布、2 份受阻。实际块数 684 与前轮固定解析输入得到的 676 不同，因此这是**实际版本重建效果**，不能把全部变化单独归因于 clean-7。原始单元文本比较仅发现华创宏观报告的一组联系方式合并、电话顺序变化，未发现研究正文文本增删；结构及块边界仍可能变化。见 [corpus-delta.json](corpus-delta.json)、[reparse-raw-delta.json](reparse-raw-delta.json)。

执行中两份内部资料因脚本首次未包含既有 supersedes 审核祖先而未进入构建。补齐原审核链后，在新隔离库中恢复这两次未完成尝试改变的当前准入指针，再正式重建并发布；未生成审核意见或绕过门槛。尝试与恢复记录保留在 [admission-recovery.json](admission-recovery.json) 及 build-results 的 previous_attempt。

## 2. 对照方式与结果

保持原 32 道题（24 正例、8 压力题）和检索代码不变，运行旧/新库 × 词法/混合，共 128 份真实 `search_with_coverage` 记录。混合检索经过实际 PG 全文候选、稠密候选、RRF、选带、去重及上下文补齐；32 个问题向量由真实 API 生成并缓存，同一题两库共用同一向量，全部正常走 hybrid，没有词法降级。

证据标注为旧样本的 39 个块出现次数（30 个唯一块）。跨版本按相同来源及非模板原文覆盖匹配，不依赖旧 chunk ID。完整块指标要求该块所有保留片段都出现；标题敏感的原指标保留，同时增加正文指标诊断标题引用变化。详见 [指标定义](metric-definition.json)、[逐题指标](metrics.json)。

| 指标 | 旧词法 | 新词法 | 旧混合 | 新混合 |
|---|---:|---:|---:|---:|
| 最终锚点中已审模板主导片段出现次数 | 39 | 0 | 37 | **2** |
| 最终锚点总数 | 320 | 320 | 268 | 265 |

| 首条覆盖完整标注块（含原标题） | 18/24 | 18/24 | 22/24 | 21/24 |

“模板主导”指锚点取证文本中至少 80% 字符来自已审模板/既有 noise 单元；次数按题累加，同一块可多次出现。37 → 2 不等于不相关结果只有 2 条，也不是完整 Precision@K。剩余两次均为华创资格批文页脚（p06、p13）。返回上下文中模板片段出现次数仍为 413 → 259，不能宣称模板全部清除。

只统计本轮真正发布新版本的来源：21 道正例、34 个标注块，旧/新混合返回范围均覆盖 **34/34**，正文首条均覆盖 **19/21**。光力科技 p19–p21 的 3 道正例仍针对旧活动版本，不作为新版本证据保留的证明。见 [新版本来源子集](updated-source-metrics.json)。这些都是已见开发样本，不是独立盲测或全库召回率。

### 需要保留的具体问题

- **p24 标题引用变化：**首条正文、词法分数、向量相似度和 RRF 分数一致；上下文标题引用从“大脑一 财务审计师”变为父标题“五脑辩论”，造成含旧标题的严格首条指标下降。标题仍在扩展范围，正文未丢失。正文指标在发现此差异后补充，未替换原指标。见 [诊断](p24-diagnostic.log)。
- **p13 来源优先级：**问题指定平安策略周报，平安仍排第二，第一条为天风。减少模板没有解决这类来源排序问题。
- **p16 多实体要点覆盖：**问题同时询问华工正源与立讯技术，首条仍只覆盖立讯部分；其他返回范围中能找到所需证据。上表“覆盖一个标注块”不等于首条完整回答多要点问题。
- **n01 公司错配：**询问“紫荆量子光电股份有限公司”，仍会返回光力科技等其他公司片段。仅凭金融数字与语义近似召回不足以证明实体匹配。
- **p20 选带缺口：**混合候选池有全部旧标注块，但最终范围仍缺其中一个完整块；另一返回块已包含问题所需的 3.51 亿元与 1.01 亿元，因此不能将缺少一个旧标注块等同于无法回答。此题目标光力科技未发布新版本，旧/新对照均存在该缺口。词法返回范围为 39/39，下一轮仍应检查融合后的排序、去重及选带是否损失有用证据，不能只看向量候选是否命中。

## 3. 延迟与模型用量

另做两轮交替顺序的混合检索测量，每库 64 次；查询向量已缓存，计时包含实际服务检索链路，但**不含查询向量 API 网络耗时**。

| 耗时 | 旧库 | 新库 |
|---|---:|---:|
| 中位数 | 310.5 ms | 324.0 ms |
| P95 | 513.3 ms | 516.9 ms |
| 均值 | 349.1 ms | 351.9 ms |

本地小样本未观察到提速，也不足以认定稳定性能退化；本轮不作端到端延迟收益承诺。详见 [原始计时](latency-raw.json)、[汇总](latency-summary.json)。首次 128 份采集中只有一侧承担查询向量生成耗时，因此不拿其原始混合计时直接比较。

684 个当前块对应 675 个唯一向量输入，612 个复用缓存，63 个需新增计算。文档向量成功 63 次、实际尝试 65 次，成功响应报告 29,306 tokens；两个传输状态不确定的请求各重试一次，其供应商计费是否发生无法确认。32 个查询向量共报告 1,633 tokens。合计成功响应报告 30,939 tokens，不折算未核实的货币价格。

完成后再次运行增量索引，新增请求为 0、尝试计数不变，确认当前快照重复执行复用缓存。详见 [缓存重放](cache-repeat.json)、[最终验证](verification.json)。仓库要求的 preflight 另执行一次廉价模型调用，不计入上述向量用量。

## 4. 验证与后续方向

验证完成：所有 128 份记录的候选均对应各自数据库当前活动 build；旧版本候选没有混入新活动版本。新库 684 块全部就绪；原试验库和生产 publication 未变；32 题 manifest 哈希未变；增量重复调用为零。导入 stage 1/2、符号闭合、preflight 均通过，日志为 `gate-0.log` 至 `gate-3.log`。本轮仅新增实验脚本和记录，没有进一步修改清洗或排序业务规则。

**建议下一步固定本轮新库快照，分别验证正文公司/实体匹配、多要点覆盖，以及融合候选到最终选带的证据损失。** 原 32 题保持不变，沿候选池、最终锚点、扩展范围分别计分；关注 p13/p16/n01 等问题能否改善，同时守住已发布来源的 34/34 证据覆盖。残留页脚可单独做小修，不继续以扩大清洗范围替代排序实验。

本轮完成的是部分来源发布成功的隔离实验，默认业务库和服务未切换；两份受图像缺口阻断的资料仍待后续处理，不能将本轮结果表述为全部 18 份已完成 clean-7 升级。
