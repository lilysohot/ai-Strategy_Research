# B0-D3：真实文件名补齐实验

结论：补齐真实登记文件名后，B 组三次均明确识别了该文件名，但三次仍继续广搜，没有转向交付或交付必需校验。身份字段缺失是已确认的接口问题；本次不支持把“拿不到一个合格文档的文件名”作为该决策点续搜的充分解释。尚未证明唯一根因，不修改生产提示词或工具逻辑。

## 执行范围

用户审阅 D3 后回复“开始执行”。A 保留原始成员第二轮结束时的输入；B 仅在目标文档的 document 回执末尾增加经过独立核验的 original_names。新增 71 个字符，2532 → 2603，仍在原 max_chars=3000 内。正文、游标、未读完标记、原派工多候选要求、工具继续检索条款、工具定义和采样配置均不变。

该名称取自当前来源登记，归档哈希及文档单元指纹与 B0 匹配；不是把正文标题当文件名，也不是历史时点的数据库快照。模型输入未添加“停止”“足够”等指令。

## 六次结果

| 配对 / 顺序 | A 原始输入 | B 增加真实文件名 | 是否转向交付或必要校验 |
|---|---|---|---|
| 1 / A、B | 3 次广域 search | 2 次广域 search | 否 |
| 2 / B、A | 2 次广域 search | 1 次广域 search + 1 次无日期条件的空 query | 否 |
| 3 / A、B | 2 次广域 search | 另一候选文档续读 + 1 次广域 search | 否 |

全部实际模型为 `deepseek-v4-1-flash-261017`。6 次有效调用，0 次执行错误，另有独立预检 1 次。13 个拟议工具调用均未执行。

B2 空 query 不带日期条件，按当前 corpus_search 参数校验会被拒绝；这是模型生成的无效工具参数，不是已经发生的工具执行错误。B3 的 fetch 指向 ce4cdb 开头的另一候选，不能统计成对已补齐名称的目标文档进行身份核实；同时仍有广搜，不能因为 search 数量下降而算收敛成功。

| 组别 | 输入 tokens | 输出 tokens | 调用耗时合计 |
|---|---:|---:|---:|
| A | 69,930 | 1,269 | 19.718 秒 |
| B | 70,044 | 1,398 | 21.700 秒 |

六次合计输入 139,974 / 输出 2,667 tokens；预检额外输入 34 / 输出 11 tokens。耗时受缓存及请求波动影响，不能外推端到端收益或退化。

## 最有区分力的新证据

B1 可见回复明确表示已取得第二篇文档的真实文件名，随后仍要扩大搜索确认候选并取得更多名称。

B2 原句：

> Found `original_names` on the second doc — that's the actual filename. Let me probe for more candidates, including whether a filename literally contains "SpaceX".

这表明新增字段被识别，不是只在输入里存在而被忽略。它随后又提出“文件名是否字面包含 SpaceX”的选取条件，原始用户没有要求该字面条件。

B3 可见回复也承认拿到了一个原始文件名，随后要确认另一篇名称并继续换角度搜。

因此应分开评估两个结果：名称身份识别得到了明确反馈；停止/交付行为没有达到改进标准。不能把前者直接写成整个收敛问题已修复。模型可见陈述只是行动证据，不被视为底层心理机制的独立证明。

## 三项实验合起来说明什么

| 实验 | 单独改变 | 观察到的停止/交付转变 |
|---|---|---|
| D1 | 删除派工多候选比较条款 | 无，B 3/3 广搜 |
| D2 | 删除工具描述继续检索条款 | 无，B 3/3 广搜 |
| D3 | 补齐已核验的真实文件名 | 无，B 3/3 仍含广搜；均识别名称 |

这否定了目前三种“只改这一点就能解决该边界问题”的乐观预测；不等于排除三者的作用或交互，也不等于证明模型普遍无法收敛。三项实验共用同一历史，是同一决策点的筛查，不能把它们当成多个独立用户任务。

尚缺的具体检验是：**名称已经齐备时，派工中的多候选义务是否继续推动扩搜。** D1 在名称缺口未补齐时删条款，D3 在多候选义务保留时补名称；两个单独阴性结果无法排除“两项同时解除才收敛”。此前不能据此完全否定首次派工影响。

为避免继续盲目加提示词，下一项 D4 仅作为条件效应实验准备：两臂都使用 D3 已补名称的输入，B 再只删除原派工多候选句。它不新增任何指令。A/B 各 3 次的具体输入已准备并等待审核；没有执行新的模型调用。若阳性，仅支持该条件下派工条款的局部作用，仍不等于完成正式同期 2×2 交互检验或生产闭环验证。

## 完整性与局限

配对 A/B、B/A、A/B；并发 1；每次 120 秒逻辑上限、8192 输出上限；temperature=1.0、top_p=0.95、top_k=20，thinking 与 D1/D2 相同，无 fallback、无择优重跑。调用前预检实际版本。

保存了每次请求、原始流增量、完整响应、usage、耗时。离线检查确认同臂输入一致、A 请求与 D1 A 一致、A/B 仅多一个 source-name 字段，汇总工具参数与原始增量一致。B0 在调用前后校验通过，生产 tracked diff 未变化。

历史完整 schema 未保存，此次沿用已冻结的重建 schema；历史临时附加消息、路由和采样仍未知。因此是受控重建，不是历史请求逐字节复现。只观察下一步，未执行生成工具，也未产生最终回答；最终文件名交付正确性和全文覆盖正确性均为未评估。每臂 3 次不宣称统计显著或通用根因。
