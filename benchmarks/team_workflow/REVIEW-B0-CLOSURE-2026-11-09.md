# 待审核：B0-CLOSURE-1，先验证名称能否通过工具到达模型

这轮收敛问题、样本和执行边界。**先做最多 3 次确定性的工具调用，0 次 Agent 模型调用；暂不开始另一批随机 A/B。** 两个后续模型条件的完整初始输入已准备，但不把尚未就绪的连续执行器包装为可运行基准。

## 为什么先停在这一层

前两轮分别移除外围工具、四个显式进度字段，仍未得到稳定改善。继续删除字段只能不断说明某因素不是必要条件，无法定位失败发生在哪个边界。

已有身份审计证明名称保存在源记录中；之前的最小模型实验把该名称补入了工具结果。这证明模型在拿到名称后有时能回答，却不能证明现有真实工具能把名称送到模型。因此必须区分：

1. 所需信息能否经真实工具返回。
2. 信息已返回后，模型能否决定交付。
3. 模型交付后，运行时和协调员能否结束并正确传递答案。

本轮只检验第 1 项。这是先验证测试前提，不再加入一个生产修复或针对性提示。旧实验仍有效，但作用限于各自被控制的场景。

## 本次提交审核的 3 个调用

| 编号 | 调用 | 核查 |
|---|---|---|
| G1 | corpus_search(query="SpaceX", limit=10) | 返回是否含目标文档；是否明确暴露该来源的准确文件名 |
| G2 | corpus_fetch(doc_id=已冻结目标句柄, scope="document") | 正常全文首页回执是否暴露同一来源的准确文件名 |
| G3 | corpus_inventory(doc_id=同一目标, scope_ref=G1 的原样句柄) | 结构清单是否暴露准确文件名；旧返回则使用原 context_locators |

目标句柄、预期名称、具体参数和 G3 绑定规则见 gate-cases.draft.json / protocol.json。G1 没有该目标或有效清单句柄时，G3 标为未评估，不猜 locator、不追加搜索。

判定名称可达必须同时满足：实际返回明确表达原文件名、精确匹配已审计名称、可绑定同一文档/来源。标题、文件名式文本、模型猜测均不能替代登记名。无论字段是否叫 original_names，只要语义和绑定充分均可接受。

检索/读取使用真实生产工具序列化路径，不向回执人工注入名称。源语料与归档只读；工具引用与会话状态必须隔离到临时存储。隔离或依赖不可用则报告基础设施未评估，不静默改用假工具。无入库、重建、外网搜索或生产修改。

顺序执行，最多 3 次，单次上限 120 秒，总上限 300 秒，不重试。Agent 模型调用预算为 0；检索后端若调用 embedding/reranker，独立记录，不能把“零 Agent 调用”说成零外部计算成本。

## 何时停止

- **任一真实回执提供名称：** 记录具体 JSON 路径及版本绑定，名称至少有一条可达路径；完成固定检查后停止本轮，再据实际可用路径完成短循环运行器。
- **固定调用成功但均不提供名称：** 报告这些访问路径未证明名称可达，优先检查源元数据到工具回执的传递契约；不能笼统宣称所有工具和所有查询都无法提供名称。
- **服务、鉴权、隔离、句柄或超时问题：** 标为未评估；不记成模型能力失败。

按固定计划保存各调用的结果，不因首个有利结果丢弃已计划的可执行检查。完成后停止，不自动进入模型 A/B。

## 已准备、尚不执行的两个模型条件

用户请求保持原句：“从资料库中，找出一篇关于space x的文章。只需要得知文件名就可以”。

- A：使用上一轮 A 的完整输入，相关正文和准确 original_names 均已交付。
- B：仅删除 original_names；五个原文单元、身份句柄、全部进度字段、15 个工具定义、调用历史与用户请求均相同。

B 的标题依然保留日期和近似标题，这是现有证据的一部分；不得因此将猜出的下划线文件名当作有依据的登记名。输入中的缺失仅用于实验，不主张生产删除字段。

预期区别：A 已有满足要求的信息；B 缺少准确身份信息，应有目的地补查，或者在工具无法提供时明确不能确认。明确不能确认不算找到了文件，但优于编造；不能为了提高停止率而奖励不查就猜。

后续建议只做 A/B 各 2 次，顺序 A、B、B、A，每例最多 3 次模型决策，共最多 12 次实验调用及 1 次预检。**这是后续预算建议，不属于当前可执行授权；须先通过名称可达性核查并明确真实循环/工具/终止边界。** 不增加全文阅读目标、第二篇文章或额外提示词变体。

质量评价分开记录：身份正确性、补查必要性、参数及工具执行、证据首次充分的时点、此后新增取证、无依据的附加断言、实际终止原因、成员输出与团队最终回答。预算耗尽不算收敛；工具接收不算答案真实；正确文件名加中性格式不算失败。
