F18 的节选可引用性及原文出现在保存的模型上下文中，并非只有后端记录。

它是可观察的执行理由，不是单凭隐藏推理推定根因。
该题首次 add_task 的 done_when 只要求年份与审批状态及证据句柄，没有要求全文。
因此本次首次过读并非由任务板显式加入全文义务造成；偏离发生在取证后的继续决策。

需要修正先前对 F19 的表述：搜索只送达 u01 的 excerpt/ref 和候选 scope_ref，
并未直接送达 u02 locator。目录展开后是两条带页码的候选，没有语义摘要。
fixture_contract 的 search_context_units 也不被当前适配器消费。因此不能将
首次全文选择描述为“模型已拿到精确 u02 定位却不用”。确定的过读发生在首个
全文页已经返回 u02 之后，后两页仍被读取。

独立接口探针通过原生产工具在同一 F19 固定语料上展开目录，并分别按 locator
取回 u01/u02。u02 单块返回年份、未获批表述和可引用 evidence_ref，证明局部
读取能力存在；该脚本不调用模型，不证明模型能自主选对候选。

## 从样本定位出的确定性状态错误

F19 settings.json 明确记录 planning_mode=false。模型第 2 轮调用 finish_planning，
旧实现却无条件写入 `_PHASE[task_id] = "execution"`。planning_enabled 通过该键
是否存在判断规划策略是否启用，最终验收因而意外要求成员工作及独立复核。

这与“完成计划阶段”的含义不同：阶段结束动作不应为未配置的运行启用另一套
验收义务。主节点只在配置打开时调用 start_planning；工具绕过了这条边界。

独立最小复现只使用通用任务板和真实 finalize_gate，不含文档、公司或场景词：

```bash
uv run python .scratch/dispatch-scope/repro_planning_activation.py
```

修复前输出 planning_enabled_after_finish=true，并拒绝交付：
`Cannot finish: no sub-agent has done any work ... Planning Mode forbids ...`。
同一复现修复后输出 false、finalize_error=null。回归在修复前为 1 failed、2 passed；
失败项对应非空任务板意外启用规划策略。空任务板及显式启用规划的对照被保留。

生产修复仅位于 `plugins/tools/task_board.py::finish_planning`：未启用规划时直接
返回未变更状态；已启用时通过既有 force_finish_planning 转阶段。没有修改提示词、
关闭明确配置的规划约束、删除必要核验或根据任务主题决定是否收敛。

这一修复解决的是额外派工义务的来源，不能解释或解决此前 F18/F19 的首次过读。

## 当前结论

1. 已修复一个可确定复现的运行时义务扩张：未启用规划的运行被 finish_planning
   改成必须派工及复核。它不是提示词缺少提醒，也不是文档切块问题。
2. 按需停止仍未解决。F18 在充分节选后开启全文；F19 在已取得所问事实后增加
   “全文无相反表述”的要求。首次任务定义正确也不能保证后续收敛，故仅约束首次
   派工不足以覆盖这些样本。下一层诊断应集中在证据到达后的继续决定，而不是
   继续改写同义的范围提示词。
3. 没有证据支持新增固定读取上限。F20 明确要求全文，真实轨迹能够读取全部
   单元；F19 又确有必要补证。后续任何收敛方案必须保留这两种正向能力。
4. 模型长调用超时仍限制端到端结论。预检成功不保证研究或汇总完成；本轮未换
   模型、放宽预算或重跑失败样本来取得更好结果。当前证据不能确定超时的根因。
