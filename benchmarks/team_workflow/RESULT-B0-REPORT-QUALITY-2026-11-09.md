# B0 报告回放与 agent 执行质量评估

两个已审核的确定性回放均符合预期：原样报告被接收并产生终结信号，空内容负对照被拒绝且不产生终结信号。实际执行 submit_report 两次，新增真实模型调用 0 次，执行异常 0 次。

**这只说明所测工具与观察器边界可工作，不说明 agent 执行质量已经合格。** 结合已保存输出，真实问题仍包括名称身份确认、非必要续搜、用户要求之外的交付扩张，以及证据范围表述过强。纠正格式误判不能抹掉这些问题。

## 执行质量：格式之外还存在什么

### 1. 答案是否满足用户真正需要的身份信息

MIN E0 三次都给出准确登记名：

`2026-11-06_深度_太空算力：SPCX_有望在_2028_年实现_1_GW_在.pdf`

多出的简短引导语是轻微冗余；不能把它描述成找不到文章或名称错误。它们仍不是主动停止能力的证明，因为该组没有工具可选。

原始 B0 最终回答则以“文件名：深度|太空算力：SPCX 有望在 2028 年实现 1 GW 在轨算力”开头。这里使用的是文章标题，历史工具回执没有提供登记文件名。它与后来只读核实的登记名不同，不能把文章标题直接认证为精确文件名。

这不是 Markdown 或空格问题，而是**标题与原始文件身份的混用**。后续元数据取证不是历史数据库快照，因此不能声称知道历史登记是否变过；但历史输出的精确文件名确认缺少证据这一点成立。

### 2. 后续研究是否解决用户仍未满足的要求

MIN E1 只有一篇候选，已有相关正文与登记名，仍有两次提出 query=SpaceX 的新主题搜索。可见输出没有指出必须补齐的具体身份缺口。在“找一篇、给文件名”的要求下，目前看不出这两次搜索的必要性。

这是实际的行动选择质量问题，不能因格式评分有误就忽略。也不能把所有 search/fetch 一律算坏：初次发现候选、确认主题相关性、补查缺失名称，都可能必要。本轮只针对已经具备相关内容与登记名的 E1 条件下判断。

两次搜索只被提出，没有执行，因此不计算它们实际增加了多少检索耗时或后续 token，也不推断完整运行最终必然失败。

### 3. 内部交付与用户答复是否匹配各自用途

R1 是 460 字符的成员内部报告，包含名称、依据和置信度；它遵循当时提供的 submit_report 格式。不能仅凭比 47 字符文件名长，就断言其用户答复冗长，因为还没有观察到协调员输出。

原始 B0 的最终用户答复实际为 1,256 字符，加入三个备选、定位句柄、覆盖分析和主题说明。用户只要一个文件名，这是真实发生的交付范围扩张。即便名称正确，仍应在需求符合性与简洁性上记问题；它比 E0 的一句中性引导语严重得多。

### 4. 表述强度是否超过证据范围

B0 使用了“以 scope=document 打开全文……核实，正文通篇……”和“库内唯一”的表述。目标文档的 document 模式只返回首批 5 个单元、fetch_complete=false，未沿该游标续读；后续搜索又送达一些目标文档节选，不能说整次运行只看了 5 个单元，但也没有全文遍历完成证明。

“全文核实／通篇”的措辞容易让用户高估核查覆盖度；“库内唯一”也缺少全库充分覆盖证据。答复后面的非穷尽免责声明并不能建立前面的唯一性结论。

这属于证据与表达的匹配问题，不是单纯格式错误，也不能因工具接受报告就视为通过。

### 5. 成本是否与任务价值匹配

原始 B0 实际耗时 271.49 秒，记录了 16 次模型尝试、14 次 corpus_search、3 次 corpus_fetch、1 次 corpus_inventory。对于仅要求一个名称的任务，这是需要解释的工作量。

但没有同环境下成功的端到端对照，不能把所有动作判为浪费，也不能给出“可节省百分之多少”的数字。当前只记录实际成本、任务要求，以及哪些动作未显示出必要性。

## 对修复方向的约束

本轮消除了一个局部疑点：E1-r1 的具体报告并没有在所测 submit_report 与终结观察器边界被拒绝。另两个 E1 样本是在工具执行前就选择继续搜索，说明问题至少已在下一步动作选择阶段出现；完整团队后续是否另有问题仍未知。

因此不应因为这两个回放通过，就修改最终判定为“agent 已具备稳定收敛能力”；也不应继续围绕“必须直接输出、不许用报告工具”修提示词。接下来的质量评估应同时约束：

- 用户要求的身份信息正确且有来源支持；名称、标题、定位句柄不能互相冒充。
- 后续研究对应一个明确、必要的剩余要求，而非为了更全面而继续搜索。
- 交付意图、工具接收、成员终结、最终用户交付分别有证据。
- 不以文档总页数、scope=document 或提交成功证明全文核实或全库唯一。
- 按用户要求衡量最终答复冗余与成本，区分内部报告协议和对用户的输出。

这些是后续评估维度，不是本轮新增的生产提示词或已证明有效的修复。原评分与阶段门槛保持冻结；没有解锁未执行的 E2/E3，没有追加模型实验。
