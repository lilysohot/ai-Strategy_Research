# B0-D1：首次派工多候选条款消融结果

结论：同模型的 3 对单步实验中，两臂全部继续广搜。当前证据不支持“删除派工中的多候选比较条款，就能解决第三轮续搜”。尚未获得经干预验证的根因，不提交生产修复。

## 对根因的约束

1. **H1 未得到局部因果支持。** 三对均未从扩展搜索转向交付或当前文档身份核对。不能继续围绕这一句加规则并声称修复。样本量小、历史前两轮保持不变，因此不排除该条款早已影响前两轮路径，也不等于证明其在所有任务中无影响。
2. **偏差出现在已有证据后的行动选择。** B0 第二轮已经交付完整文章标题和关于 SpaceX 的正文。此次六个输出全部继续寻找更专门、更直接的文章。例如 p1-B 可见回复为 `Let me broaden the search to find the best SpaceX-focused article.`；实际参数是无 doc_id 限定的关键词搜索，不是只核对当前文章的身份。p3-B 还明确要检查是否有标题更直接的文件。以上是可见行为证据，不将模型自述当作因果解释。
3. **确实存在名称契约缺口。** 派工要 `exact filename / title 字段`，但 search 工具明确 `title` 是首命中块标题，未必是报告名称。全文页可以给出正文标题，却没有独立的原始文件名字段。故“已找到文章”和“已取得原始存储文件名”不能当成同一个评分条件。缺口如何导致广搜，仍需独立实验；不能把正确标题冒充原始文件名来做阳性样本。
4. **不是已证明全文读取能力缺失。** scope=document 已经成功返回标题和正文，分页是否读完与本轮找一篇文章的收敛是两个问题。本实验没有测全文完成率，也没有验证最终交付的真实性。原运行“全文核实/唯一”措辞问题保留为独立证据范围问题。

下一层优先验证 H3：corpus_search 描述存在无条件的“未合并的候选需继续检索”。它可能把尚有候选转成继续研究义务，但目前只是候选解释。不要把这句看起来可疑直接等同于根因。

## 可复核性与限制

- 顺序 A/B、B/A、A/B；并发 1；每次逻辑上限 120 秒；输出上限 8192；temperature=1.0、top_p=0.95、top_k=20；启用并保留 thinking；没有 fallback 或择优重跑。
- 使用当前生产 client.stream 和 for_wire；保存历史 assistant 内容及 reasoning_content，移除 usage 等非 wire 元数据。所有请求、原始流增量、完成原因、实际模型、usage 均落盘。
- 历史轨迹缺完整工具参数 schema。此次以当前 15 个 builtin 定义重建参数并保留历史描述，两臂完全相同。历史采样、临时附加消息、路由配置未知。是受控重建，不是历史请求逐字节重放。
- 一行差异、同臂请求一致、输入哈希、流输出及参数解码已通过离线校验；B0 的原始来源和冻结工作区指纹在模型调用前后均通过校验。
- 记录器初版汇总误按嵌套 function 读取 StreamDelta；实际增量使用平铺 name/arguments。原始增量完整保存，因此用 decode.py 离线还原了全部调用，未更改请求、未补跑模型。原汇总保留供审计；行动判断以 graded-results.json / decoded-results.json 为准，不能使用原 *.result.json 中的空工具名称。
- 三次重复用于筛查，不代表统计显著或通用因果结论；未执行工具，也未生成最终答案，最终正确性均为未评估。
