## 改变的测试问题

D1–D4 始终在同一套完整历史上改小片段，未获得成功对照。新测试先问：**较小上下文能否正确完成原始需求，而完整上下文仍继续扩搜？** 只有两个端点可稳定区分，才进入中间层定位。

不是先认定某一层有错，再寻找有利样本。若较小上下文也失败，停止当前恢复流程，报告这个起点尚不能完成任务；不能继续删句或宣布系统提示词有问题。

## 四组具体输入

所有组使用同一真实用户问题、同一四条工具回执、同一真实登记文件名和全部 15 个工具。仍可选择搜索、读取、提交报告等动作，不通过禁用检索迫使作答。

| 组 | 模型看到什么 | 与前一组的差异 |
|---|---|---|
| L0 较小起点 | 原始用户原句 + 原有工具调用及结果；保留两篇候选的所有原文和目标文件名 | 没有成员 system、没有生成派工；assistant 的自述与 reasoning_content 清空 |
| L1 恢复成员系统要求 | L0 + 原有完整成员 system | 只增加该 system 消息 |
| L2 恢复生成的任务上下文 | L1 + 原有成员 user 消息 | 用历史 user 消息替换用户原句；其中包含同一原始问题、生成派工及 workspace contract |
| L3 恢复历史自述 | L2 + 原有 assistant 可见自述及 reasoning_content | 恢复 215 字符自述和 737 字符 reasoning_content；输入等于 D3 B / D4 A |

L0 是**相对较小起点**，不是无上下文的模型能力考试，也不是完全无历史：保留原有 4 个工具调用的名称、参数、ID 和对应的 4 条结果，维持合法消息配对，避免把 tool 原文改写为另一条 user 指令。调用轨迹本身和工具描述仍可能影响选择。

L0–L2 仅清空 assistant 内容和已有 reasoning_content 的值；不删除调用或结果，不补入新的分析、结论或提示。若提供方拒绝这种合法性重建，记执行错误并按规则停止，不偷偷补提示重跑。

L2 的一层是整个生成任务消息，包含派工与 workspace contract；L1 也包含整个成员系统包。因此成功定位最多先指向一组上下文，不能直接归因到某一句。输入长度随恢复变化，这也不能被忽略。

## 执行顺序与停止条件

第一阶段只比较端点，顺序为 **L0、L3、L3、L0、L0、L3**，各 3 次，共 6 次。

仅当以下条件同时成立，才进入第二阶段：

- L0 三次均直接给出准确登记文件名，不再调用工具；可接受文件名外的 Markdown 代码或加粗包裹，不能接受标题替代、臆造名称、额外无依据主张。
- L3 三次均生成有效的扩展候选/覆盖度搜索；不能把针对当前已知文档名称的窄范围核对误判成广搜。

若任一端点混合、错误或不满足条件，本轮停止，剩余层标未评估。不会挑选成功样本补跑；边界不稳定本身就是结果。

第二阶段顺序为 **L1、L2、L2、L1、L1、L2**，各 3 次，最多再 6 次。每个输入独立调用，不把上一条测试输出带进下一条测试。

总预算：最多 12 次实验调用，另有 1 次必要预检；第一阶段不满足条件就只做 6 次。实际模型须为 deepseek-v4-1-flash-261017，配置同 D1–D4：temperature=1.0、top_p=0.95、top_k=20，thinking 启用并保留；并发 1，每次 120 秒逻辑上限和 8192 输出 tokens。无 fallback、无选优重跑；连续两次执行错误后停止，剩余标未评估。预检失败不启动样本。

只观察一次模型决策，不执行任何生成的工具调用，不自动写任务板或清单。

## 评分须分开两条轴

**行为轴：** 是否继续广搜、读取其他候选、重复读目标、针对具体必要缺口核实、提出交付必需校验，还是直接交付。按真实参数标注；同一轮既说“已找到”又继续广搜，仍算含广搜。

**交付轴：** 是否准确输出登记文件名，是否只给了文章标题，是否夹带全文读完/全库唯一等无依据说法。直接正确输出、submit_report 的正确内容、仅准备 manifest、无交付须分开记录。

L0 的端点成功要求直接正确交付。中间层带有系统规定的 report/manifest 路径，不能因为没有普通文本 final 就认定一定失败；相反，仅调用这些工具也不能认定任务已完成。工具不执行，report/manifest 只能计作拟议交付/校验动作，协议执行成功和最终团队交付仍未评估。违反恢复后系统协议的直出也应单列，而不是拿来证明生产流程成功。

## 如何解释结果

- L0 正确交付、L3 扩搜：获得可区分端点，可以继续定位；不是证明完整上下文中的每个要求都错误。
- 在 L1 开始扩搜：优先定位成员 system 这一整组上下文，再做针对该层的受控细分。
- L1 仍倾向交付、L2 开始扩搜：优先定位生成的任务上下文。
- L2 仍倾向交付、L3 开始扩搜：优先定位历史自述/推理这一组内容。
- 行为不是单调变化或样本不一致：记交互/不稳定，不能把最后一层强判为根因。
- L0 也继续研究或交付错误：此起点未成功，不能据此断言模型普遍不具备能力；工具描述、机械历史、证据充分性、模型判断或交付契约仍需区分。本轮不自动追加其他实验。

每层 3 次用于筛查，不宣称统计显著；固定恢复顺序给出的是条件效应，不是完整析因分析。新的 system/派工修改以及端到端修复不在本次授权范围。
