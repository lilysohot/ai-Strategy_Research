# A4 报告闭合：enforce 原位降级 + /outputs 报告纳入校验范围

## Context（为什么做）

`docs/data_clean_dos/01-table-recovery.md` §A4.2/§A4 评审（C5/C6）显式声明了两条**已知语义边界**，这两处正是「报告交付闭合」的缺口（README v7 列为当前验收缺口）：

1. **enforce 档过弱（评审 C6）**：`publish_boundary` 在 `A4_ENFORCE` 开启时只对未通过报告**追加锚定限定块**，原文中的强断言仍保留可见。原方案 A4.2 要求对无支持结论**修正/降级/移除**，当前是显式选择的「草稿保留」过渡档。
2. **/outputs 报告脱审（评审 C5）**：由文件工具（sub-agent 经 `create_file`/`write_file`）另行写入 `/outputs` 的报告文件不在 `publish_boundary` 校验范围内，`report_sha256` 只绑定被边界校验的那份 final_text，/outputs 交付物可绕过证据完整性校验。

目标：让报告交付闭合——未通过证据校验的无支持结论在最终报告中被**原位降级标注**（而非任其以强断言呈现），并把 `/outputs` 报告文件纳入同一校验范围做**一致性+同步处置**。两者都保持确定性、无 LLM 调用、可复算的既有纪律。

范围与约束：
- enforce 行为仍由 `A4_ENFORCE` 开关控制，**默认关闭**（观测模式不改变行为，仅新增观测字段）。
- `report_quote` 是权威原文逐字锚点、同时是 final_text 内的**逐字子串**（否则已按 C4 记 `not_in_report`），这使得「在原位替换该子串」是确定性且跨语言安全的。
- /outputs 只存在于 agent_team（sub-agent 文件交付）语义下；stateful_react / reporter 路径无 sandbox /outputs 概念，不接线。

## 设计

### 1. enforce 原位降级替换（Closure A）

ledger.py 新增 `_downgrade_unsupported_in_place(text: str, verification: dict) -> str`：

- 遍历 `verification["conclusions"]`，对每条 `status != SUPPORTED` 且带非空 `report_quote` 的行；
- 若该 `report_quote` 在 `text` 中存在，把**首次命中**的子串替换为：
  `quote + （A4 证据未校验，不作结论依据）`（即原位保留原文、紧贴标注为降级形态——满足「修正/降级」且在原文可见、可复算、不裁切句子）；
- 按 `len(report_quote)` **降序**逐条应用，避免短锚点嵌套长锚点重复命中；返回新文本与已处理条数（供记账）。

该函数供 `publish_boundary` 在 enforce 且未通过校验时对 `final_text` 调用（替换仍保留末尾追加的 `_limitation_block`，不破坏既有锚定清单）。

### 2. `/outputs` 报告一致性 + 同步处置（Closure B）

ledger.py 新增两个辅助 + 扩展 `publish_boundary`：

- `_discover_output_reports(outputs_dir: Path) -> list[Path]`：扫描 `outputs_dir` 顶层报告类文件（`*.md`/`*.markdown`/`*.txt`，跳过隐藏与临时文件）。返回存在与否皆可。
- `publish_boundary` 新增可选参数 `outputs_dir: Path | None = None`。
  当传入时，主流程在得到 `verification`（final_text 的绑定校验）后，对每个报告文件：
  - 读取文本、算 `_sha256`；
  - 若 `text == final_text` → `consistency="identical"`，复用主校验状态；
  - 否则 `consistency="divergent"`，用同一账本对该文件文本独立做**报告绑定校验**（`verify_manifest`，`final_text=<该文件>`），得自身 `publish_status`；
  - 追加 `verification["output_reports"]`（每项：`path/sha256/chars/consistency/publish_status`），并落盘进 `manifest_verification.json`（`verify_and_record` 的 `extra` 已支持纯增量）。
  - 汇总 `output_ok = all(consistency=="identical" or publish_status==PUBLISH_VERIFIED)`。
- 整体未校验判定：
  `not_verified = (verification.status != PUBLISH_VERIFIED) or (outputs_dir and not output_ok)`。
  - 若仅 outputs 失败：`verification["publish_status"]` 覆盖为 `PUBLISH_PARTIAL`（回应“报告类别不能只靠正文取全”）；
  - `boundary_action`：
    - 主通过且 output_ok → `publish`；
    - `not_verified` 且未开 enforce → `observe`（新增 `output_reports` 观测字段，不改内容）；
    - `not_verified` 且 enforce → `downgrade`：对 final_text 做原位降级 + 追加限定块；同时**回写**每个 divergent/未通过的报告文件（对其自身文本做原位降级，失败则记日志 hold-open，不吞主流程）。

### 3. 接线 workflow 调用点

- `workflows/agent_team/nodes/main_agent.py`（L1695 已调 `publish_boundary`）：`outputs_dir = _resolve_worktree_root(state, ctx.task_id).parent / "outputs"`（已有该 Resolver，L1285），传入。
- `workflows/agent_team/nodes/reporter.py`（L357）与 `workflows/stateful_react_agent/nodes/main_agent.py`（L1178）：不传 `outputs_dir`（保持 `None`；reporter 的 report 即 final_text，已被校验）。

### 4. 观测字段与文档

- `manifest_verification.json` 新增 `output_reports`（schema 纯增量，兼容旧读端）。
- 更新 `01-table-recovery.md` §A4.4/已声明边界 与 `README.md` §状态：消除两处「已知边界」，标注为已闭合（enforce 默认仍关闭）。

## 测试 / 验证

新增单元测试（镜像既有 `publish_boundary` 四态与 report 绑定用例的写法）：
1. enforce 原位降级：构造未支持结论（含 `report_quote`），`A4_ENFORCE=on` → 断言 final_text 中该 quote 被原位标注且限定块附加；`report_quote` 缺位/不在报告中则不加注。
2. outputs 一致性：`outputs_dir` 下同内容文件 → `consistency=identical`、状态复用；内容不同文件 → `divergent`、独立校验、整体压 partial。
3. outputs enforce 回写：divergent 文件在 enforce 下被原位降级并回写磁盘，draft 正常。
4. 观测模式（默认，无 enforce）：增 `output_reports` 字段但不改 final_text/文件。

## 明确不做

- 不引入 LLM 参与文本手术；不改 `A4_ENFORCE` 默认关闭。
- 不为 stateful_react / reporter 接线 /outputs（无该语义）。
- 不动 B2 噪声判定、不重建语料、不开启受保护评测答案。
