先说一个反直觉的事实

一个 agent 节点，默认会收到
整个共享状态的全部字段。

不管你用不用得上。ContextPolicy 就是用来改这个默认的：给每个节点开一张纸条， 上面写清楚"你只需要这几样"。框架照着纸条，把资料放到他桌上。

整个资料室 = state ＋ 主管的纸条 = ContextPolicy → 桌上的几份 = 节点收到的数据
第一幕

先看看"没有纸条"的世界是什么样

点一下按钮，看全部字段倒给一个节点会发生什么。

这个节点真正用得上的：3 个字段
工人的桌子（容量有限）
reporter负责把结果写成对外报告
结果：桌上堆了 33 份文件，其中只有 3 份是他真正要用的。 剩下的 30 份不会消失，它们会一起进入模型的上下文—— 模型要在 33 份无关文件里，找到那 3 份有用的。

这就是理解 ContextPolicy 的唯一前提： 默认行为是全量塞满，不是按需给。 所以在没有它之前，"给多了"根本不是配置问题，而是默认状态。

第二幕

换成一个你每天都见的场景：新来的实习生写周报

同一个任务，两种交办方式。差别不在"保密"，在"聚焦"。

方案 A · 没有纸条（= 默认行为）

主管把公司共享盘的全部 33 个文件夹权限给了小王：

研发部 38 轮会议纪要 财务报销流水 销售客户名单 法务合同扫描件 上一季度招聘记录 ……还有 28 个
"都在这儿了，你自己看着办吧。"
结果：小王翻了三天资料，周报里还莫名其妙写进了报销的事。
方案 B · 有纸条（= ContextPolicy）

主管只给他一张纸条，上面写：你只需要这 10 样。

本周工作记录 上周周报 老板的原话 项目进度表 ……共 10 样
"按这张单子准备，别的不用管。"
结果：半天写完，内容聚焦，没有一句跑题。

注意：那张纸条不是在限制小王的权限， 而是在告诉他"你该看什么"。 这两件事听起来像，其实是相反的——一个是"不许"，一个是"专注"。

第三幕

把这个故事一对一换成代码里的东西

没有新概念，只是把刚才每个人都听懂的故事换成术语。

故事里的东西代码里的东西
公司共享盘的全部文件夹 state —— 整条管线共享的那一份数据，只会越来越多
主管写的那张纸条 ContextPolicy.include_fields —— 声明在图纸上（PipelineSpec）
小王桌上实际放着的那几份 节点函数收到的 dict（就是"托盘"）
主管本人：负责照纸条挑文件 框架外壳 _wrap_with_context_filter —— 节点代码完全不用管
小王交回来的周报 output_fields —— 节点干完活往共享盘里写什么

三句话对上：
共享盘 = state（越写越满）
纸条 = ContextPolicy（每个工人一张，不一样）
桌上的文件 = 节点真正收到的数据（不是全部）

第五幕

三个最容易被搞错的地方

如果你只记住这一节，也比记住所有字段名有用。

误解 1：被过滤掉的字段，值是空的（None）
不是空，是根本不存在。工人翻遍桌子也找不到这份文件，不是找到一个空文件夹。 代码里表现成 KeyError 或取不到，而不是拿到一个 None。 这很重要："有但为空"和"压根没有"是两种完全不同的信号。
误解 2：这是为了省 token（省钱）
省 token 只是顺带的。真正的问题是"信息越多，模型越容易跑偏"—— 桌上一堆无关文件，它会去翻那些不该看的，然后写进周报里。 这叫上下文污染，比多花钱严重得多。
误解 3：让工人自己从资料室里挑，不是更灵活吗？
工人自己挑，就没人知道他挑了什么。 纸条写在纸上，主管不在时别人也能照着办，出了问题能查是谁改了纸条。 藏在工人脑子里，只有他自己知道——这叫不可审查。
第六幕

最后一个问题：纸条为什么要贴在墙上？

技术上完全可以写进工人自己的代码里，为什么偏偏要声明在图纸（PipelineSpec）上？

工人自己挑（写在节点代码里）

主管想知道"这个工人会看什么"，只能去问工人本人。 工人换了、代码改了，行为跟着变，没人察觉。 想统一做截断、压缩、预算控制，框架根本插不上手—— 因为数据进门时，它不知道这个工人要什么。

纸条贴墙上（声明在 spec 里）

不读一行代码，看图纸就知道"谁给谁什么、谁需要谁"。 框架在递资料之前就知道要裁哪几份，所以截断、压缩、对齐工具 全都能插手。纸条写错了，编译期就能查出来。

进门的裁剪，必须在进门之前决定。 这就是为什么它必须是一张提前写好的纸条，而不是工人临场的判断。

如果只记住一句话

节点看到的不是整个资料室，
是主管按纸条放到他桌上的那几份。
而每张纸条，都贴在图纸上，不在工人脑子里。

state 管"有什么"，ContextPolicy 管"给谁看"。 管线越长、白板越胖，这张纸条的价值越大——因为它决定了 模型在每个环节是"面对一堆杂物"，还是"面对该做的事"。
