## CodeBuddy CLI 权限配置（2026-09-18，减少复核命令反复确认）

用户反馈形如 `cd <repo> && env -u PYTHONPATH uv run python .scratch/.../run_review.py 2>&1 | tail -8; echo "EXIT=$?"`
的复核命令每次都要人工确认。已创建**用户级** `~/.codebuddy/settings.json`（此前不存在）：
`permissions.defaultMode = "acceptEdits"`，`allow` 覆盖 `cd/env/uv/python/tail/head/echo/cat/ls` +
git 只读（`status/diff/log/show/--no-pager`），`deny` 覆盖 `git push`、`git reset --hard`、`git clean -fd`、
`git checkout --`、`rm -rf`、`sudo/su`、`curl/wget`、`ssh/scp`。
**未开 bypassPermissions / CODEBUDDY_IS_SANDBOX**（本仓库有冻结 write-once 产物 + PG 真库零写入纪律）。

可复用要点：
- 用户级配置对所有项目生效；项目级 `.codebuddy/settings.json` 会进 git（本仓库 `.codebuddy/memory` 已跟踪），
  个人命令白名单应放用户级，团队共享规则才放项目级。
- 权限求值顺序里 allow 分「可信（第 3 步，早于命令安全检查）」与「不可信（第 7 步）」两档，
  `Bash(uv:*)` 这类宽通配可能落在后者 → 若仍弹确认，收窄为 `Bash(uv run:*)` / `Bash(uv run python:*)`。
- `deny` 永远压过任何 mode；受保护路径清单（.git/.envrc/.npmrc/.codebuddy 等）只约束 Edit 类工具，
  **Bash 放行后写冻结文件不会被二次拦** → 冻结纪律须靠 deny + git diff 复核兜底。

### 仍弹确认的真正原因（同日追加，官方权限规则确认）

1. **重定向会让 allow 通配符失效**：含 `>` `<` `>>` `<<` `&>`（含 `2>/dev/null`、`2>&1`）的命令，
   allow 规则下**只认精确匹配**，前缀/通配规则不生效 → 必然进入 ask。这是 `... 2>/dev/null` 类命令的根因。
2. **复合命令要求所有子命令命中**：CodeBuddy 按 `&&` `||` `;` `|` 拆分成子命令独立判定，
   allow 需**全部命中**，任一未命中整条询问（deny/ask 则是任一命中即触发）。
3. **`defaultMode: "acceptEdits"` 不管 Bash**：只自动放行编辑类，Bash 仍走完整判定链（阶段 7 基线=ask）。
4. 双端路径陷阱：WSL 侧 `~/.codebuddy/settings.json` 才是本会话生效的那份；
   Windows 侧 `C:\Users\Administrator\.codebuddy\` 只有 diagnostics/logs，**没有 settings.json**（IDE 若从
   Windows 端启动则规则不生效）。

对策（按推荐度）：命令里去掉 `2>/dev/null` / `2>&1`；或把这类命令写成精确匹配规则；
或拆成单条；或在弹窗勾 "Yes, don't ask again" 让 IDE 回写最稳前缀；
会话级可用 `--allowedTools "Bash(ls:*) Bash(wc:*) ..."`。
