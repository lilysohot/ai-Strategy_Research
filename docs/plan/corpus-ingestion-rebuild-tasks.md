## 1. 角色与符号

- **U（用户/人工）**：环境与凭据提供、准入终态裁决、金标判定、批准签认、维护窗口排定。
- **A（Agent）**：脚本、代码、测试、报告生成与文档起草；全程零模型约束，不含任何模型调用。
- **A+U（联合）**：A 生成候选/结构化产物，U 判定与批准。
- **D0**：I0 启动日，由用户排定。所有"起止"为 `D0+n` 相对工作日，标"估"；标"待标定"者须以 I0-A/B 实测结果（来源量、库规模、恢复耗时）修订。
- 各任务交付物路径见 v1.1 §12.1（`.scratch/corpus-evidence-pipeline/ingestion-rebuild/`）。

## 2. 依赖与里程碑总览

```text
I0A-1..5 ──┬─(I0A-5 逻辑契约冻结)──> I1 内存执行链 ──────────┐
I0B-1..2 ──┴─> I0C-1..4 设计复核与冻结 ─────────────────────┴─> I2 PG 层 ─> I3 三类E2E ─> I4 切换 ─> I5 增量/运维
```

- 关键路径：I0A → I0A-5 → I1 → I2 → I3 → I4 → I5；I0B 与 I0A 并行，汇于 I0C。
- 并行轨道：① 盘点与契约（I0A）② 恢复演练（I0B）③ 内存链（I1，I0A-5 后即可开工）。
- 人工作业重项：I0A-2（逐源终态）、I0A-4（金标/出题）、I0C-1（裁决签认）；吞吐在 I0A-1/2 摸清源量后复排。
