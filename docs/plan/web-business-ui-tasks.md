| 项 | 内容 |
|---|---|
| 版本 / 日期 | v1.4 · 2026-10-02；补数请求与会话业务回执按所属会话汇总 |

| 需求依据 | [Web 业务资料 PRD v0.6](../design/web-business-data-prd.md)；[产品需求](../product-requirements.md) PR-BIZ-01—06、PR-WB-07、PR-DATA-13、PR-WATCH-01—04 |

| 范围 | 三栏工作台、资料录入与回执、分析依据、补数、监控、站内通知及浏览器验收 |

本清单回答“用户在哪里操作、看到什么、异常后如何继续”。服务端保存、真实性状态校验、
事务、监控判定和调度由 DATA 清单负责；页面不能代替服务端强制校验。

任务编号用于设计和依赖引用，本次不建立实施进度台账。进入实施时按
[本地任务规范](../agents/issue-tracker.md)将每项分别建为 issue，状态只在对应 issue 维护。
产品状态仍以产品需求为准；本次拆分不调整其他专项优先级，不启动部署或迁移。

## 1. 交互约束

- 保留研究导航、对话、右侧画布三栏；账户资料与登录账号设置分开。
- 实际资金、成交价须由用户如实明确提供。没有数据保持空/待澄清，不预填示例金额或用计划价、现价替代。
- 用户明确提交后直接保存并给出回执，不增加重复“确认真实”弹窗；“用户提供”不能显示为外部核验。
- “保存资料”不启动 LLM；“保存并分析”使用服务端返回的 Run 和快照，不靠聊天文本认定保存成功。
- 资料草稿只留当前页面内存；离开时提示未保存，不向 localStorage 写资金和持仓正文。
- 监控由后台执行，页面只配置和展示；关闭页面不应停止已生效规则。
- mock 可用于页面开发；只有与真实服务端联调并完成验收才算用户流程交付。

## 3. 页面任务与验收

### UI-01 工作台入口与资料卡

**需求**：PR-BIZ-01、PR-DATA-13；PRD §4.1。

- 左侧增加“交易账户资料”和“监控”入口；每个研究会话标题栏提供“会话计划”入口，
  显示其所属计划集合并允许设置当前主计划。
- “交易账户资料”的计划模块只展示“计划—唯一所属会话—当前主计划—状态”列表，
  不在该模块创建计划或修改会话归属。
- 中间显示可折叠摘要：资金口径、币种、标的、计划/实际价格、数据时点和保存状态。
- 右侧展示账户/计划详情与修改历史，返回报告时保留阅读位置。
- 空资料、加载、无权/不可用、已归档和读取失败均有明确状态；未交付能力不放可点击空按钮。

**验收**：跨研究切换不串账户、草稿或旧异步响应；刷新/重新登录显示服务端绑定。
一个账户可被多个研究引用；一个研究可拥有多个计划，但一个计划只属于一个研究；
每次分析只选择该研究的一个账户和一个计划。对应 AC-01、19。

### UI-02 账户与计划录入

**需求**：PR-BIZ-01/02、PR-DATA-13；PRD §3.2—3.4、§4.2。

- 账户表单区分总资金/可用资金、币种、口径、时点，并展示可多选的研究引用关系。
- 计划表单只从具体研究会话进入，页面固定显示当前研究且不提供会话选择器；保存后自动归属当前研究，
  再填写标的市场、方向、计划价/区间与目标价。当前主计划只在该研究范围内设置。
- 按用途补充风险预算及单位、仓位上限、时间窗、止损/失效条件、盈亏比定义，不要求普通材料阅读先填全档案。
- 十进制字符串编辑和传输，避免经 JavaScript Number 往返损失精度；比例和数量明确单位。
- 显示“已买入/未成交”；未成交时实际成交价为空，真实计划可在所属研究内单独保存。
- 提供“保存资料”“保存并分析”；未提交表单草稿只在页面内存中。用户主动保存不完整资料时，
  服务端保存为明确标记的待补充记录，刷新可读；它与未保存草稿不同，不得显示为可用于依赖计算的有效资料。
- 提交用途决定必填字段，页面使用服务端用途契约；一般阅读、未成交计划分析、持仓成本计算分别校验。

**验收**：假设、估计、歧义或缺失字段被定位提示；有效明确值无需二次确认。
界面校验不替代 DATA 服务端准入；资金缺失不阻断无关阅读。对应 AC-03、25—28。

### UI-03 实际记录与策略采纳

**需求**：PR-BIZ-01/02/04、PR-DATA-13；PRD §3、§4.3—4.4。

- 持仓录入数量、成本口径、时点和来源；成交录入方向、数量、价格、币种、费用、成交时间。
- 更正展示前后值并创建新版本；手工持仓和成交不在前端叠加重算账户。
- 从策略产物“保存为计划”时在当前研究内创建计划并明确采用对象及来源，不生成成交记录，
  不允许保存成其他研究共享的同一计划。
- 历史列表展示版本、来源、时点；业务撤销提交补偿操作，文件 revert 保持原有文件语义。

**验收**：计划、成交、持仓、策略互不冒充；缺失不变零，多币种不直接求和。
撤销遇到后续修改须显示冲突。对应 AC-03、04、22、26。

### UI-04 保存反馈与并发冲突

**需求**：PR-BIZ-04；PRD §4.2—4.3、§5.3。

- 同一用户动作生成并保留幂等键；不确定结果先查询/用同键重试，不生成新的重复操作。
- 页面刷新/重新登录后，用不含业务正文的操作标识和服务端“最近操作”恢复提交结果；
  键未知或结果待核定时先展示查询状态，不盲目重发。退出登录清除页面草稿、订阅及缓存。
- 带附件提交显示上传/校验/提交/派发阶段；同名文件冲突就地提示，失败重试复用已登记附件，不能悄悄覆盖。
- 成功回显服务端有效值、版本、保存时间和修改项；网络错误保留页面草稿。
- 版本冲突展示原编辑版本与当前版本的差异，允许调整后按新版本重新提交。
- 区分“保存失败”“资料已保存，分析待派发”“分析运行中”“分析失败”，不将派发延迟误报为资料丢失。
- 本模块只收录会话内操作回执；每条回执显示唯一所属会话并可返回。纯账户页操作结果留在账户页，
  不为进入汇总列表而绑定一个无关会话。

**验收**：双浏览器修改第二次冲突；超时重试只保存一次，保存并分析只建一个 Run；
worker 启动失败仍能找到原保存结果和待恢复任务。对应 AC-04、05、23。

### UI-05 聊天修改与澄清

**需求**：PR-BIZ-02/03/04；PRD §4.3。

- 渲染服务端业务操作回执，与普通助手回复分开；显示修改目标、结果和版本。
- 多账户、口径不明或不确定更正时就地提问，只问歧义，不重复询问已经明确的事实。
- 历史聊天/附件抽取只展示候选，明确采用前不标为保存；不设置“仅本次假设覆盖”入口。
- 用户先明确真实价格再提问时保留事实语义；不能按问号或关键词简单拒绝。

**验收**：明确修改、假设、估计、材料引用、已知值上的不确定更正均按 PRD 行为回显；
未成功写入时助手文案不能显示“已记住”。对应 AC-02、22、25、27、28。

### UI-06 分析依据与重算

**需求**：PR-BIZ-02/05、PR-DATA-13；PRD §4.4、§6。

- 提交时显示采用账户/计划与必要字段摘要；报告“分析依据”读取该 Run 冻结快照。
- 当前资料改版时提示“本次分析使用较早资料”，不能把详情自动替换成当前值。
- “用新资料重算”提交停止与关联新 Run 操作，展示停止/排队状态；与原研究串行。
- 已排队手动 Run 保持原快照；用户通过取消重提采用新资料。
- 报告文件缺失或快照不可读显示具体状态，不伪装为空报告或改用当前资料。

**验收**：A 采用 10 万，修改后 B 采用 8 万，A 详情不变；重算保留旧轨迹及来源关系。
对应 AC-06、07、10、18、27。

### UI-07 补充资料与逻辑续接

**需求**：PR-WB-07、PR-BIZ-03；PRD §4.5。

- 展示 pending/answered/cancelled/expired 请求，包含用途、字段、单位、已知值及待澄清原因。
- 一个会话可有多条请求，但每条请求只属于一个会话；跨会话页面仅汇总，列表和详情都显示所属会话。
- 页面刷新后查询持久请求；原 Run 显示 input_required 原因，回答后连接到后续 Run。
- 提交期间防重复；另一窗口已回答、已取消、过期或研究删除时显示冲突并刷新。
- 有歧义回答显示已收到但仍待补充；不展示成分析已继续，不复用工具审批对话框。
- 展示已提交回答、剩余待补项及资料已被其他窗口改版的冲突；可明确沿用新值或重提，不能覆盖更新。
- 自动事件在创建分析 Run 前发现缺数时，请求可关联事件而暂时没有 Run；页面仍能回到所属研究回答。

**验收**：重启/刷新可回答；明确回答只生成一次后续 Run；原快照不改。
对应 AC-08、24、25、28。

### UI-08 监控配置与管理

**需求**：PR-WATCH-01/04；PRD §7.1—7.2。

- 创建页包含标的、行情口径、币种、阈值、方向、有效期、触发次数模式、提醒/自动分析、任务与预算。
- 用户明确要求自动分析时保存该意图；仅要求提醒时不擅自开启。聊天已明确的字段不再重复确认。
- 展示创建时已达标的处理选项、采样频率、最近有效行情/检查时间、暂停/恢复/取消回执。
- 计划修改不静默改变规则阈值；规则修改显示新版本。
- 规则编辑、暂停、恢复显示对未启动事件的处置；既有运行不会因编辑阈值而改写输入，停止须明确操作。
- 显示行情观测时间、接收时间、口径与质量状态；无可靠观测时间、休市/停牌或来源异常时，
  不把“刚收到报价”显示为“最新成交”。不满足监控能力的标的/行情模式禁用并说明原因。
- C 阶段只交付单次规则；D 阶段开放重复规则，展示冷却、重新布防边界及状态。
  确认持续时间可作为待定配置；不把讨论中的“3 秒、10 分钟、19.90 元”固定为产品默认值。

**验收**：触发后与“分析失败”状态分开；持续在阈值附近波动不呈现重复分析。
冷却结束本身不会显示为新触发；断线恢复注明观测缺口。对应 AC-11、12、16、21。

### UI-09 行情事件与站内通知

**需求**：PR-WATCH-02/03；PRD §7.3—7.4。

- 原研究加入行情事件回合：触发原因、规则版本、触发报价和时间、分析开始报价和时间、延迟。
- 区分待分析、运行中、完成、失败、过期、已合并、预算阻止和待补资料；按服务端状态提供合法后续操作。
- 全局通知可回到所属研究，已读状态由服务端保存；断线按用户级游标补读，过期则重新同步。
- Run 内进度继续使用已有 per-run SSE；业务事件和运行事件不重复生成卡片。
- 展示后台在线/行情故障，不能以页面仍开着表示监控正常。
- 自动事件缺资料/凭据失效时显示具体处理入口；登录过期只影响页面访问，不自动撤销已保存监控授权。
- “重试派发”与“重新分析”分开：前者恢复原任务，后者保留失败 Run 并显示关联的新分析，避免抹掉历史尝试。

**验收**：触发后无需再次点击即可自动排队；重复推送/刷新不重复卡片；
合并事件能追溯去向，达到预算保留触发原因，缺资料进入补数流程。对应 AC-13—16、21、24。

### UI-10 归档与删除反馈

**需求**：PR-BIZ-06；PRD §5.4。

- 清除草稿、清除聊天、归档账户/计划、删除研究分别说明实际影响。
- 归档后显示关联监控的暂停原因；删除研究显示监控与自动任务取消/活动 Run 停止结果。
- 跨研究共享账户与历史报告保持可识别；研究所属计划随研究停止新采用，不将软删除称为物理擦除。
- 对服务端部分处理/重试状态给出可恢复反馈，不能仅隐藏页面假装删除完成。

**验收**：删除一个研究不删另一个研究仍引用的账户资料，也不把该研究计划转给其他研究；
清聊天不清业务事实。
对应 AC-17、18。

### UI-11 浏览器验收

**需求**：本清单涉及的全部 PR-*；PRD §10。

- 每阶段交付时运行真实浏览器及真实对应 API；覆盖刷新、重新登录、两窗口冲突、断线、超时重试、迟到响应。
- 375px 窄屏完成填数、修正、保存、回执与详情返回；标签、单位、焦点、键盘操作和非颜色状态均可识别。
- 使用两个专用测试身份检查不串账户/研究；浏览器采用独立上下文，不把新端口当作认证隔离。
- mock 页面、截图或前端单测不代替完整服务端链路；后端拒绝越权不能只凭 UI 隐藏按钮验收。

**验收证据**：记录场景、测试批次、界面结果、网络回执中的对象/版本/Run 标识及脱敏截图。
AC 全量映射见配套清单 §6；AC-20 的成本实验由 DATA-15 负责，UI 不另造缓存命中“优化成功”结论。

## 4. 两条任务线如何交付

| 交付门 | 页面范围 | 服务端前提与通过标准 |
|---|---|---|
| A 资料闭环 | UI-01—04、09/10/11 的资料部分 | DATA-00—04、12—14 对应基础范围；保存、操作结果恢复、版本冲突、隔离及资料恢复通过 |
| B 分析闭环 | UI-04—07、09、11 的分析部分 | DATA-05—08、12 补数通知；业务快照实际进入 worker，请求/回答重启可恢复，重复提交不建重复 Run |
| C 单次监控 | UI-08 单次模式、UI-09、10、11 | DATA-09—12；单次触发、持久派发、预算、通知补读及基础重启恢复通过 |
| D 重复与扩展 | UI-08 重复模式及全链异常验收 | DATA-10 重复状态机、DATA-13—15；重新布防、冷却、观测缺口、取消竞争及联合恢复通过 |

UI-01—03 可在 DATA-01 接口契约确定后并行开发；各阶段发布必须接入真实后端。
事务、归属、幂等、持久派发与基础恢复随首次使用交付，不统一拖到 D 阶段。
