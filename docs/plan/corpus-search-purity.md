# Native search 结果提纯：第一阶段

日期：2026-10-23。已完成本地实现与测试，未重启服务、未切换默认索引。

## 实现范围

在 Native 宽召回、融合排序、原文预算选取之后，进入 Agent 之前增加来源筛选；同时改善原文片段选择。没有增加模型调用或网络请求，没有修改索引、向量、fetch 协议、原文或句柄算法。

实现入口：`plugins/corpus/retrieval/purity.py`、`text_quality.py`；接入 `native_live.search` 和 `display.select_passages`。

### 来源筛选

- 使用当前查询、原文正文、已有上下文说明、标题与来源名称。上下文说明只帮助相关性判断，不能成为证据。
- 每个来源取其最佳块的查询字符覆盖度，不把不同页面的零散词语合并成一个高分。
- 至少观察到三个主题词、最佳覆盖至少六个查询字符时才启用相对覆盖门槛；弱尾部低于最佳来源的 40% 时筛除。日期数字不作主题票数。这是可审计的启发式门槛，不是校准过的相关概率。
- 从来源名称中识别已有公司主题线索，排除泛化后缀、歧义名称片段和省份前缀误判。明确主题没有在正文、来源或有实质正文支持的上下文中出现，且覆盖低于最佳来源的 75% 时，可筛除尾部来源。缺少主体本身不构成排除依据。
- 保留首位语义来源、公司上下文中的省略主体段落、较强的主题覆盖，以及复合问题中只回答一个并列主题的材料。比较多个公司时不要求每篇资料覆盖所有公司。
- 允许少返回，筛掉的来源不再用更弱候选补满。保留来源的内部块序列不变，因此同一候选池中的 `doc_id`、`locator`、`context_locators` 和 `scope_id` 不变。

### 片段降噪与去重

- 常规业务问题不展示分析师声明、版权免责等模板段落；用户明确询问声明、持股、利益冲突等内容时保留。
- 排除只有大量数值刻度、缺少可读关系的图表残片。数值多不等于噪声，可读数据行、风险、限定条件和持股事实保留。
- 同一来源内，用忽略空白、控制字符及 Unicode 宽窄字符差异的副本比较重复段落；返回的始终是原文。不同日期、金额、正负号、否定词不因去重被抹掉，不合并不同来源的独立证据。
- 这一阶段没有做语义改写或同义段落合并，也没有用词语覆盖宣称“答案完整”。

### 可观测性与恢复

`coverage.purity` 返回策略版本、考虑/过滤来源数和原因计数；完整决策在调用方启用的 `RetrievalTrace.purity_decisions` 中，避免将诊断明细占满 Agent 上下文。宽召回 trace 保留原有候选。

全部候选被筛除时，工具明确提示“筛选后未获得可展示正文，不代表资料库无答案”。可改写或拆分查询继续检索；已持有的旧句柄仍按原范围 fetch。此次没有增加新的恢复工具或绕过撤回、版本及权限检查的读路径。

## 验证结果

冻结 15 个真实查询的候选池，逐一通过实际 search 序列化、20,000 字符预算处理与引用账本回放：总来源数从 41 降至 24，88 个交付节选通过原文回切、范围/摘要和账本校验。保留来源的全部身份字段与候选池内原值一致。数量下降不等于已经测得全库精确率提升。

| 查询 | 改前来源数 | 改后来源数 | 内容核对 |
|---|---:|---:|---|
| 茅台调价、批价、成交价联动 | 7 | 2 | 保留双锚机制与另一篇市场改革评论；去掉房地产、京东、半导体公司名误匹配、股票回购及图表混杂来源 |
| 茅台线上与自营店价格 | 2 | 1 | 保留 1639/1753 元与对应机制；去掉化工报告图表/选股段落 |
| 茅台稳价风险、批价回落 | 4 | 2 | 保留消费复苏不及预期等风险；去掉房地产风险与化工泛化风险 |
| 用户原始茅台复合问题 | 2 | 1 | 线上挂钩批价、自营锚定成交价和稳价解释仍在 |
| 可插拔瓶颈与 NPO/CPO 可靠性 | 1 | 1 | 三堵墙与 FIT 改善至少十倍仍在 |
| AI 数据中心 800V 与液冷 | 5 | 3 | 单独涉及液冷机柜的部分答案保留，不要求每篇覆盖两个主题 |

实时使用上下文索引重复 15 个查询，并对保留的 88 个节选按原版本句柄回读验证；另确认一条被筛掉的旧句柄仍可 fetch。验证脚本的回读是审计行为，不是 Agent 被迫增加 fetch。

一次新向量请求可能改变相近尾部块的排序，进而影响范围 ID；实时身份对照因此复用**同一次召回结果**，避免把独立检索波动误归因于提纯。固定输入回放另行验证旧结果身份不变。

耗时与逐项结果见 [实时记录](../../.scratch/corpus-search-purity-20261023/live.json)；新增来源筛选耗时约十余毫秒，搜索整体仍约两秒。前后各 15 次的单轮测量不足以归因微小网络波动，未运行长时间 Agent 推理。

自动检查：22 项新增边界测试；相关回归合计 **235 passed**；变更文件 Ruff 与 Pyright 通过；两阶段 import smoke、符号闭包及真实模型 preflight 通过。全库 Pyright 有 21 处报错，分布在本轮未修改的 service、server、scripts、deploy 文件，详情见 [类型检查记录](../../.scratch/corpus-search-purity-20261023/pyright.log)。

## 边界与下一步

这是低成本、偏保守的规则提纯。仍可能保留“主体相关但没有回答问题”的行业背景、推荐名单；公司主题线索依赖现有来源命名，对未知别名和隐含关系不能保证识别。未引入语义重排，也没有证明未知查询上的完整召回率。

复合问题回放曾暴露“只回答液冷的有效来源被相对分数门槛误删”，已补充并列主题保留规则与独立回归测试。后续应扩大人工标注查询集，分别统计无关内容、有效部分答案损失、风险/反证保留和延迟，再决定是否对有限候选引入语义重排。

## 第二阶段：优先改善片段覆盖（2026-10-23）

本轮按用户要求保持来源过滤不变，只调整 `display.select_passages` 与新增的
`passage_coverage.py`。未修改 `purity.py`、`text_quality.py`、召回、融合排序、
上下文范围、句柄、fetch 或证据协议；不增加网络或模型调用。单来源展示预算仍为
两个块、每块 600 个原文字符，总片段数最多六个。

### 通用选择方式

此前把“新增查询词”作为跨块选择的必要条件。重复主题词多的背景段容易占位，
同一主题的补充解释却可能因为没有新词而无法进入展示。本轮改为以下组合：

1. 对查询字符位置计分，重叠的词与二元字组不重复投票。根据同一来源候选片段中的
   出现频率加权：到处出现的主体词权重较低，较少出现的问题侧面权重较高。
   完全相同、仅排版不同的候选不重复计算频率。
2. 已展示侧面的权重按 `1 / (1 + 已选次数)^2` 递减，允许另一个块用相同查询词
   提供不同解释。候选之间的字符四元组相似度只作软降权，最多扣减一半，不能因为
   相似就硬删不同金额、否定或限定条件。
3. 原因/过程、条件/要求、比较三类通用语言线索提供有限的补充评分；每类相当于
   三个虚拟查询位置。必须先匹配实际查询主题，单凭“因为”“只有”等词不能入选。
   时间、数量问句不因此被当作条件或因果问题。
4. 展示匹配忽略“报告中”“论文认为”“the report says”等引用语境。无句读、
   无数字或键值结构的标题倾向降序，数值行与显式目录查询仍可展示。
5. 长度只作有界降权，不截短本来可放下的完整解释段；分号不再单独切断句子，
   避免遗漏后半句的限制。原有相邻原文单元验证、跨缺口禁止拼接、偏移、哈希、
   不完整节选标记与首位语义命中保护继续生效。

这些规则依赖查询和候选正文，没有公司、产品、行业、题号、页码或金标答案表。
它仍是词面与语言结构启发式，不等同于理解所有问题要点，不能据评分宣称证据充分。
