# Native search 结果提纯：第一阶段

日期：2026-10-23。已完成本地实现与测试，未重启服务、未切换默认索引。

## 实现范围

在 Native 宽召回、融合排序、原文预算选取之后，进入 Agent 之前增加来源筛选；同时改善原文片段选择。没有增加模型调用或网络请求，没有修改索引、向量、fetch 协议、原文或句柄算法。

实现入口：`plugins/corpus/retrieval/purity.py`、`text_quality.py`；接入 `native_live.search` 和 `display.select_passages`。

### 来源筛选

- 使用当前查询、原文正文、已有上下文说明、标题与来源名称。上下文说明只帮助相关性判断，不能成为证据。
- 每个来源取其最佳块的查询字符覆盖度，不把不同页面的零散词语合并成一个高分。
- 至少观察到三个主题词、最佳覆盖至少六个查询字符时才启用相对覆盖门槛；弱尾部低于最佳来源的 40% 时筛除。日期数字不作主题票数。这是可审计的启发式门槛，不是校准过的相关概率。
- 从来源名称中识别已有公司主题线索，排除泛化后缀、歧义名称片段和省份前缀误判。明确主题没有在正文、来源或有实质正文支持的上下文中出现，且覆盖低于最佳来源的 75% 时，可筛除尾部来源。缺少主体本身不构成排除依据。
- 保留首位语义来源、公司上下文中的省略主体段落、较强的主题覆盖，以及复合问题中只回答一个并列主题的材料。比较多个公司时不要求每篇资料覆盖所有公司。
- 允许少返回，筛掉的来源不再用更弱候选补满。保留来源的内部块序列不变，因此同一候选池中的 `doc_id`、`locator`、`context_locators` 和 `scope_id` 不变。

### 片段降噪与去重

- 常规业务问题不展示分析师声明、版权免责等模板段落；用户明确询问声明、持股、利益冲突等内容时保留。
- 排除只有大量数值刻度、缺少可读关系的图表残片。数值多不等于噪声，可读数据行、风险、限定条件和持股事实保留。
- 同一来源内，用忽略空白、控制字符及 Unicode 宽窄字符差异的副本比较重复段落；返回的始终是原文。不同日期、金额、正负号、否定词不因去重被抹掉，不合并不同来源的独立证据。
- 这一阶段没有做语义改写或同义段落合并，也没有用词语覆盖宣称“答案完整”。

### 可观测性与恢复

`coverage.purity` 返回策略版本、考虑/过滤来源数和原因计数；完整决策在调用方启用的 `RetrievalTrace.purity_decisions` 中，避免将诊断明细占满 Agent 上下文。宽召回 trace 保留原有候选。

全部候选被筛除时，工具明确提示“筛选后未获得可展示正文，不代表资料库无答案”。可改写或拆分查询继续检索；已持有的旧句柄仍按原范围 fetch。此次没有增加新的恢复工具或绕过撤回、版本及权限检查的读路径。

## 验证结果

冻结 15 个真实查询的候选池，逐一通过实际 search 序列化、20,000 字符预算处理与引用账本回放：总来源数从 41 降至 24，88 个交付节选通过原文回切、范围/摘要和账本校验。保留来源的全部身份字段与候选池内原值一致。数量下降不等于已经测得全库精确率提升。

|---|---:|---:|---|
| 茅台调价、批价、成交价联动 | 7 | 2 | 保留双锚机制与另一篇市场改革评论；去掉房地产、京东、半导体公司名误匹配、股票回购及图表混杂来源 |

| 茅台稳价风险、批价回落 | 4 | 2 | 保留消费复苏不及预期等风险；去掉房地产风险与化工泛化风险 |
| 用户原始茅台复合问题 | 2 | 1 | 线上挂钩批价、自营锚定成交价和稳价解释仍在 |

实时使用上下文索引重复 15 个查询，并对保留的 88 个节选按原版本句柄回读验证；另确认一条被筛掉的旧句柄仍可 fetch。验证脚本的回读是审计行为，不是 Agent 被迫增加 fetch。

一次新向量请求可能改变相近尾部块的排序，进而影响范围 ID；实时身份对照因此复用**同一次召回结果**，避免把独立检索波动误归因于提纯。固定输入回放另行验证旧结果身份不变。

耗时与逐项结果见 [实时记录](../../.scratch/corpus-search-purity-20261023/live.json)；新增来源筛选耗时约十余毫秒，搜索整体仍约两秒。前后各 15 次的单轮测量不足以归因微小网络波动，未运行长时间 Agent 推理。

自动检查：22 项新增边界测试；相关回归合计 **235 passed**；变更文件 Ruff 与 Pyright 通过；两阶段 import smoke、符号闭包及真实模型 preflight 通过。全库 Pyright 有 21 处报错，分布在本轮未修改的 service、server、scripts、deploy 文件，详情见 [类型检查记录](../../.scratch/corpus-search-purity-20261023/pyright.log)。

## 边界与下一步

这是低成本、偏保守的规则提纯。仍可能保留“主体相关但没有回答问题”的行业背景、推荐名单；公司主题线索依赖现有来源命名，对未知别名和隐含关系不能保证识别。未引入语义重排，也没有证明未知查询上的完整召回率。

复合问题回放曾暴露“只回答液冷的有效来源被相对分数门槛误删”，已补充并列主题保留规则与独立回归测试。后续应扩大人工标注查询集，分别统计无关内容、有效部分答案损失、风险/反证保留和延迟，再决定是否对有限候选引入语义重排。

复现材料：[冻结输入](../../.scratch/corpus-search-purity-20261023/baseline.json)、[回放脚本](../../.scratch/corpus-search-purity-20261023/replay.py)、[回放结果](../../.scratch/corpus-search-purity-20261023/replay.json)、[实时验证脚本](../../.scratch/corpus-search-purity-20261023/live.py)。

## 第二阶段：优先改善片段覆盖（2026-10-23）

本轮按用户要求保持来源过滤不变，只调整 `display.select_passages` 与新增的
`passage_coverage.py`。未修改 `purity.py`、`text_quality.py`、召回、融合排序、
上下文范围、句柄、fetch 或证据协议；不增加网络或模型调用。单来源展示预算仍为
两个块、每块 600 个原文字符，总片段数最多六个。

### 通用选择方式

此前把“新增查询词”作为跨块选择的必要条件。重复主题词多的背景段容易占位，
同一主题的补充解释却可能因为没有新词而无法进入展示。本轮改为以下组合：

1. 对查询字符位置计分，重叠的词与二元字组不重复投票。根据同一来源候选片段中的
   出现频率加权：到处出现的主体词权重较低，较少出现的问题侧面权重较高。
   完全相同、仅排版不同的候选不重复计算频率。
2. 已展示侧面的权重按 `1 / (1 + 已选次数)^2` 递减，允许另一个块用相同查询词
   提供不同解释。候选之间的字符四元组相似度只作软降权，最多扣减一半，不能因为
   相似就硬删不同金额、否定或限定条件。
3. 原因/过程、条件/要求、比较三类通用语言线索提供有限的补充评分；每类相当于
   三个虚拟查询位置。必须先匹配实际查询主题，单凭“因为”“只有”等词不能入选。
   时间、数量问句不因此被当作条件或因果问题。
4. 展示匹配忽略“报告中”“论文认为”“the report says”等引用语境。无句读、
   无数字或键值结构的标题倾向降序，数值行与显式目录查询仍可展示。
5. 长度只作有界降权，不截短本来可放下的完整解释段；分号不再单独切断句子，
   避免遗漏后半句的限制。原有相邻原文单元验证、跨缺口禁止拼接、偏移、哈希、
   不完整节选标记与首位语义命中保护继续生效。

这些规则依赖查询和候选正文，没有公司、产品、行业、题号、页码或金标答案表。
它仍是词面与语言结构启发式，不等同于理解所有问题要点，不能据评分宣称证据充分。

## 第三阶段：冻结规则后的真实查询匿名盲测（2026-10-23～24）

### 样本与冻结范围

本轮不修改检索、来源过滤、片段选择或 search/fetch 契约。冻结 102 个相关文件及
旧选择器快照，逐次核对 SHA-256。两种选择器共用每条查询的一次真实召回结果，
然后分别经过实际展示、序列化、预算限制和证据账本校验。

从真实 Web 研究运行的 `corpus_search` 工具调用提取查询，排除显式测试、监控触发、
没有人工来源的运行，以及此前实验已出现的查询或问题意图。69 条去重查询中，
62 条通过该筛选；按预先固定的哈希抽样得到 40 条，涉及 22 个运行、13 个会话。
这是 **40 条真实 Agent 工具查询，不是 40 个独立用户问题**。样本主要涉及工业富联、
茅台与宏观市场，很多关键词变体来自相同研究任务，不能代表全部行业或长问句。

参考标注先读取冻结资料的全部 585 个块，再对匿名 A/B 展示片段评分。评审模型
不接触版本名称、选择器代码、历史答案或运行中的其他工具。参考标注和评分均由
`doubao-seed-2.1-lite` 完成，属于模型匿名评测，不能称为人工金标。40 条主评审之外，
预先选择每五条中的一条进行 A/B 标签互换复评，共 8 条。

参考要点及引用先锁定，再开展匿名评分。在查看语义评分及版本映射之前，另行锁定
问题范围审核：剔除自动参考给“目标价、评级”等关键词擅自扩写的要求，保留原始
参考和全部评分用于诊断。主指标为有效查询的已支持要点覆盖率均值；纯实体探索、
无支持证据、参考争议及完全相同展示却评分矛盾的记录不进入该指标。

40/40 条前后来源决策、顺序和句柄一致，合计均返回 140 个来源。经过原文回切与
哈希核验的展示片段为 344 → 388；展示字符数（含标签）为 56,910 → 70,286，
增加 23.5%。更长的正文不直接算作质量提升，仍须看要点覆盖与无关内容。

40 次共享的 native 检索累计 71.49 秒、中位数 1.007 秒。其中 38 次 hybrid 检索
累计 39.65 秒，最大 1.388 秒；2 次因 embedding 传输不确定降级为 lexical，

长时间的参考标注、匿名评分及其重试属于离线评估成本，不能混入检索延迟。

### 评估器审计

模型生成引用曾出现省略、格式变化及多片段拼接。仅当字符可在原文中校验时才恢复
格式或省略区间；数字、主体、年份、否定不得改写。参考中的一处 Markdown 加粗
恢复有独立勘误，原始响应完整保留。评审器的引用校验另修正了“只接受单个连续
片段”的限制：多句引文须分离引用间的分隔符、逐句匹配同一匿名组的实际展示，并分别记录来源；
任一分句不匹配仍拒绝。该修正只涉及实验脚本，原始冻结记录及修订哈希均保留。

每次模型调用保留 300 秒超时预算和最多一次传输重试；引用修复最多两轮。无效评审
不补分、不换题、不无限重试，作为缺失数据单列。有效样本的覆盖公式保持不变，
缺失处理方式也在揭盲前锁定。参考阶段曾触及 12,000 token 输出上限，故在匿名
评分开始前将上限增至 24,000；同样在评分前固定独立调用最多并发 3 个。

**判断：有局部收益，但不足以通过“整体质量改善”的验收。** 平均覆盖提升约

#### 实例复核：汇总之外仍有明确退步

## RQ-06 退步专项核查与措施（2026-10-24，尚未修改生产规则）

### 已确认的原因

用户复查的无空格查询为“贵州茅台2026目标价”。本次用冻结 RQ-06 的 16 个同源候选块，
调用实际 `display.select_passages` 离线重放；该池不同于用户当天重新检索的 8 个成员，
但复现同样的标题加图表背景、目标价丢失。进一步缩减为标题、背景、目标价三个块仍失败；
去掉标题或背景任意一个，答案恢复。测试不调用数据库、向量服务或模型。

根因不是没有召回答案，也不是 JSON 截断。第二轮候选的实际排序如下：

| 候选 | 内容评分 | 代码认为的年份 | 时间兼容标记 | 结果 |
|---|---:|---|---|---|
| 相关研究报告、图表标签 | 4.154 | 2025、2026 | 真 | 入选 |
| 目标价：2030 元；当前价：1341.99 元 | 11.558 | **2030（误判金额）** | 假 | 未入选 |
| 含一年目标价和评级的完整投资建议 | 9.841 | **2030（误判金额）** | 假 | 未入选 |

`display.py` 用 `19xx/20xx` 四位数字提取年份，并将 `not conflict` 放在内容评分
之前作字典序比较，因此误判的冲突不能靠更高相关分数补救。旧版也有该年份判断，
但跨块必须增加查询词；选中标题后，只有公司名和日期的背景块不能入选。新版允许
重复主题跨块补充，背景块重新进入竞争，暴露了原有错误。这不意味着应恢复旧版
“跨块必须有新词”的硬限制，否则同主题补充解释的收益会丢失。

另有两个共同作用的因素：`_heading_only` 只要看到数字就不将其判为标题，导致含
2026 的真实标题可以触发首块保护，占用两个正文块位中的一个；图表背景也因数字
通过该判断，而 `_navigation` 仅识别特定编号列表，未识别这种相关报告与坐标标签。

单变量验证：仅在诊断进程将“明确带元单位的金额”排除出年份识别，保持全部候选、
两个块位和 600 字预算，目标价恢复。将最小例中的金额改成 1930、2099 仍丢失，
改成 1830、2130、3030 则恢复，进一步确认这是四位数字分类问题。该“元”探针仅
用于确认原因，不能直接视为通用数值/时间解析方案。增加到三个块位也能找回答案，
但只是用更多内容掩盖选择错误，不作为修复方案。

### 建议实施顺序及验收

1. **先纠正时间识别和冲突语义。** 区分真实日期/年份、金额、带单位数量、产品或
   标识符中的数字；来源发布日期与陈述适用期分开处理。有明确时间语法或可靠表头
   才形成高置信时间约束，无法确定的四位数字不能触发硬性降级。金额识别不能只写
   “2030 元”例外，也不能直接关闭年份检查；要保留真实跨年冲突、预测期和历史对比。
2. **纠正标题保护与结构分类。** 首位保护只适用于实质内容，利用已有 chunk kind
   和段落结构，不能用“含数字”认定正文。来源首句柄、顺序和范围保持原样，标题
   不再强占正文回答名额。相关报告、坐标轴、署名等按结构降权；保留字段—数值
   成对的真实表格。用户明确查标题、目录或图表时应允许相应内容，不作一律删除。
3. **再完善“直接事实先、补充后”的选择策略。** 优先保护明确匹配问项、带数值/
   单位或完整结论关系的原文片段；单纯重复主体、日期不能当作已覆盖问项。随后补
   时间口径、否定、条件、解释等依赖内容。模糊语义保留原语义召回回退，不宣称规则
   已经理解所有问题，也不建立公司、行业、题目或答案词表。不要先加一套笼统的
   “答案分类器”掩盖已定位的具体缺陷。
4. **从选择一直验证到实际交付。** 本例应展示目标价及必要的一年期限、来源日期，
   不以仅出现数字作为完整通过。校验实际 JSON、span 偏移/哈希、对应成员 fetch；
   不仅断言内部候选命中。保留现有来源过滤、句柄、召回及 fetch 契约，预算不扩大。
   当前 native payload 超限会整条舍弃尾部命中而非截断片段，本例在此之前已丢答案；
   后续也要测试小预算路径，但不应将两个问题混为一谈。

验收至少覆盖：1930/2030/2099 等金额与真实同值年份的区别；其他单位、型号和代码；
含日期标题、相关报告与真实数值表格的区别；陌生主体和中英文问法；同主题解释不
新增查询词时仍可补充；否定、条件、预测时点不丢。先重放已有 57 题和本轮 40 条
作为回归（此后不能再称盲测），核对 RQ-06 恢复及 RQ-36 的补充收益，再另取未见
真实查询验收。该路径不需要新增模型调用，单独测量选择 CPU 耗时。
