“数据持久化”包含保证数据实际进入分析的服务端链路，不只建表。业务数据沿用现有 PostgreSQL
业务库，与语料库分开；运行轨迹和文件继续由既有受控文件存储承担，数据库保存关联和索引。

本文任务编号用于拆分设计。进入实施时按[任务规范](../agents/issue-tracker.md)为每项分别建立 issue，
仅 issue 维护执行状态；本文不增设产品进度真源，不实施迁移，不修改既有排期。
页面任务负责展示与操作，所有者、真实性状态、版本、幂等和预算必须由服务端强制执行。

## 2. 环境与共同接口

### DATA-00 实际环境与验证入口

**需求**：PR-BIZ-04/06；衔接[环境准备](web-storage-validation-environment.md)。

- 核实 API 进程、加载代码、解释器、实际 PostgreSQL 库/版本/schema、Run 根和前端代理；既有观测须刷新。
- 只读/正常测试先复用现有服务；改动版第二 API 使用同 PG 实例独立测试库、受限角色、数据根和按需端口。
- 检查启动孤儿恢复、多 worker/副本与共享库风险；不能新开端口后仍连接原业务库。
- 建立显式 PG 集成入口，防止自动测试夹具切回 SQLite；父子进程配置、模型来源、端口、测试身份均登记。
- 实例/卷故障才另设独立故障环境；不顺带升级 PG，不修改真实用户资金或持仓。
- 记录备份与清理清单；任何阶段的 readiness 都不能只用 healthz 200 证明。

**验收**：环境对应表、版本/路径清单与可执行验证入口齐备；配置不符立即失败，无静默回退。

### DATA-01 共用数据与操作契约

**需求**：PR-BIZ-01—05、PR-DATA-13、PR-WATCH-01—04；PRD §3、§8。

向 UI 和 Agent 工具提供同一份协议，字段/API 路径在此阶段确定，不把 PRD 建议路径当现成接口：

| 契约 | 必须明确的内容 |
|---|---|
| 数值与来源 | 十进制字符串、币种/单位、资产精度、业务时点、记录时间、来源及明确/待澄清状态 |
| 对象读写 | owner 由认证绑定；对象/版本标识、expected_revision、归档状态、前值与变更回执 |
| 幂等与错误 | 同键同内容返回原结果，同键不同内容拒绝；字段定位、冲突、不可用、限额与可重试条件 |
| 分析提交 | JSON/multipart 共用 investment_input；仅保存不建 Run；保存并分析返回原子提交结果和 Run/派发状态 |
| 快照与补数 | 不可变快照、请求状态、回答记录、来源/后续 Run 关联、必要字段准入 |
| 监控与通知 | 规则版本、触发方式、创建/恢复策略、冷却/布防、事件/Run 关系、游标与已读状态 |

状态分属业务对象、监控规则、触发事件、派发任务与 Run，不能将“已触发”“分析成功”合并成一个标志。
形成与现有 Run 状态的映射；input_required 先作为明确结束原因，不宣称已有原 worker 暂停恢复。
服务端时间统一存储并在 UI 本地化，区分业务时点、行情观测/接收时间及分析开始时间。

**验收**：提供有效/缺失/歧义/冲突/超时重试/无权的协议样例；未定默认值有明确冻结门槛。

## 3. 业务数据与分析链路

### DATA-02 业务模型与迁移

**需求**：PR-DATA-13、PR-BIZ-01/04；PRD §3、§5.2。

- 建立账户、计划及不可变版本，持仓快照、成交更正链、研究关联、独立策略版本与来源引用。
- 金额/价格/数量采用适合资产范围的精确数值；定义比例单位与盈亏比口径，计算值保留公式版本及输入引用。
- 缺失与零分开；计划与实际成交分开；手工持仓和成交不重复累加，多币种不隐式换算。
- 通过外键、唯一约束及服务校验保障对象归属与关系；版本不能原地覆盖。
- Alembic 覆盖空库与现有库升级，核验历史行兼容、锁影响与回退/前滚策略；不把旧聊天批量转换为已确认事实。

**验收**：真实 PG 验证精度往返、约束、版本不可变与迁移；当前生产库不用于试跑迁移。
覆盖 AC-01、03、04、09、22、26。

### DATA-03 统一写入与真实资料准入

**需求**：PR-BIZ-02/04；PRD §3.4、§4.3、§5.3。

- 表单 API、Agent 操作工具使用同一服务；owner 从认证取得，模型不能指定其他用户身份。
- 保存业务变更、版本、审计和幂等结果；使用 expected_revision 防止覆盖并发修改。
- 用户明确资料直接保存，不重复确认；假设、估计、疑问候选仅保留草稿/回答记录，不进入有效计算字段。
- 账户/口径不明必须澄清；附件、历史抽取、模型建议不直接写实际资金/成本。
- 不确定更正保留旧版并标记受影响用途待澄清，不能默默使用旧值完成本轮计算。
- 补偿版本实现业务撤销；同键重试不重复写版本，相同键不同内容明确拒绝。

**验收**：表单、聊天、JSON/multipart 均无法绕过；语义不以问号/关键词替代。
覆盖 AC-02、04、05、22、25—28。

### DATA-04 查询、关联与历史

**需求**：PR-BIZ-01/04、PR-DATA-13；PRD §3.1、§8。

- 提供账户/计划/持仓/成交/策略列表、详情、版本历史与研究关联读写。
- 第一版一个 Run 一个主账户/主计划；研究可关联多计划，跨研究复用同一业务对象。
- 查询按认证归属过滤；无权与不存在不泄漏区别；归档对象不能成为新分析有效选择。
- 保存返回服务端实际版本；避免从浏览器或聊天摘要恢复业务真源。

**验收**：跨刷新、登录、研究绑定一致；双用户直接请求任意对象/版本 ID 均受控。
覆盖 AC-01、03、09。

### DATA-05 Run 快照与重算

**需求**：PR-DATA-13、PR-BIZ-02/04/05；PRD §4.4、§6。

- 保存 schema 版本、对象版本、完整解析有效值、必要字段来源与明确状态；只引用 ID 不算快照。
- 手动 Run 在提交时冻结；排队/执行中资料变化不修改快照。旧非业务 Run 无快照须明确标记，不用当前值回填伪造。
- 保存并分析前完成必要字段校验；不支持假设覆盖。未成交可做支持的计划分析，但不得执行依赖实际成本的计算。
- 重算关联新旧 Run、使用新快照，并通过调度保证停止旧执行后的同研究串行；排队任务采用取消重提。
- 快照查询按 Run 所有者授权，历史报告继续读取旧版本。

**验收**：A/B 不同时点输入固定；JSON/multipart 同规则；跨 worker 仍使用同一快照。
覆盖 AC-05—07、09、10、26、27。

### DATA-06 原子提交与持久派发

**需求**：PR-BIZ-04；PRD §5.3—5.4。

- “保存并分析”的业务变更、版本/审计、快照、queued Run 与 outbox 在同一数据库事务提交。
- worker 仅在提交后领取任务；失败回滚不显示完整成功，提交成功但启动失败保留可恢复派发状态。
- 用唯一约束、租约/领取版本和研究级互斥实现重试与串行；租约过期要核定旧 worker 状态，不能仅重新领取就启动第二个执行。
- 派发重试复用原 Run，不重复业务写入；外部调用不确定结果记录尝试并限制重试，不承诺绝对只计费一次。
- 与既有孤儿恢复统一职责，避免内存 handles 扫描把其他存活进程任务错误收尾。

**验收**：事务各边界故障、启动失败、崩溃领取、重复投递及并发派发不丢任务、不重复创建 Run。
覆盖 AC-05、15、23；同研究不并发执行。

### DATA-07 持久补数与续接

**需求**：PR-WB-07、PR-BIZ-03；PRD §4.5。

- 持久保存用途、字段/单位、来源 Run、已知版本、状态、回答及后续 Run 引用。
- 原 Run 以 input_required 原因结束；请求先保存再通知，不依赖活 worker 等待。
- 明确回答的保存、业务更改、快照及后续任务建立形成原子/可恢复操作；歧义回答只记回答，请求保持待补充。
- 同一请求仅生成一次有效续接；过期、取消、已回答、研究删除和并发回答有冲突结果。

**验收**：服务/页面重启后可续接，原快照不改；不走工具 approve 接口。
覆盖 AC-08、24、25、28。

### DATA-08 业务上下文与工具接线

**需求**：PR-BIZ-05、PR-DATA-13、PR-DATA-04；PRD §6、§8。

- 实现按认证身份和 Run 精确读取的 InvestmentContextResolver，返回必要值、来源、缺失与待澄清字段。
- 经真实 server worker → workflow 路径显式注入模型请求；同 Run 不重复追加，压缩后保留或重建同一快照。
- 固定规则/工具与动态业务资料分开；资料作为数据而非高优先级指令，不取全账本或每笔报价。
- 计算工具与工作流共同检查必要字段；业务工具进入白名单/server profile，market/sizing 等按 PR-DATA-04 验证可达。
- worker 使用最小必要数据或受限 resolver，不交付全库凭据；不向通用 ReAct 内核写业务语义。
- 记录输入/输出、缓存读/写、调用数；缓存失效正常重建，不定时调用模型保活。

**验收**：真实 worker 请求可验证使用冻结值；长对话压缩和模型切换不靠历史摘要猜数。
覆盖 AC-10、20、24、27、28。

## 4. 监控事件与自动分析

### DATA-09 规则持久化与管理

**需求**：PR-WATCH-01；PRD §7.1。

- 保存标的/市场/币种/报价口径、阈值/方向、有效期、次数模式、研究/计划关联和分析意图。
- 规则版本保存创建时条件已满足策略、断线恢复策略、预算及重复模式的冷却/重新布防参数。
- 明确自动分析指令才创建分析任务；提醒规则不调用模型。计划改版不静默修改已保存阈值。
- 创建/编辑/暂停/恢复/取消有版本、幂等和归属校验；记录最近检查及有效行情时间。

**验收**：重启后规则及状态存在，生命周期操作可追溯；C 只开放单次模式，D 才开放验收通过的重复模式。
覆盖 AC-11、12、21。

### DATA-10 行情判定与防重复唤醒

**需求**：PR-WATCH-01/04；PRD §7.2；补充阈值附近反复波动讨论。

- 普通程序验证来源、标的、币种、时效、顺序与重复报价，再判断上穿/下穿/区间；不使用浮点相等触发。
- 单次规则触发后消耗该次触发资格；分析失败不恢复成未触发。规则状态、事件和派发意图原子保存。
- 重复规则持久保存判定基线、布防状态、冷却截止与触发序号；重新布防采用与触发阈值分离的边界。
- 只有重新布防、冷却满足及新的有效穿越同时成立才创建新事件；冷却计时到期不自行触发。
- 明确冷却中发生穿越的处置：本设计建议只记录抑制原因，不在到期时补发；后续需重新布防与新穿越。
  该选择在 DATA-01 冻结并在 UI-08 说明，不能静默遗漏语义。
- 确认持续时间若启用，以新鲜观测为依据；断线/行情陈旧不能靠计时器自动认定持续达标。
- 创建时已达标、重启首次报价和行情恢复分别执行已保存策略；不能凭空补造断线期间的穿越。
- 事件唯一身份结合规则版本和一次触发资格；重复投递、并发判定不重复消耗。阈值抖动只更新观测/抑制记录，不反复建分析。

**验收**：固定时钟和行情序列覆盖 19.99→20.02 上穿、10 分钟阈值附近往返、一直越线、
冷却结束未布防、回落再穿越、暂停/恢复、乱序重放与重启。示例价格/时间只用于测试，不是默认参数。
覆盖 AC-11、12、15、16、21；监控链模型调用数为零。

### DATA-11 自动分析、合并与预算

**需求**：PR-WATCH-02/03；PRD §7.3—7.4。

- 事件先排队；真正调度创建 Run 时重新核对规则/研究有效性、用户权限、有效期、最大延迟和预算。
- 按执行时最新有效业务版本创建不可变快照；与手动提交时冻结的语义分开。
- 在同一研究内与手动 Run 串行；事件→Run 幂等。待派发同标的事件只在规则意图/账户/计划等兼容时合并，
  保留所有原事件及合并去向，不能跨用户/研究合并；已运行 Run 的输入不因新行情改写。
- 触发快照和分析开始行情分别保存来源与时点；执行时刷新行情，过期事件不伪装实时分析。
- 原子预留每规则/用户次数、并发及 token 预算；实际调用尝试记账，释放/结算幂等，不能把模型重试视为免费。
- 达限保留事件并说明原因；缺字段转 DATA-07；失败重试关联原事件与尝试记录，不因再次触价重复建任务。

**验收**：触发到同研究自动 Run 无需再点确认；取消/归档与领取竞争时不启动失效任务；
延迟、改版、缺资料、预算竞争、重试及合并均可追溯。覆盖 AC-13—16、21、24。

### DATA-12 业务事件与通知

**需求**：PR-WATCH-03、PR-BIZ-03/04；PRD §5.1、§7.4。

- 持久记录 Run 外资料变更、补数、触发、派发与故障通知；不复制 token delta/工具轨迹库。
- 用户级事件查询、SSE、游标续读和已读状态受所有者隔离；先提交再推送。
- 游标过期明确要求全量同步；重复推送按事件 ID 去重，通知可定位研究、规则和 Run。
- 已启动 Run 沿用 per-run SSE；HTTP 查询是恢复真源，连接存在不等于后台在线。

**验收**：关闭浏览器再打开能恢复事件/已读，断线补读无业务事件丢失；用户之间无法读取。
覆盖 AC-09、15、16、21。

## 5. 生命周期、恢复和工程验收

### DATA-13 归档、删除与取消

**需求**：PR-BIZ-06、PR-WATCH-04；PRD §5.4。

- 账户/计划归档停止新采用并暂停相关监控，保留旧快照；删除研究取消其规则/待派发并停止活动运行。
- 共享账户、计划及成交不随单一研究删除；清聊天和文件 revert 不修改业务事实。
- 取消动作与调度竞争使用事务/状态版本再检查，重试不复活已取消任务。
- 发布前定义业务数据、快照、审计、轨迹、产物和备份的保留/物理删除范围；软删除不等于擦除。

**验收**：跨研究共享、归档历史、取消与领取竞争及重复删除通过。覆盖 AC-17、18、21。

### DATA-14 备份、安全与文件引用

**需求**：PR-BIZ-06/04；PRD §5.4、§8。

- 逻辑恢复可在原 PG 实例的独立库与测试目录进行；实例/卷故障使用独立故障环境。

### DATA-15 分阶段联合验收与成本

**需求**：全部关联 PR-*；PRD §10。

- 实际供应商协议/行情时效在受控试运行中另验；模拟行情或模型通过不能称生产实时性/计费已通过。
- 记录代码/配置版本、环境批次、测试对象、结果及脱敏证据；不确定 LLM 尝试如实计量。

**验收**：本阶段关联 AC 全通过或明确未通过，不因建表/页面可见就完成；不承诺尚未实测的节省比例。

## 7. 实施顺序与范围边界

1. DATA-00/01 核定环境与契约；UI 可据契约并行开发，真实联调依赖服务端。
2. A 交付 DATA-02—04、13/14 的资料范围，并通过 UI 资料闭环。
