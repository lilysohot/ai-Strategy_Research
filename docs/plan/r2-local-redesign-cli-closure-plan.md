## 1. 执行目标与明确不做的事

保留现有证据、入库、检索、财务复算和市场工具。修正 R2 的职责与验收错位，然后在 CLI 实现可重复、
可回取证据、可解释失败的材料—数据—分析闭环。CLI 既包括明确参数的命令，也包括终端 Agent 的
实际调用；只有 scratch 脚本能运行，不算正式 CLI 接通。

三条路径各自成立：

| 路径 | 输入 → 输出 | 不得依赖 / 冒充 |
|---|---|---|
| 材料 | 单份文件或指定 EvidenceRun → 忠实材料理解 → 出处回取 | 不依赖行情、入库或策略卡；不把材料数字称作独立核实的观测 |
| 数据 | 合法且已确认的 THS 端点 → 固定调用证据 → 受控计算 | 不依赖 R2；不以材料填补接口缺口，不假定已有政府统计/一致预期权限 |
| 综合分析 | 已验收材料 + 所选观测/计算 → 只读关联报告 | 不覆盖任一来源，不把系统推断冒充作者论证 |

当前不做 Web 接入、前端/SSE/账户改造、第二套 claims 数据库、全库重抽、全量迁移、通用 OCR、
无限长上下文或新框架。BLS 暂缓状态不变。Web 暂缓是排期调整，不是删除长期产品目标。

## 4. R2 Interface 重设计方案

P1 细化并冻结为 [Interface/终态/评分契约 v1](r2-p1-interface-contract.md)。以下为整体设计方向；
精确 P1 不变量、容量、语义未验证边界与 P2 移交以该契约为准。见 [P1 报告](../../.scratch/corpus-evidence-pipeline/r2-p1-report.md)。

### 4.1 对外一个契约，内部按职责拆分

建议的概念 Interface（不是已实现函数签名）：

```text
固定 EvidenceRun + MaterialRequest（范围、任务/协议版本、预算引用）
    → prepare：来源/配置校验、有限义务计划与容量检查
    → execute：注入模型或历史响应 Adapter，逐项处理
    → validate：证据、终态、语义支持与覆盖状态
    → MaterialRun + Audit + 可选 Readout
```

Interface 不再要求普通调用者自由组合 staged_jsonl、slot_protocol、容量和关系布尔参数。
已批准配置封装为版本化任务契约；仍需显式选择范围/阶段/预算，默认 0 调用，不默认跑全文或关系。
现有旧入口作为显式兼容路径保留，不直接换掉默认；新路径与验收必须跨越相同 Seam，不能一套生产
逻辑、一套“为了考试”的 scratch 逻辑。由方案评审确定新显式入口名，不提前宣称命令已存在。

模型是真外部依赖，注入真实 Adapter 与 replay/fake Adapter；本地纯处理直接测试，不为每个函数
建立抽象层。数据库只属于明确保存操作，不进入纯语义核心。测试先证明新 Interface 覆盖旧场景，
再判断 R2 私有重复测试是否可替换；本阶段不得删除公共模块或历史安全回归测试。

### 4.2 来源片段与原子义务分层

- 不改共享 parser。在固定源坐标上构建 R2 私有片段引用，系统拥有 source_rev、parse_rev、
  packet_id、locator、start/end、内容 hash；坐标单位与边界规则写入契约。
- “结构片段”不宣称等于“原子命题”。一段多命题应产生有限子义务；无法可靠分解时记录 unresolved，
  不靠一槽只准一条的规则隐藏遗漏。父子义务必须可追踪，不能在模型执行中无限派生。
- 系统先冻结最大深度、最大子义务数和总容量；拆分超过容量时在调用前停止。37 槽只是旧版计划，
  不要求新协议为了保持数量而重复旧粒度错误。
- 模型填写 obligation_id 与语义，不重新创造源坐标。证据用稳定 span 身份回取；文本重复本身不拒绝，
  但错 source、越界、不匹配文本、错误义务绑定必须拒绝。短引文用于显示，不再承担唯一身份全部职责。
- 相邻上下文只作为明确来源引用提供；跨包组合使用多条原始 span，不伪造一个不存在的连续引文。

### 4.3 字段与终态

每个字段区分 source_observed、validated_transform、model_interpreted、unknown 四种来源；这是新
契约设计项，不是当前已有数据字段。规则只做可验证转换，不凭“专家/投资者/复盘”等标签赋予问答
功能、极性或行为时间。数值必须绑定原文值和单位；无证据则 null/unknown，而非沿用模型数字。

义务终态建议：extracted、no_supported_item、unresolved、failed、deferred；排除项另记依据。
每个义务恰好一条终态，未知枚举/重复 ID/缺终态都不能完整通过。合法记录逐项保留，坏记录只阻断
依赖项；关系端点不合法时不得补造。no_supported_item 必须可核查，不能用它刷“全完成”。

分别报告 source_scope、obligation_coverage、protocol_completion、content_fidelity、semantic_status、
relation_status。材料类别 degraded 与任务验收状态分开；不存在一个可替代全部维度的 complete。
选择子范围、关闭关系或预算用尽，必须显示范围和未完成项，不能在 CLI 显示全文理解成功。

所有参数/预算/版本校验先于构造真实模型、调用、保存；执行结果与显式持久化分离。记录实际 provider、
model、配置/协议 hash、调用编号、token/耗时及异常；不记录密钥和隐藏推理，不把请求的 model 标签
当成实际执行模型证据。

## 5. 验收器重设计：先能拒绝错误，再衡量改进

### 5.1 可组合且失败关闭的门

| 门 | 判定对象与反例 | 准入要求 |
|---|---|---|
| G0 身份与范围 | 错 revision、越界、错义务、重复/缺失 ID、评分配置漂移 | 绑定完整；非法输入全部拒绝 |
| G1 终态与容量 | partial、截断、漏终态、重复终态、超预算、无理由拒绝 | 冻结必做义务有唯一合法终态；未解决项不得计为完整 |
| G2 内容忠实度 | 虚构 text、删条件、翻转否定、扩大适用对象、把计划当成交 | 关键错误 0；未知裁决不能计通过 |
| G3 字段语义 | 归属、话语功能、极性、时间、数值及未知一致性 | 使用前瞻冻结的逐轴标准；不得只测标签存在 |
| G4 关系 | 同页共现、错端点、无依据 supports、问句当承诺 | 正负控均有效；按关系类型报告，不扩大已支持范围 |
| G5 旧流程隔离 | R2 不可加载/失败/0 预算，旧证据、引用、计算及检索 | 固定快照不变，公共代码保护检查通过 |
| G6 逐类非回归 | 四类开发、六微范围及既有财务/取证保护 | 同 scorer 同范围比较；任一受保护指标下降即停止 |
| G7 CLI 交付 | 正式命令、取证、重放、退出状态与实际 Agent 调用 | 后续 R3/D/A 阶段验收；不拿脚本成功替代 |

阈值使用显式 `min`/`max` 与分母，不以统一“小于”处理错误计数。空分母标 not_applicable，范围
缺失标 not_evaluated；任一必需门未评估即不放行。关键错误独立否决，不能由均分或成功率抵消。

P1 已以前瞻契约冻结新门槛及分母规则：保留旧开发 item recall/precision=1.0、semantic≥0.9 的
最低要求，关键归属、否定、条件、行为和证据零错误；新增真实忠实度、终态及未知矛盾检查。
尚未实现 scorer 或裁决新原子分母；**不替换旧 policy**，不能看到候选结果后下调。

### 5.2 零模型如何验证语义，不能夸大确定性评分

坐标、hash、容量与字段一致性可确定性核验；任意自然语言转述的忠实度不能仅靠字符串或引文命中
普遍证明。零模型阶段采取两层：

1. 合成最小正反例与已知失败构成 mutation suite；变异后的合法 hash 也必须被业务门拒绝。
2. 固定开发范围使用已裁决的命题/约束金标；未裁决转述列入人工复核，复核记录绑定输出文本 hash。
   text 改动立即使裁决失效。不能允许模型或同一抽取规则自行给自己盖“忠实”章。

如果现有金标不足以裁决内容，先补开发标注并评审，不调用评审模型来假装“零模型”，不接触留出。
独立评审模型如未来确有需要，必须另列调用预算，不隐含在 scorer 中。

最低反例库存：重复短引文合法定位；错 source/坐标；编造 text/数字；否定/条件丢失；说话人身份与
话语功能混淆；意图/声称执行/复盘时间混淆；unknown 与已填值矛盾；一段并列多命题；寒暄误抽；
非法终态/截断/超容量；无依据关系；评分上限方向；跨类目局部退化；hash/预算漂移；非法参数先保存。

### 5.3 基线与候选如何公平比较

- 保留 v12/v13 历史 verdict；用新 scorer 重评两者并明确标为诊断基线，不追溯改写旧报告。
- v13 为当前工作树实现/输出基线（不代表已部署放行）；v12 已验证正确的具体项作为补充保护资产，避免把 v13 已有退化当
  新的合格下限。不得从不同版本各取最好值拼成一次实际通过的“虚构基线”。
- 每个样本同时列基线、候选、差值、分母和未裁决项；先前未经全文裁决的额外项不能直接计 precision。
- 有原始响应才进行 extractor replay；只保存了 MaterialRun 的成功案例只能做产物评分或新反例，
  不能伪称完整原始响应回放。协议变更需要模型输出新字段时，缺失字段不得由 gold 自动补齐。
- 新协议可先用 fake 验证端到端，用兼容响应验证可重放部分。若关键逐类非回归无法在现有资产上
  建立，停在零模型阶段，报告缺哪些裁决/资产；不能把 not_evaluated 当通过后申请真实调用。

## 8. CLI 端整个数据链路如何打通

### 8.1 现有与待建能力分开

现有正式命令：`python -m plugins.corpus.service` 下的 extract-claims、claim-runs、claims、
claim-evidence、derive-claims、reconcile-claims 等，按精确 run_id 工作；入库是独立显式操作。
`frontier-agent` 提供 react/agent_team 与 --no-tui、--input、--max-turns、--max-tokens 等。
这些能力存在，不代表完整材料/数据/综合产物已打通。

待建 CLI 能力如下，表中名称表示操作意图，**不是可直接复制运行的现有子命令**：

| 操作 | 输入 / 输出 | 要求 |
|---|---|---|
| 材料理解计划与执行 | source 或 evidence_run_id + scope + contract + budget → MaterialRun/Audit | prepare 默认零调用；execute 必须显式预算；未入库可用 |
| 材料读取与回取 | 精确 material_run_id/产物 + item/span → 原文及 readout | 不选“最新最好”，不将生成摘要当原始证据 |
| 数据采集 | 已消歧 thscode + 端点参数 + CLI Run → 固定 Observation/调用记录 | 复用既有市场 Adapter；每个结果绑定本次逻辑调用 |
| 数据计算 | 精确观测引用 + 已批准公式/参数 → 计算产物 | 不从报告中偷取缺失输入；输入错位拒绝 |
| 综合分析 | 材料引用 + 观测/计算引用 + 用途 → 只读分析报告 | 可比性先验；作者、供应商、系统三者分开 |
| 校验与重放 | 已保存运行包 → 各门结果与证据检查 | 无网络重放；缺证据给 unknown，不能宣称已验证 |

优先沿用既有 CorpusService/market Interface 和 apodex 的运行/产物约定。P6/P7 设计评审后确定
最小 CLI 挂载点；不提前增加第二套 TUI、Agent runtime 或通用 workflow 框架。

### 8.2 精确 Run 与市场调用证据是必做项

现有 `plugins/market/trace_store.py:121-134` 的 resolver 解析 request_id 后未按其过滤，只渲染标的
相关记录。故“有 trace”不足以证明“这个数字来自本次指定调用”。D1 必须实现并验收：

- CLI execution_id 与 apodex session/run 目录、MaterialRun、EvidenceRun 各有显式关联，不复用同一
  字符串掩盖不同身份；同一可恢复会话中的不同运行也须区分。
- 逻辑调用 ID、provider request ID、重试 attempt ID 分开；请求参数、响应内容 hash、来源时点、
  获取时点、模型/工具配置与运行身份绑定；聚合行情/估值保留所有输入调用引用。
- resolver 必须按运行与具体调用回取；跨 Run、错误 request_id、同标的旧记录、损坏/缺失 trace
  不能过“已验证”门。缓存可用但明确来源调用，不伪装本次新请求。
- trace 保存失败可以保留取数结果供提示，但认证级交付必须 unknown/未验证；不能静默通过。

这属于 D1 的局部扩展，不在 R2 私有重构中修改市场模块，也不要求重写整个 transport。

### 8.3 CLI 产物、保存与失败语义

运行包建议包含 manifest、材料产物、精确引用、市场调用记录、计算/分析结果、各门验收结果及
人读 Markdown 报告。沿用 `.apodex/runs/<session-id>/outputs/` 与现有 trace 约定；实现时明确
多次运行子标识。不为 MaterialRun 新建独立观点数据库；优先内容寻址文件产物，复用 EvidenceRun
存储与引用。source 文件未入库且未保存 EvidenceRun 时，需要明确保存可重放的证据快照与来源
revision；否则只可称临时产物，不能承诺原文件删除后仍可回放。

默认读取/prepare 不写库。保存显式且幂等，非法参数在写入前拒绝。产物受本地权限保护，密钥和
私有响应不进入公开日志；源文档中的指令只作为内容。新 CLI 退出码拟定 0=请求范围所需门通过，
1=有部分结果但未通过，2=参数/绑定/环境导致未启动；旧命令退出码保留。错误也输出结构化状态、
已保存产物 ID、是否发生调用/写入及下一步，不能把非零退出码等同于“什么都没保存”。

CLI Agent 接入必须验证实际工具可见性、真实调用路径、只读输入、输出隔离、取消、恢复和预算。
原有注册白名单与 profile 不全局替换；如需新材料工具，按 P6 白名单单独接线并回归旧工具集合。
模型不能直接跳过必需门把失败摘要写成成功报告。终端一次性命令与 Agent 都读取相同 gate 结果。
这里的 gate 是运行时 ValidationReport，不要求新用户文档提供开发金标；金标评测 EvaluationReport
独立运行，不能导入生产层或被运行时“证据合法”状态替代。详见 §11。

### 8.4 CLI 端到端验收矩阵

| 场景 | 必须看到的结果 |
|---|---|
| 未入库、无数字、缺专家标签的可读材料 | 可生成来源忠实的有限范围产物，未知明示；无 DB/市场依赖 |
| 已入库材料检索 → fetch → 固定证据版本 → 材料理解 | 引文逐字回取；R2 开关不改变旧检索与原文 |
| 材料抽取失败/取消/预算 0 | partial/deferred 与调用数一致；旧结果不覆盖，不自动重跑 |
| 材料内财务复算 | 原有公式和输入引用一致，明确“来源内部核对” |
| 无材料，仅市场数据与受控计算 | 独立完成所选数据用途，不要求 R2 |
| 缺密钥/无权限/超时/空数据/null | unknown 与经确认 absent 分开，null 不变 0；不借材料填补 |
| 错 Run/request_id/旧行情、错复权/期间 | 验证或计算拒绝，保留原始观测与理由 |
| 材料与数据口径不兼容或观点冲突 | 双方证据保留，不可比/系统推断明示，不改作者观点 |
| 保存后新进程加载、无网络重放 | 指定版本可回取、计算可复现；不自动选择另一成功 Run |
| 真实终端 Agent 调用 | 工具路径和交付可追踪，安全/预算/取消/恢复有效；不是手工拼 JSON 的模拟通过 |
