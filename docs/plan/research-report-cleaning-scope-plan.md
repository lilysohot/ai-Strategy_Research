## 1. 为什么这样调整

两轮证据不支持“只要移除纪要就能通过”，也不支持把问题都归到模型或清洗：

- 非纪要 v13 历史微范围仍为 24/25 item，公司评级绑定失败，行业类型 12/14。
- 最新 P4 首批本来就是普通研报，8 个响应中 4 个枚举非法；另有运行依赖 gold、绕过正式执行
  Interface、字段来源缺失和 scorer 定义错误。因此不能继续围绕纪要加补丁或直接换模型解释一切。
- 55 项基础工程测试通过、1 项 PG 测试跳过，只证明所测用例；不能代替三类研报业务验收。
- 宏观旧规范字段仍 0/3，这是历史字段测试，不是新 R2 的 3 个原子义务，更不代表宏观整体不可读。

依据：[非纪要实验](../../.scratch/corpus-evidence-pipeline/r2-nonminutes-report-v1.md)、
[P4 归因](../../.scratch/corpus-evidence-pipeline/r2-p4-root-cause-and-legacy-review.md)、
[已有清洗与财务修复](../../.scratch/corpus-evidence-pipeline/semantic-repair-report.md)。

**方案性质：收缩业务范围，保留已验证能力，重整局部执行链。** 首阶段不替换 PDF/DOCX 解析技术，
不换模型，不建设另一套来源库，也不扩大同花顺或 Web 范围。只有在对应层出现可重复失败时，才评估
该层替代方案。源格式不规范是需要处理的输入条件，不是可以自动降低忠实度要求的理由。

## 2. 明确处理范围：先材料类型，再研究领域

| 材料 | 本阶段处理 | 主要内容 |
|---|---|---|
| 公司研报 | 主线 | 公司深度、业绩点评、盈利预测、估值与评级、公司专题 |
| 行业研报 | 主线 | 行业深度/专题/周报、供需与竞争格局、产业链、分析师书面问答 |
| 宏观研报 | 主线 | 经济/政策/利率/流动性/宏观策略研究；保留原始口径，不开启新宏观计算 |
| 电话/会议/交流纪要、业绩会实录 | 范围排除 | 包括有专家标签、无标签对话、转写或问答实录；不投入本阶段模型预算 |
| 个人交易、复盘、独立市场评论、其他材料 | 主线外保留 | 保留历史和必要兼容回归，不新增相应模型优化；不冒充三类研报样本 |
| 混合材料、类型/领域不确定 | 待人工复核 | 先列原因和定位；不凭 fallback 自动纳入或永久删除 |

“公司/行业/宏观”是 `research_domain`；`research_report/conference_minutes/earnings_call` 是
`material_type`。现有 `classify_doc_kind()` 只返回三领域，且可能 fallback 到 industry，**不能用它
代替材料准入**。同一个规则集可以服务三类报告，但清洗策略和验收必须按类分开。

准入规则（拟实现）：

1. 先登记路径、来源哈希、来源登记/用户标签，识别已确认纪要；不先全篇抽取再决定是否剔除。
2. 其余开发材料用标题、署名、正文结构等可解释信号确认材料类型；疑似对话实录进入复核。
   规则不能仅检测“专家”字样，也不能仅凭“会议、Q/A、问答”关键词自动排除。
3. 《化工十问十答》保留为行业研报；研究报告中分析一次政策会议、引用一句访谈也不整篇剔除。
4. 以访谈实录为主体且含分析附录的混合材料先隔离，人工决定整篇排除或明确准入的独立章节。
   若仅纳入章节，未纳入部分进入范围台账，不宣称全文完成。
5. 人工决定优先于启发式规则，记录审阅人、时间、原因及原文依据；不改写领域冒充类型纠正。
6. 默认活动语料与新批次执行必须共用准入决定；历史审计仍可显式回取排除材料。新文件改变哈希
   后重新评估，不能继承另一版本的批准。

建议新增独立的准入记录：`admission=in_scope/excluded_by_policy/review_required`，同时记录
`material_type/research_domain/policy_version/source_sha256/reason/review_ref`。这些是待实现的契约，
不是当前已存在的命令或数据库列。解析状态另记，`excluded_by_policy` 不计作模型失败或来源无数据。

## 3. 数据清洗做什么，不做什么

**清洗的目标是忠实、可定位、可供抽取的材料，不是把所有内容变成“确定事实”。** 分三层交付，
避免再把结构解析、模型语义、验收缺陷混成一个分数。

| 层 | 具体改造 | 输出与通过条件 |
|---|---|---|
| C0 准入与登记 | 版本、去重、材料类型、研究领域、人工覆写、排除台账 | 每个登记来源有明确去向；已确认纪要不会进入默认执行 |
| C1 保真结构清洗 | 标题/章节、分栏顺序、正文/表格/脚注、噪声标记、坐标映射 | 范围内每个结构区有处理状态；引用能回到原文；无法解析的区域显式保留 |
| C2 语义整理 | 有限候选与字段义务，模型填写类型/角色等，独立校验 | 协议、证据、语义、覆盖分开报告；不能靠全部拒绝得到通过 |

### 3.1 通用规则

- 原始文本与清洗视图分离。页眉页脚、目录、免责声明、评级说明等可以不参与候选，但原文保留，
  清洗视图记录剔除原因和坐标；“评级说明”与“首次覆盖，给予买入评级”必须有成对反例。
- 断行、空白和字符归一保留映射；数字、负号、倍率、日期、主体、否定与条件不得改写。
- 表格保留标题、列头、行名、单位、期间、脚注与单元格位置；正文与表格解读共用来源身份。
- 需要 OCR 或阅读顺序无法验证时输出 `review_required/needs_ocr` 等具体原因；范围台账不得隐藏
  这些部分。首轮不新接 OCR，不为追求通过率静默删掉困难页。
- 无数字评级、观点和定性预测必须可成为候选；取证不要求先成功抽取数字 Claim。
- “某机构称”“引述管理层”等归属必须保留；剔除纪要不意味着普通研报可以忽略转述身份。

### 3.2 按主类目处理

| 类目 | 首批修复目标 | 必须守住的反例 |
|---|---|---|
| 公司 | 重复短引文用 source/packet/span 消歧；评级与评级说明分开；财务表头、A/E/F、原单位和期间对应 | 买入评级不丢；预测不变实际；客户销售额不变公司总营收；源净利率不擅自换公式 |
| 行业 | 多对象不借用单一 ticker；书面问答成组保留；供需/产能/周期中的观点、预测、条件与风险分开 | 问句不是事实/承诺；risk 属 statement_role，不是 semantic_type；多个指标/单位不能串接 |
| 宏观 | 原指标、原值/单位、同比/环比、实际/预期/前值、期间和文档日期分别保留；只做有依据的规范投影 | 不用发布日期补年份；“万”不猜成岗位单位；来源宏观值不升级成已核验政府观测 |

个人复盘仅保留“意图不等于成交、复盘不倒填当时理由”的已有兼容反例，不占主线新模型预算。

## 4. 把 R2 收口成一个 Module，而非第四条试验链

拟以 `CorpusService.understand_material` 为正式业务 Interface，内部统一来源解析、候选规划、
有限执行及运行时校验。CLI、fake/replay 和开发试验跨同一 Seam；开发 scorer 在运行之后读取
独立金标。不要再复制一份只能在 `.scratch` 通过的抽取器。

```text
准入清单 + 原文件/精确来源版本
    → 保真 EvidenceDocument → 确定性结构区/候选/义务 → 预算执行 → MaterialRun
                                                  ↑             ↓
                                     real / fake / replay Adapter
                                                        独立 scorer ← 开发金标
    → CLI 保存 / 查询 / 逐字取证 / 重放（与上述同一 Interface）
```

### 4.1 有限义务保留，但纠正其来源与完整性定义

- planner 只读来源、独立元数据和版本化规则；禁止读取人工 evaluation projection 或 gold 来决定
  item 边界、身份和数值。系统发现的是有限候选，不声称它们已经是全部正确原子命题。
- 每个候选携带来源坐标、上下文、需填写字段及适用条件；复合命题能否按规则拆开必须可复核。
  无法可靠切分标记复核，不能为了适配 gold 秘密增加切分规则。
- 两份台账分开：结构区台账说明范围是否被扫描；义务台账说明每个候选的处理终态。
  gold 只在独立评分时衡量候选/最终 item 的召回；候选全部完成不等于全文语义完整。
- 无候选但原文存在已标注目标、超容量、被筛掉的定性观点均必须导致覆盖缺口，不能算作 absent。
  未发送、非法响应、合法拒绝、有效 item 分别计数；合法拒绝仍可能漏掉金标目标。

### 4.2 字段协议先修正，不靠追加枚举掩盖错误

- semantic_type 维持 fact/forecast/opinion/behavior/unknown；risk/condition 属 statement_role，
  question/answer 属 speech_role。单纯问句不能为了填 semantic_type 被强写成事实。
- 每个字段明确定义、枚举、适用条件、可空性、unknown 原因及正反例；同一契约生成请求和校验。
  没有身份依据的字段保留 unknown，不把 gold 中的 speaker 映射当系统事实。
- 数值保留原文、数值分量及各自单位/位置；范围、多个数值不强塞单标量。
  可执行规范化保留规则版本和输入定位，不以金标专用转换名代替实现。
- `unknown`（适用但不知道）、`not_applicable`（字段不适用）与业务排除不混用；是否入分母由
  前瞻契约确定。协议合法、证据合法与语义正确是三种结果。
- 请求/响应、attempt、已预留预算和检查点可回放；超时和崩溃不会触发隐式二次调用或丢失记录。

### 4.3 修改与保留清单

| 对象 | 本方案处置 |
|---|---|
| `plugins/corpus/evidence.py`、`ingest.py`、`metadata.py` | 按明确失败点局部修改；共用源身份/定位，检索文本与证据视图允许用途不同，但不允许出现两套相互矛盾的事实 |
| `material_semantics.py`、`_r2_plan.py`、`_r2_runtime.py`、`_r2_audit.py` | 选取通过验证的实现归并；去掉重复执行和旧试验选项，不要求三条失败路径永久兼容 |
| `plugins/corpus/service.py` 及语料 CLI | 保持单一业务入口；补准入、R2 命令、保存/查询/取证和重放接线 |
| `claims.py/claims_v2.py` 的旧抽取/表读写 | 先列调用者和共享模型/LLM/校验依赖，后迁移与退休；不能直接删同名文件 |
| `evidence_pipeline.py`、`_semantic_validation.py`、`derivation.py` | 默认保留已验证用途与计算纪律；必要改动必须携带对应正负控和逐类差异报告 |
| `frontier_agent/`、通用 `workflows/`、审批/沙箱、`plugins/market/`、仓位/策略校验、Web | 本轮不改；若出现实质依赖，另列影响再评审，不顺手扩大重构 |
| 原文、人工复核完成件、冻结预算、raw/attempt、历史 scorer/结果 | 留档只读；新契约新版本，不回写历史分母和分数 |

新的 Module 通过 Interface 测行为；迁移完成后删除只锁定旧实现细节的重复测试，但保留历史失败
证据和仍有效业务反例。工程保护靠能力用例，不靠包括 Web 运行目录在内的全目录 hash 冒充业务
非回归；冻结试验资产仍用 hash 核验。

## 5. 开发集与验收重新冻结

### 5.1 样本不能直接沿用“剩余 24 条”等于新主线

| 集合 | 数量与用途 |
|---|---|
| 历史 v13 非纪要 | 25 条目标：公司 7、行业 14、个人复盘 4；只作历史对照 |
| 人工修订后的非纪要 P3-I/P4 | 24 条：公司 7、行业 13、个人复盘 4；上轮重评分范围 |
| 新三类主线待冻结 | 已复核公司 7 + 行业 13 = 20 条开发参照，另加宏观新审定的 M 条；不是 24，也不是简单把宏观旧 0/3 加进来 |
| 辅助兼容 | 个人复盘 4 条及既有取证/财务/安全用例；单列，不混入主线准确率 |

S0 先从已经使用过的开发材料中选择每主类目至少 2 份，分别覆盖正文和表格/混排；先核验实际
可用性，不声称已有 6 份完整金标。公司、行业可复用已知失败与财务样本；宏观优先核验已有华泰、
中银开发资料。开发范围必须覆盖无数字项、噪声负例、表格和缺失字段，不只挑容易段落。

在明确的页/章节范围内人工穷举目标和负例；更大文档只报告结构覆盖，不能宣称全文 item precision。
新候选计划冻结后，评测方建立一对一映射；匹配不唯一先裁决，不能匹配不上的输出直接忽略。
新发现的旧标注错误另记 amendment，先裁决后冻结；不得边看新模型结果边改验收答案。

全库盘点只读既有登记/审计元信息和文件清单；开发原文按允许清单读取。受保护留出不得被全文扫描、
分类提示词或新金标建设读取。未知新文件不能自动称为干净留出。模型冻结后，每主类目至少 1 份独立
未参与修正的材料作为小范围留出，另行预算；若样本身份或标注不足，向用户列明缺什么，不污染现有留出。

### 5.2 先冻结新 scorer，再跑模型

| 验收门 | 前瞻要求 |
|---|---|
| 准入 | 已确认纪要在默认路径放行数 0；已确认主线研报误排数 0；所有未决项有原因和复核状态 |
| 结构与证据 | 冻结范围内结构区台账 100%；被引用的 source/locator/span/cell 唯一回取 100%；不得丢关键限定 |
| 义务协议 | 所有已发送义务各有唯一终态，协议非法数 0；未发送单列 not_evaluated，全拒绝不得通过召回门 |
| 小型穷举开发范围 | item precision/recall 各 100%；防止在已知小样本上放弃评级等漏项 |
| 语义标签 | 每主类目、每有样本标签的 precision/recall 各 ≥90%；无数字预测单列；零分母为 not_evaluated |
| 关键忠实度 | 归属、原值单位期间、否定、条件风险、未知诚实均 100%；关键错误 0，一票否决 |
| 逐类非回归 | 新 scorer 对同一冻结来源和标注重评基线/候选，各类各轴不下降；关键正控不丢、反例不新增放行 |
| 关系（后段） | 当前用途需要的显式论据关系 precision 100%、recall ≥90%，负例与端点漏召回单列；不推断作者未表达的关系 |
| 小范围独立留出 | item recall ≥90%、关键 item 100%；其余上述适用语义/忠实度门不变，报告样本量，不宣称全库泛化 |

未测试项不能作零错误，也不计作模型已答错；同时最终完成门要求所有必需范围已评估，防止以
缩减已发送分母放行。额外 item 必须审核并计误报；非穷举全文不可声称 precision。

新增 scorer 必须独立读冻结来源，验证输出文本及限定忠实度，不能只检查 hash 非空。
逐类非回归必须真正比较基线，而不是所有字段逐字等于 gold 的隐含全对门。
原始范围 25/24 与新范围不得直接相减宣称提升；只比较可对齐子集，剩余部分单独报告。
尚无可对齐宏观语义基线时标 baseline_pending，先建立基线，不能写成零退化。

自动校验不能证明任意转述忠实。未有可靠机械判定的语义、条件保留和关系，由冻结的人工标注/
盲审承担最终裁决；不使用同一个抽取模型自评替代验收，不把预算花在新的 judge 循环上。

必须覆盖的零模型反例：重复短引文消歧、risk/question 错轴、问句误作承诺、纯评级被过滤、
条件/否定被截断、模型臆造作者、复合 value 错配、source 篡改、跨版本引用、空分母、全拒绝、
少发义务、逐类退化被总平均掩盖、禁 gold 后无法规划、无权限保存及崩溃预算重复消费。
历史 raw 协议不兼容新 wire 时，只作为明确版本的反例输入；不得改写 raw 后称为真实模型重放通过。

关系 not_evaluated 的产物称为完整 R2 材料理解通过。

## 7. 模型预算与止损：现在为 0，过门后另冻

本计划不消费任何历史余额。建议 S4 首轮按以下模板冻结，实际数额必须由计划容量计算决定：

- 范围：仅三类开发清单；同一轮固定模型、请求契约、提示词、解析器、scorer、来源和标注 hash。
- 并发 1，自动重试 0，每批最多 8 个义务，单调用超时 60 秒；先各类 1 个协议批次，再完成余批。
- 建议单轮最多 8 次真实请求，包含任何单独连通性 preflight；次数按各类 `ceil(N_class/8)`
  加 preflight 预留计算。不为凑 8 次丢弃目标；若容量超过上限，先报告并重新设计范围/批次，不调用。
- 每请求先预留并持久化预算；超时、失败、重发都消耗次数。冻结每批输入/输出 token 上限、累计
  token 上限、最长墙钟及费用硬上限（如可取得价格）；预检无法证明容纳时停止，不靠截断输出省预算。
- 同轮不改提示词、不修代码后继续剩余调用。任一协议非法、关键忠实度错误、hash/准入/留出违规
  立即停机并关闭预算；剩余义务记未评估，余量不转为新轮授权。
- 最多提出 1 次有明确根因的纠偏复验申请，同样单独批准，不默认执行。若重复卡在无 gold 规划、
  结构或验收定义，则停止模型试验，回到对应层；不进入 v14、v15 式无止境调参。

是否更换模型只在输入可观测、字段协议明确、scorer 正确后讨论；仍持续出现同类语义错误才提出
同一冻结小范围的模型对照，另行预算。关系、留出和终端 Agent 模型调用与 item 预算分开，不隐式扣用。
通用 `preflight.py` 含真实调用，S0—S3 不运行；离线门与预检完成状态必须区分。

## 8. 实验数据库与 CLI 如何落地

### 8.1 先隔离，再切换，不直接清空现库

用户已允许实验数据重塑，无须把旧 schema 当永久产品约束；但先核验实际 host/database/schema、
角色权限、表/索引/序列/视图/任务及调用者，确认与 Web/其他数据是否共库。日志不打印凭据。

1. 纯规划/清洗/语义离线测试在 pytest 收集前建立网络/PG 拒绝策略，仅挂载开发允许来源；
   不直接全量执行可能连库、读留出或调用模型的测试。I2/I3 必须另用显式隔离 PG 真实验证，
   不再规定模型试验前全部阶段都不能测 PG。
2. I0-B 完成首次隔离恢复，I0-C 据盘点/恢复证据复核布局；I2/I3 建立并验证候选版本、索引和
   活动发布；I4 按精确批准清单迁移/清理切换，另核最新一致性备份的实际恢复，不复用过期演练。
   原文与历史 run/人工复核/预算 raw 保留，纪要不进入活动集；旧库清除后历史取证依赖归档，
   不把旧句柄静默映射到新 build。S5 只补语义产物持久化门，不重复基础库建设。
3. 同一来源内容哈希但 parse_rev/政策版本不同，应可生成新结果；不能让旧 `ON CONFLICT` 或
   “内容未变则跳过”造成修复后的清洗永远不入库。语义结果按 source/parse/contract/model 版本记录。
4. 只重建通过开发门的清单，核验文档/块/产物计数、孤立引用、坐标、全文索引、幂等和逐样本差异。
   必须实际验证默认搜索/抽取排除纪要，不能仅测试模型 manifest 排除。
5. 完成真实 CLI 往返及失败恢复后再切活动版本；新架构内可切回仍准入的旧 build。首次清库后的
   系统级回退必须恢复已验证备份，不能声称旧在线版本还在。不能回滚原始来源或抹去失败记录；
   停用旧兼容写入后检查无活跃消费者，按清单退休，不整库递归删除。

### 8.2 CLI 命令是交付任务，不能把设计当现有能力

当前确有 `extract-claims/claim-runs/claims/claim-evidence/derive-claims` 等命令；
`CorpusService.understand_material` 已存在，但当前 CLI 没有完整材料理解子命令。

拟在现有 `python -m plugins.corpus.service` 增加以下命令职责（名称/参数在 S2 冻结，现在不要执行）：

| 拟新增命令 | 职责 |
|---|---|
| `material-plan` | 对显式来源/清单做准入、结构/义务规划和预算估算；不调用模型、不写 PG |
| `understand-material` | 读取已冻结计划，执行显式预算；保存 run/attempt/partial 状态，不隐式全库运行 |
| `material-show` | 读取确切 run 的条目、范围、失败与用途许可，不挑另一次成功版本代替 |
| `material-evidence` | 回取该 run 的原文与定位，可核验是否属于排除历史范围 |
| `material-verify` | 无金标地重放协议、来源和预算校验；语义业务评分另由开发 scorer 执行 |

已有 ingest/search 的默认活动范围也须使用同一准入策略；运行测试覆盖直接路径、保存后加载、
无数据库、数据库中断、失败但已保存、相同来源重跑、历史版本、错误 run_id、跨版本引用。
CLI 进程退出码和 stdout 要区分 completed/partial/failed，并给出可恢复的 run_id。
终端 Agent 后续接入复用正式 Interface 和实际工具注册，不再新建隐藏抽取入口；Web 继续暂缓。

## 10. 完成与不可行时的出口

- **清洗完成**：三类冻结开发范围有准入决定、可回取的正文/表格及全部缺口；结构/引用/非回归门过。
- **条目抽取完成**：三类同一 Interface 的有限调用、item 语义、忠实度及逐类非回归通过。
- **缩减范围 R2/CLI 可用**：上述通过，并完成声明用途所需关系、实际保存查询取证重放和独立留出。
  分别报告每一类和每一种用途；宏观只引用不等于宏观事件计算获准。
- **整个项目完成**仍需 D1/D2/A1/V1 各自证据，本方案不把材料清洗替代数据接入与跨层分析。

若 S3 前就不能证明可靠切分与无 gold 执行，不消耗模型预算；给出失败原文定位、发生层和替代提案。
若有限纠偏后仍无法达到某类忠实度，只交付可核验清洗证据包与人工辅助条目，保持自动语义该类
未放行。降低产品承诺或进一步缩类必须明确说明并由用户决定，不能静默改阈值宣布 R2 完成。

**当前下一步为 I0：三类来源/准入、逐类基础基线、消费方/对象盘点与版本契约；R2-S0 复用其结果。**
本次方案编制没有执行准入部署、数据库迁移、模型调用或新的业务测试。
