> **本文要解决的问题**：D2 的 claim 抽取自诞生起就**只按「公司研报」一种文档设计**（坐标轴是
> `tickers` + `metric` + `period`）。而当前语料里 **96% 的文档不是公司研报**，它们抽出来的
> claim 既没有主体坐标、也没有正确口径 —— 钱花了，D3/D4 聚不到数。
>
> **本文的第二件事**：上一轮讨论里出现了两组"三"（`完整性/一致性/质量评估` 与
> `company/industry/macro`），很容易被混为一谈。本文先分层消除歧义（§2），再分别设计。

> **现状已落地的运行时改造**（2026-09-11，见附录 A）：逐块原子提交、块级台账
> `claim_block_runs`、模型/prompt 指纹跳过、连续失败熔断、失败死信、显式超时、
> token 花费台账、备份补 `claims`。**这些是本文 §3.6 的前提，不是本文要评审的内容。**

## 1. 问题（结论全部有实测数据，命令见附录 B）

### 1.1 现状一句话

`plugins/corpus/claims.py` 的 `PROMPT_TEMPLATE` 举的例子是「营业收入 1741 亿元」「目标价 1888 元」
—— 典型公司研报口径。用它去抽宏观数据点评、行业周报、策略报告，**主体与口径都会跑偏**。

### 1.2 先记录：数据质量本身是好的（不要误伤）

用假 LLM 与真实语料各做过验证，**这几项不要动**：

| 事实 | 实测值 | 说明 |
|---|---|---|
| **数字幻觉率** | **0%**（121/121 条的所有数字都能在原文块逐字找到） | 模型在忠实读取，不是编 |
| **`kind` 与 `period` 自洽** | **100%**（`2024A/2025A`→`fact` 各 20 条；`2026E/2027E/2028E`→`forecast` 各 27 条，零例外） | 早期误判为"随机二分"，实为 2025A vs 2026E 的正常区分 |
| **跨块交叉一致** | `EPS`（seq=2）与 `每股收益`（seq=4）在 2026E/27E/28E **完全吻合**：65.77 / 70.77 / 77.66 | 两次互不可见的独立调用得出同值 |
| **字段完整度** | `period` / `metric` / `value_text` 缺失率 **0%** | —— |
| **单块失败不中断** | 纪律成立（与 ingest 一致） | —— |

**所以本文的重点不是"模型抽得差"，而是"抽出来的东西没有正确的坐标，无法聚合"。**

### 1.3 已实证的缺陷（按严重度）

| # | 缺陷 | 实测证据 | 后果 | 状态 |
|---|---|---|---|---|
| 1 | **宏观「实际值 / 预期值 / 前值」不分** | 非农点评原文：「新增非农就业16.2 万人，**预期5.6 万人**，前值…修正为2.1 万人」——三条并列，现有 schema 只有 `value_text` | D4 聚合"市场对 8 月非农的一致预期"会把**实际值**也算进去 → 共识 ≈11 万。正确结论是实际 16.2 ≫ 预期 5.6（强非农）→ **结论直接反了** | ⬜ |
| 2 | **宏观/行业报告没有主体坐标** | 121 条 claim 的 `tickers` **100% 为空**（已修 + 已回填 `600519.SH`） | 按 ticker 聚合全部落空 | ✅ 已修 |
| 3 | **指标命名无受控词表** | 同一份文档：`EPS`(3 条) vs `每股收益`(5 条) 并存；seq=2 的 8 个 metric 与 seq=4 的 21 个**零重叠** | 聚合"贵州茅台 2026E 一致预期"只命中一半 | ⬜ |
| 4 | **同指标同年份跨块重复** | `毛利率 2026E` 出现在 2 个块：`90.4%` / `90.42%`（同一数字不同精度，`ON CONFLICT` 挡不住文本不同） | D4 共识度**重复计数** | ⬜ |
| 5 | **文档领域未分类** | 78 份 = `company 3` / `industry 47` / `macro 28`；候选块花费占比 **4.3% / 49.5% / 46.2%** | 96% 的花费落在没有模板的领域上 | ⬜ |
| 6 | **表格块被压平后坐标靠猜** | `seq=4` 财务三表 1398 字符被压成数字流，抽出 **97 条**、单块 `ct=20164` token | 输出 token 约文字块的 **200 倍**（对照 `seq=6` 仅 `ct=99`）；行列关系缺失时 `period` 只能靠推理 | ⬜ |
| 7 | **叙事无处安放** | 华创《从分化到收敛》一半篇幅是无数字的逻辑推演，被 `has_signal` 正确跳过 | 宏观研报最值钱的"主题/逻辑链"完全没留下 | ⬜ |

> ⚠️ 缺陷 1 与 5 是**同一层问题**（内容层的坐标不对）；缺陷 3、4 是**落库后的数据卫生**；
> 缺陷 7 需要新载体，**不应塞进 `claims`**（会污染"claims = 可验证论断"这条底线）。

## 2. 分层：先消除"两组三"的歧义

| | 第一组"三" | 第二组"三" |
|---|---|---|
| 名称 | **company / industry / macro** | **完整性 / 一致性 / 质量评估** |
| 分层 | **内容层**：研报里的论断怎么抽 | **元层**：关于已抽数据的体检 |
| 产物 | `claims` 行 | 审计 JSON（**不产 claim**） |
| 由谁定义 | claim 模板的**领域插槽** | 审计层的**检查项** |
| 本文节次 | §3 | §4 |

### 2.1 为什么不合并

若把三类审计报告做成"claim 模板"，则 `claims` 表会同时装「研报里的论断」和「关于数据的论断」，
`claims = 研报里能回到原文的那句话` 这条定义立刻失效（硬闸① 的前提）。**两组三必须分居两层。**

## 3. 内容层设计

### 3.1 文档分类（`doc_kind`）—— 零成本规则

不调 LLM，用 `document_ticker()` 已有的三个分支（**已实测零误标**）：

| 判据 | `doc_kind` | 实测 |
|---|---|---|
| 标题含代码，或**正文严格形态代码恰为 1 个** | `company` | 3 份（贵州茅台 ×2、光力科技） |
| 正文严格形态代码 **> 1 个** | `industry` | 47 份（化工专题 **53 个**码、机器人周报 46、农业 17、传媒 8） |
| 无任何代码 | `macro`（标题含宏观/策略/周报/流动性/复盘…）否则 `industry` | 28 份 |

**副产品**：这套规则同时决定了要不要给文档级标的兜底 —— `industry`/`macro` **不给**
（错误的坐标比缺失的坐标更危险，下游无法察觉）。

### 3.2 claim 模板 = **1 个骨架 + 3 份领域插槽 + 1 个表格追加段**

不做三套完整模板（会维护漂移：改一处忘两处）。

**共享骨架（所有领域一致，不动）**：只输出 JSON、不许编造原文没有的数字、
`kind` 定义（fact/forecast）、字段清洗、分级 triage、逐块落库、指纹机制。

**领域插槽（差异全部收在这里）**：

| 插槽项 | `company` | `industry` | `macro` |
|---|---|---|---|
| **主体** | ticker `600519.SH` | 行业 / 板块 / 商品：`基础化工`、`焦煤期货` | 指标 / 资产：`US.NFP`、`XAUUSD` |
| **地域** | 不需要（ticker 隐含） | 可选（A股 / 美国） | **必填**：US / CN / EU / JP |
| **期间口径** | 报告期 `2026H1` | 周期（周 / 月） | **必填**：同比 / 环比 / 季调 / 折年 / 累计 |
| **数据三态** | 不需要（研报自己的预测即 forecast） | 不需要 | **必填**：实际 / 预期 / 前值 |
| **指标词表** | 营业收入·归母净利润·EPS·毛利率 | 开工率·库存·价格·产能利用率 | 非农·CPI·PPI·社融·M2·联邦基金利率 |
| **受控命名** | 中文指标名 | 中文指标名 | `主体.指标.口径` 编码（§5.3） |

**表格追加段（第 4 轴，可选）**：块被判定为"被压平的表格"时追加，
要求「每个 行名×列头 一条，必须带子表名/口径」。**不做成第 4 套模板**（否则是 3×2=6 种组合）。

**指纹对接**：把「骨架 + 插槽 + 表格段」一起纳入 `EXTRACTOR_VERSION` 的哈希 →
改任何一处都会**自动失效重抽并按块整体替换**（机制已就绪，见 §3.6）。**这是本文最大的杠杆。**

### 3.3 claim 坐标模型

| 坐标 | 现有字段 | §1.3 缺陷 | 承载方式（见 §5.1 / 待确认 Q1） |
|---|---|---|---|
| 主体 | `tickers` | 2、5 | `company`→tickers；`industry`/`macro`→编码进 `metric` 前缀 |
| 地域 | — | 1 | 编码进 `metric`：`US.NFP…` |
| 期间 | `period` | — | 复用（宏观用 `2026-08` 月度） |
| 口径 | — | 1 | 编码进 `metric`：`.YoY` / `.MoM` / `.SAAR` |
| **数据三态** | — | **1（最致命）** | 编码进 `metric`：`.actual` / `.consensus` / `.previous` |

### 3.4 命名规范与别名归并

1. **受控词表**：prompt 里给 30~50 个标准指标名，要求优先选用（先在 `macro` 试）。
2. **别名归并表**：落库前把别名映射到规范名（`EPS` / `每股收益` / `每股盈利` → `每股收益`）。
3. **数值归一**：`90.42%` → `90.4%`（按指标精度）、会计括号 `(325)` → `-325`。
4. **跨块去重**：对 `(doc_id, metric, period, kind)` 保留最新一条（解决缺陷 4 的重复计数）。

### 3.5 文档级元数据（**只保留可得且有用途的字段**）

| 字段 | 来源 | 实测可得性（78 份） | 用途 |
|---|---|---|---|
| `doc_id` / `title` / `content_hash` / `status` | ingest | 78/78 | 锚点、幂等、过滤 |
| `doc_kind` | **派生**（§3.1 规则） | 78/78 | **决定用哪套插槽** |
| `subject` | 派生（ticker / 行业标签 / NULL） | 3 直接 + 派生 | claim 坐标兜底 |
| `org` 机构 | 标题 / 首块正则 | **43/78** | 来源可信度、去重、共识加权 |
| `published` | doc_id 前缀 / 首块 | 59/78 可解析 · 54/78 已入库 | 时效排序、Recency 偏置 |
| `analysts` 作者 | 首块「分析师：X」 | **15/78（19%）** | ⚠️ 只能做**可选**字段 |
| ~~版本~~ | 语料中不存在（研报只有发布日期） | 0/78 | **删除** |
| ~~来源系统~~ | 语料来源就是文件系统 | — | **删除** |
| ~~校验状态~~ | 属于 claim / 块层面（`claim_block_runs.status` 已承担） | — | **移到元层审计（§4）** |

> **设计纪律**：`DocumentMetadata` 的每个字段都要标「来源」与「可得性」。把 19% 可得的
> 字段做成核心字段，等于设计一个**注定填不满**的结构。

### 3.6 落库 / 跳过 / 指纹（现状，已实现）

| 机制 | 口径 |
|---|---|
| 落库粒度 | **块**：`claims` 行 + `claim_block_runs` 标记在**同一事务**提交 |
| 跳过判据 | `status='ok'` **且** `model` + `extractor_version` 都匹配当前（换模型/改 prompt 自动失效） |
| 换指纹 | **整块替换**旧 claims（避免两代模型结果混在一张表） |
| 死信 | `failed` 且 `attempts >= max_attempts`（默认 3）→ 跳过并计入 `skipped_dead_letter` |
| 熔断 | 连续失败 `max_consecutive_failures`（默认 5）→ 干净退出，退出码 **130** |
| 花费台账 | `prompt_tokens` / `completion_tokens` 落 `claim_block_runs`，summary 汇总 |
| 超时 | `CORPUS_LLM_TIMEOUT`（默认 300s）· SDK `max_retries=0`（重试只由 `with_retry` 负责） |

## 4. 元层设计：三类语料审计报告

**只读现有表**（`documents` / `blocks` / `claims` / `claim_block_runs`），**不产 claim、不调 LLM**。
输出 JSON，退出码非 0 表示发现冲突（可做 CI 门禁）。

| 报告 | 检查项 | 现在就能算出的真实值 |
|---|---|---|
| **完整性** | 候选块 vs 已抽块缺口；0 候选文档；字段缺失率；备份覆盖率 | 628 候选 / 14 已做；17 份 0 候选；`period/metric/value` 缺失 **0%** |
| **一致性** | 跨块同指标同年份数值冲突；指标命名分裂；ticker 与文档标的冲突；`kind↔period` 自洽 | `毛利率 2026E` **2 块重复**（90.4% / 90.42%）；`EPS` vs `每股收益` 分裂；ticker 已回填 |
| **质量评估** | 数字溯源率；JSON 解析失败率；死信率；单块耗时/花费分布 | 溯源 **121/121 = 100%**；`failed=0`；死信 0；`ct` 单块最高 20164 token |

**与 `verify.py` 的关系（重要）**：`verify.py` 的三条硬闸裁决的是**策略卡**（`strategy.json`），
本审计裁决的是**语料库**。两者**并列，不互相替代**；审计报告不重复实现硬闸逻辑，
只在语料侧提供同口径的检查项，并在输出里显式标注「本报告不是硬闸裁决」。

## 5. 字段定义表

### 5.1 `claims` 维度字段

**方案 B（推荐先行，见 §10 Q1）：不新增列，维度编码进 `metric`**

| 形态 | 示例 | 说明 |
|---|---|---|
| company | `营业收入` · `归母净利润` | 沿用现有中文指标名 |
| industry | `基础化工.价格` · `焦煤期货.收盘价` | `主体.指标` |
| macro | `US.NFP.actual` · `US.NFP.consensus` · `US.UNRATE.actual` · `CN.FAI.YoY` | `地域.指标.口径/三态` |

**方案 A（后续可选）：新增列** `subject_type` / `subject_code` / `region` / `basis` / `stat_type`。
延迟理由：**输出 token 占 89%**（3 块 = `ct` 25299 vs `pt` 2970），维度越多输出越长。

### 5.2 `DocumentMetadata` —— 见 §3.5（只列可得字段）

### 5.3 metric 编码规范（方案 B）

```
<地域>.<指标>[.<口径|三态>]        macro      US.NFP.actual / CN.CPI.YoY
<主体>.<指标>                      industry   基础化工.开工率
<指标>                             company    营业收入
```

- 地域：`US` / `CN` / `EU` / `JP` / `GLOBAL`
- 口径：`YoY` `MoM` `SAAR`（季调折年） `Cum`（累计）
- 三态：`actual` / `consensus` / `previous`
- **未知时必须留空并在 `claim_text` 里保留原文表述**，不得猜。

## 6. claim 示例（真实原文 → 目标产出）

### 6.1 `macro`：光大证券 · 2026 年 8 月美国非农数据点评（`2026-09-06_793b3967`）

原文（seq=3）：

```
【1】新增非农就业16.2 万人，预期5.6 万人，前值由-2.3 万人修正为2.1 万人；
【2】8 月失业率4.1%，预期4.1%，前值4.1%；
【3】平均时薪同比升3.1%，预期升3.0%，前值升3.2%。
市场反应：道指/标普/纳指较上一交易日分别变动-0.5%、-0.4%、-0.3%。
10 年期美债收益率上行1bp 至4.78%。
```

目标产出（8~10 条）：

| metric | period | value | kind | 备注 |
|---|---|---|---|---|
| `US.NFP.actual` | 2026-08 | 16.2 万人 | fact | —— |
| `US.NFP.consensus` | 2026-08 | 5.6 万人 | forecast | **这条才是 D4 一致预期的输入** |
| `US.NFP.previous` | 2026-07 | 2.1 万人 | fact | 原文标注"修正" |
| `US.UNRATE.actual` | 2026-08 | 4.1% | fact | —— |
| `US.AHE.YoY.actual` | 2026-08 | 3.1% | fact | 口径=同比 |
| `US.SPX.return` | 2026-09-04 | -0.4% | fact | 资产类 |
| `US.UST10Y.yield` | 2026-09-04 | 4.78% | fact | 原文另给"+1bp" |

### 6.2 `company`：国信证券 · 贵州茅台 2026 中报点评（`2026-08-17_c195233b`）

```
现预测 2026E 营业收入 173,340 百万元，调整幅度 -2.9%
每股收益 2026E 65.77（2025A 65.74 / 2024A 68.64）
```

目标产出：`metric=营业收入` / `period=2026E` / `value=173,340 百万元` / `kind=forecast`，
`tickers=['600519.SH']`。**这一路已经工作正常，不需要改**（但需纳入别名归并，见 §3.4）。

### 6.3 `industry`：长江证券 · 化工专题（`2026-08-13_174b6462`）

正文含 **53 个**公司代码，但**不应**给文档级标的。目标产出：
`metric=基础化工.最高涨幅` / `period=2016-2018` / `value=291.4%`，
且 **`tickers` 保持为空**（行业级数据不对应单一标的）。

### 6.4 表格块：财务预测与估值三表（`seq=4`，1398 字符被压平）

现状产出 97 条、单块 `ct=20164` token。目标：
- 每条带**子表归属**（`资产负债表.其他收入` / `利润表.营业成本`）
- 每条带**口径**（`2026E` 等已能正确识别）
- 成本控制：单块输出上限（见 §10 Q5）

## 7. 生成时机与消费方式

| 产物 | 生成时机 | 消费方 |
|---|---|---|
| `doc_kind` / `subject` / `org` / `published` | ingest 后一次性派生并缓存 | 抽取选插槽、检索排序 |
| `claims` | `extract-claims`（按块、可断点续跑） | D3 挖掘、D4 共识度 |
| 三类审计报告 | 按需 / 全量跑完后 / CI | 人和 CI（JSON + 退出码） |
