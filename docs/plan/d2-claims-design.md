> claim 既没有主体坐标、也没有正确口径 —— 钱花了，D3/D4 聚不到数。
>
> **本文的第二件事**：上一轮讨论里出现了两组"三"（`完整性/一致性/质量评估` 与
> `company/industry/macro`），很容易被混为一谈。本文先分层消除歧义（§2），再分别设计。

> **现状已落地的运行时改造**（2026-09-11，见附录 A）：逐块原子提交、块级台账

> token 花费台账、备份补 `claims`。**这些是本文 §3.6 的前提，不是本文要评审的内容。**

> **v1.1 相对 v1.0 的实质变化（自评补齐）**：v1.0 是"从能抽出什么往上堆字段"，漏了三处
> **字段级/方法论级缺口**，本版补齐：
> ① 新增 **§3.7 下游聚合契约** —— 改为**从 D3/D4 怎么聚合往下反推字段**；
> ② 新增 **§5.1 的"事实列必须落列"** —— `as_of` / `value_num` / `unit` 不能像区域口径那样
> 编码进 `metric`（并且 `value_num`/`unit` 是**零 LLM 成本的派生列**）；

> ④ 新增 **§11 已知缺口**（9 项自评补记，含英文研报 18% 未覆盖）。
>
> **v1.0 最严重的遗漏是 `as_of`**：`docs/plan/ths-market-data.md` §24 已把
> 「每个被引用的数字都必须标注 `as_of` 时点与来源」定为**业务前提**，而 v1.0 全文未提 ——
> 宏观数据有「数据期 `period`」与「发布期 `as_of`」**两条时间轴**（见 §1.3 缺陷 8）。

## 1. 问题（结论全部有实测数据，命令见附录 B）

### 1.1 现状一句话

`plugins/corpus/claims.py` 的 `PROMPT_TEMPLATE` 举的例子是「营业收入 1741 亿元」「目标价 1888 元」
—— 典型公司研报口径。用它去抽宏观数据点评、行业周报、策略报告，**主体与口径都会跑偏**。

### 1.2 先记录：数据质量本身是好的（不要误伤）

用假 LLM 与真实语料各做过验证，**这几项不要动**：

| 事实 | 实测值 | 说明 |
|---|---|---|
| **数字幻觉率** | **0%**（121/121 条的所有数字都能在原文块逐字找到） | 模型在忠实读取，不是编 |
| **`kind` 与 `period` 自洽** | **100%**（`2024A/2025A`→`fact` 各 20 条；`2026E/2027E/2028E`→`forecast` 各 27 条，零例外） | 早期误判为"随机二分"，实为 2025A vs 2026E 的正常区分 |
| **跨块交叉一致** | `EPS`（seq=2）与 `每股收益`（seq=4）在 2026E/27E/28E **完全吻合**：65.77 / 70.77 / 77.66 | 两次互不可见的独立调用得出同值 |
| **字段完整度** | `period` / `metric` / `value_text` 缺失率 **0%** | —— |
| **单块失败不中断** | 纪律成立（与 ingest 一致） | —— |

**所以本文的重点不是"模型抽得差"，而是"抽出来的东西没有正确的坐标，无法聚合"。**

### 1.3 已实证的缺陷（按严重度）

| # | 缺陷 | 实测证据 | 后果 | 状态 |
|---|---|---|---|---|
| 1 | **宏观「实际值 / 预期值 / 前值」不分** | 非农点评原文：「新增非农就业16.2 万人，**预期5.6 万人**，前值…修正为2.1 万人」——三条并列，现有 schema 只有 `value_text` | D4 聚合"市场对 8 月非农的一致预期"会把**实际值**也算进去 → 共识 ≈11 万。正确结论是实际 16.2 ≫ 预期 5.6（强非农）→ **结论直接反了** | ✅ P1（三态拆分，§9.2 P1 验收） |
| 2 | **宏观/行业报告没有主体坐标** | 121 条 claim 的 `tickers` **100% 为空**（已修 + 已回填 `600519.SH`） | 按 ticker 聚合全部落空 | ✅ 已修 |
| 3 | **指标命名无受控词表** | 同一份文档：`EPS`(3 条) vs `每股收益`(5 条) 并存；seq=2 的 8 个 metric 与 seq=4 的 21 个**零重叠** | 聚合"贵州茅台 2026E 一致预期"只命中一半 | ✅ P3（别名归并 + 插槽词表，§9.2 P3 验收） |
| 4 | **同指标同年份跨块重复** | `毛利率 2026E` 出现在 2 个块：`90.4%` / `90.42%`（同一数字不同精度，`ON CONFLICT` 挡不住文本不同） | D4 共识度**重复计数** | ✅ P3（跨块去重，§9.2 P3 验收） |
| 5 | **文档领域未分类** | 78 份 = `company 3` / `industry 47` / `macro 28`；候选块花费占比 **4.3% / 49.5% / 46.2%** | 96% 的花费落在没有模板的领域上 | ✅ P1+P2（doc_kind + macro/industry 插槽） |
| 6 | **表格块被压平后坐标靠猜** | `seq=4` 财务三表 1398 字符被压成数字流，抽出 **97 条**、单块 `ct=20164` token | 输出 token 约文字块的 **200 倍**（对照 `seq=6` 仅 `ct=99`）；行列关系缺失时 `period` 只能靠推理 | ✅ P4（判据 + 追加段 + 输出上限，§9.2 P4 验收） |
| 7 | **叙事无处安放** | 华创《从分化到收敛》一半篇幅是无数字的逻辑推演，被 `has_signal` 正确跳过 | 宏观研报最值钱的"主题/逻辑链"完全没留下 | ⬜（需新载体，不在 P 排期内） |
| 8 | **没有 `as_of`（发布 / 预测时点）** | 宏观有**两条时间轴**：「**2026 年9 月4 日**公布 **2026 年8 月**非农数据」；`claims` 表**连字段都没有**（`grep as_of` 为 0） | D4 做"截至某日的一致预期"会把两三年前的预测算进今天的共识；且**违反 `ths-market-data.md` §24 已确立的 `as_of` 纪律** | ✅ P1（as_of 列 + published 兜底） |
| 9 | **`value_text` 未数值化** | 值是字符串：`"173,340 百万元"`（单位）/ `"4.1%"` / `"(325)"`（会计负号）/ `"65.77 元"` | D4 算不出一致预期的**均值 / 中位数 / 离散度**，只能比字符串；跨单位（`百万元` vs `亿元`）无法比较 | ✅ P1 解析 + P3 单位基准（`UNIT_SCALES`） |

> ⚠️ 缺陷 1 与 5 是**同一层问题**（内容层的坐标不对）；缺陷 3、4 是**落库后的数据卫生**；
> 缺陷 7 需要新载体，**不应塞进 `claims`**（会污染"claims = 可验证论断"这条底线）；
> **缺陷 8、9 是 v1.1 自评补出的字段级缺口**，其字段需求由 §3.7 的下游聚合契约反推得出。

## 2. 分层：先消除"两组三"的歧义

| | 第一组"三" | 第二组"三" |
|---|---|---|
| 名称 | **company / industry / macro** | **完整性 / 一致性 / 质量评估** |
| 分层 | **内容层**：研报里的论断怎么抽 | **元层**：关于已抽数据的体检 |
| 产物 | `claims` 行 | 审计 JSON（**不产 claim**） |
| 由谁定义 | claim 模板的**领域插槽** | 审计层的**检查项** |
| 本文节次 | §3 | §4 |

### 2.1 为什么不合并

若把三类审计报告做成"claim 模板"，则 `claims` 表会同时装「研报里的论断」和「关于数据的论断」，
`claims = 研报里能回到原文的那句话` 这条定义立刻失效（硬闸① 的前提）。**两组三必须分居两层。**

## 3. 内容层设计

### 3.1 文档分类（`doc_kind`）—— 零成本规则

不调 LLM，用 `document_ticker()` 已有的三个分支（**已实测零误标**）：

| 判据 | `doc_kind` | 实测 |
|---|---|---|
| 标题含代码，或**正文严格形态代码恰为 1 个** | `company` | 3 份（贵州茅台 ×2、光力科技） |
| 正文严格形态代码 **> 1 个** | `industry` | 47 份（化工专题 **53 个**码、机器人周报 46、农业 17、传媒 8） |
| 无任何代码 | `macro`（标题含宏观/策略/周报/流动性/复盘…）否则 `industry` | 28 份 |

**副产品**：这套规则同时决定了要不要给文档级标的兜底 —— `industry`/`macro` **不给**
（错误的坐标比缺失的坐标更危险，下游无法察觉）。

### 3.2 claim 模板 = **1 个骨架 + 3 份领域插槽 + 1 个表格追加段**

不做三套完整模板（会维护漂移：改一处忘两处）。

**共享骨架（所有领域一致，不动）**：只输出 JSON、不许编造原文没有的数字、
`kind` 定义（fact/forecast）、字段清洗、分级 triage、逐块落库、指纹机制。

**领域插槽（差异全部收在这里）**：

| 插槽项 | `company` | `industry` | `macro` |
|---|---|---|---|
| **主体** | ticker `600519.SH` | 行业 / 板块 / 商品：`基础化工`、`焦煤期货` | 指标 / 资产：`US.NFP`、`XAUUSD` |
| **地域** | 不需要（ticker 隐含） | 可选（A股 / 美国） | **必填**：US / CN / EU / JP |
| **期间口径** | 报告期 `2026H1` | 周期（周 / 月） | **必填**：同比 / 环比 / 季调 / 折年 / 累计 |
| **数据三态** | 不需要（研报自己的预测即 forecast） | 不需要 | **必填**：实际 / 预期 / 前值 |
| **指标词表** | 营业收入·归母净利润·EPS·毛利率 | 开工率·库存·价格·产能利用率 | 非农·CPI·PPI·社融·M2·联邦基金利率 |
| **受控命名** | 中文指标名 | 中文指标名 | `主体.指标.口径` 编码（§5.3） |

**表格追加段（第 4 轴，可选）**：块被判定为"被压平的表格"时追加，
要求「每个 行名×列头 一条，必须带子表名/口径」。**不做成第 4 套模板**（否则是 3×2=6 种组合）。

**指纹对接**：把「骨架 + 插槽 + 表格段」一起纳入 `EXTRACTOR_VERSION` 的哈希 →
改任何一处都会**自动失效重抽并按块整体替换**（机制已就绪，见 §3.6）。**这是本文最大的杠杆。**

### 3.3 claim 坐标模型

| 坐标 | 现有字段 | §1.3 缺陷 | 承载方式（见 §5.1 / 待确认 Q1） |
|---|---|---|---|
| 主体 | `tickers` | 2、5 | `company`→tickers；`industry`/`macro`→编码进 `metric` 前缀 |
| 地域 | — | 1 | 编码进 `metric`：`US.NFP…` |
| 期间 | `period` | — | 复用（宏观用 `2026-08` 月度） |
| 口径 | — | 1 | 编码进 `metric`：`.YoY` / `.MoM` / `.SAAR` |
| **数据三态** | — | **1（最致命）** | 编码进 `metric`：`.actual` / `.consensus` / `.previous` |

### 3.4 命名规范与别名归并

1. **受控词表**：prompt 里给 30~50 个标准指标名，要求优先选用（先在 `macro` 试）。
2. **别名归并表**：落库前把别名映射到规范名（`EPS` / `每股收益` / `每股盈利` → `每股收益`）。
3. **数值归一**：`90.42%` → `90.4%`（按指标精度）、会计括号 `(325)` → `-325`。
4. **跨块去重**：对 `(doc_id, metric, period, kind)` 保留最新一条（解决缺陷 4 的重复计数）。

### 3.5 文档级元数据（**只保留可得且有用途的字段**）

| 字段 | 来源 | 实测可得性（78 份） | 用途 |
|---|---|---|---|
| `doc_id` / `title` / `content_hash` / `status` | ingest | 78/78 | 锚点、幂等、过滤 |
| `doc_kind` | **派生**（§3.1 规则） | 78/78 | **决定用哪套插槽** |
| `subject` | 派生（ticker / 行业标签 / NULL） | 3/78（仅 company；industry/macro 主体在 metric 前缀里） | claim 坐标兜底 |
| `org` 机构 | 标题正则（P6 实测校准：**只认标题**，首块机构词检索全为误报） | **38/78（19 家）** | 来源可信度、去重、共识加权 |
| `published` | doc_id 前缀 / 首块 | 59/78（P6 起全部入库：ingest 54 + undated 首块回填 5） | 时效排序、Recency 偏置 |
| `analysts` 作者 | 首块「分析师：X」（P6 实测含执业编号取姓名段） | **20/78（26%）** | ⚠️ 只能做**可选**字段 |
| ~~版本~~ | 语料中不存在（研报只有发布日期） | 0/78 | **删除** |
| ~~来源系统~~ | 语料来源就是文件系统 | — | **删除** |
| ~~校验状态~~ | 属于 claim / 块层面（`claim_block_runs.status` 已承担） | — | **移到元层审计（§4）** |

> **设计纪律**：`DocumentMetadata` 的每个字段都要标「来源」与「可得性」。把 19% 可得的
> 字段做成核心字段，等于设计一个**注定填不满**的结构。

### 3.6 落库 / 跳过 / 指纹（现状，已实现）

| 机制 | 口径 |
|---|---|
| 落库粒度 | **块**：`claims` 行 + `claim_block_runs` 标记在**同一事务**提交 |
| 跳过判据 | `status='ok'` **且** `model` + `extractor_version` 都匹配当前（换模型/改 prompt 自动失效） |
| 换指纹 | **整块替换**旧 claims（避免两代模型结果混在一张表） |
| 死信 | `failed` 且 `attempts >= max_attempts`（默认 3）→ 跳过并计入 `skipped_dead_letter` |
| 熔断 | 连续失败 `max_consecutive_failures`（默认 5）→ 干净退出，退出码 **130** |
| 花费台账 | `prompt_tokens` / `completion_tokens` 落 `claim_block_runs`，summary 汇总 |
| 超时 | `CORPUS_LLM_TIMEOUT`（默认 300s）· SDK `max_retries=0`（重试只由 `with_retry` 负责） |

### 3.7 下游聚合契约（**由消费方反推字段**）

> **方法论修正**：claim 的字段**不该从"能抽出什么"往上堆，而要从"下游怎么聚合"往下推**。
> 本节是 §5.1 字段定义与 §1.3 缺陷 1 / 8 / 9 的依据 —— v1.0 缺了这一步，才漏掉 `as_of`。

#### D4（共识度）聚合键

```
(subject, metric, period, basis, stat_type, as_of ≤ T)
```

| 规则 | 口径 | 依据 |
|---|---|---|
| **主体** | `company` 用 `tickers`（非空）；`macro` / `industry` 用 `metric` 前缀 | 缺陷 2 |
| **口径不得混键** | `YoY` 与 `MoM`、`actual` 与 `consensus` **不得合并** | 缺陷 1 —— 合并会让结论反向 |
| **时效切片** | 支持"**截至 T 日**的一致预期"（`as_of <= T`） | 缺陷 8 —— 否则两年前的预测会算进今天的共识 |
| **一机构一票** | 同一 `org` 对同一 `(subject, metric, period, basis, stat_type)` **只计一票**，取该机构**最新**一篇 | 一家券商发两篇报告不是两家（`org` 从 `documents` join，**不需在 claims 上冗余**） |
| **数值可比** | 需要 `value_num` + 归一后的 `unit` 才能算均值 / 中位数 / 离散度 | 缺陷 9 |

#### D3（挖掘）聚合键

`(subject, metric)` 的**时间序列**（按 `period` 排序）+ 跨文档同类论断聚类。

#### 由此反推出的字段需求（并入 §5.1）

| 字段 | 因为哪条契约 | 不落列的后果 |
|---|---|---|
| `as_of` | 时效切片 | 范围查询（`<= T`）无法用命名表达 |
| `value_num` / `unit` | 数值可比 | 一致预期退化为"有没有人说同一个数" |
| `metric` 含 `basis` / `stat_type` | 口径同键 | 会把 `actual` 和 `consensus` 混成一池 |
| `org`（join `documents`） | 一机构一票 | 同一机构重复计票 |

> **→ 结论**：`as_of` / `value_num` / `unit` **必须落列**，不能像地域 / 口径那样编码进 `metric`。
> 边界由 §5.1 给出。

## 4. 元层设计：三类语料审计报告

**只读现有表**（`documents` / `blocks` / `claims` / `claim_block_runs`），**不产 claim、不调 LLM**。
输出 JSON，退出码非 0 表示发现冲突（可做 CI 门禁）。

| 报告 | 检查项 | 现在就能算出的真实值 |
|---|---|---|
| **完整性** | 候选块 vs 已抽块缺口；0 候选文档；字段缺失率；备份覆盖率 | 628 候选 / 14 已做；17 份 0 候选；`period/metric/value` 缺失 **0%** |
| **一致性** | 跨块同指标同年份数值冲突；指标命名分裂；ticker 与文档标的冲突；`kind↔period` 自洽 | `毛利率 2026E` **2 块重复**（90.4% / 90.42%）；`EPS` vs `每股收益` 分裂；ticker 已回填 |

## 5. 字段定义表

### 5.1 `claims` 字段：**命名维度编码 + 事实列落列**

**方案 B 的适用边界（v1.1 明确，回应 §10 Q1）**：

| 类别 | 例子 | 承载方式 | 理由 |
|---|---|---|---|
| **可枚举的命名维度** | 地域 `US`、口径 `YoY`、三态 `consensus`、子表 `利润表` | ✅ **编码进 `metric`**（§5.3） | 它们是**聚合键的一部分**，枚举值有限、**不需要范围查询** |
| **事实列 / 数值投影** | `as_of`、`value_num`、`unit` | ❌ **必须落列** | `as_of` 要做**范围**切片（`<= T`），编码进名字无法索引；`value_num`/`unit` 要做**算术**，名字里放不下 |

**新增三列（P1 落地）**：

| 列 | 类型 | 从哪来 | 额外 LLM 成本 |
|---|---|---|---|
| `as_of` | `date` | 原文明确写到日期时由模型给出（`"9 月4 日公布"`）；**缺失时用 `documents.published` 兜底** | **≈ 0**（兜底路径不花 token） |
| `value_num` | `numeric` | **Python 从 `value_text` 解析**：`"173,340 百万元"` → `173340`；`"(325)"` → `-325` | **0**（纯后处理） |
| `unit` | `text` | 同上（`百万元` / `亿元` / `%` / `万人`），并**归一**（`万元`/`百万元`/`亿元` → 基准单位 + 倍数） | **0** |

> **关键**：`value_num` / `unit` 是**派生列**，落库前由 Python 解析产生，**不增加模型输出** ——
> 所以 Q1 的"加列会让输出变长"只对 `as_of` 成立，而 `as_of` 又有 `published` 兜底。
> **解析失败时 `value_num` 留 `NULL` 并保留 `value_text` 原文，不得猜。**
>
> ⚠️ **新增列必须同步 `_BACKUP_COLUMNS["claims"]`** —— 该列表是**逐列枚举**的，
> 漏列不会被报错，只会静默丢字段（上次整张 `claims` 表漏出备份就是这样踩的，见附录 A）。

**命名形态（方案 B）**：

| 形态 | 示例 | 说明 |
|---|---|---|
| company | `营业收入` · `归母净利润` | 沿用现有中文指标名 |
| industry | `基础化工.价格` · `焦煤期货.收盘价` | `主体.指标` |
| macro | `US.NFP.actual` · `US.NFP.consensus` · `US.UNRATE.actual` · `CN.FAI.YoY` | `地域.指标.口径/三态` |

**方案 A（后续可选，不是必需）**：把命名维度再拆成独立列
`subject_type` / `subject_code` / `region` / `basis` / `stat_type`。
延迟理由：**输出 token 占 89%**（3 块 = `ct` 25299 vs `pt` 2970），拆列会让每条 claim 更长；
且 §3.7 的聚合键用 `metric` 字符串即可表达。等出现**跨领域联合查询**（如"同时筛地域与三态"）
再拆列。

### 5.2 `DocumentMetadata` —— 见 §3.5（只列可得字段）

### 5.3 metric 编码规范（方案 B）

```
<地域>.<指标>[.<口径|三态>]        macro      US.NFP.actual / CN.CPI.YoY
<主体>.<指标>                      industry   基础化工.开工率
<指标>                             company    营业收入
```

- 地域：`US` / `CN` / `EU` / `JP` / `GLOBAL`
- 口径：`YoY` `MoM` `SAAR`（季调折年） `Cum`（累计）
- 三态：`actual` / `consensus` / `previous`
- **未知时必须留空并在 `claim_text` 里保留原文表述**，不得猜。
