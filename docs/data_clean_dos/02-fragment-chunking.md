## 1. 事实、假设与原文保护边界

历史研报样本中，首页存在 6、23、38 字的块；正文出现 `事项：\n\n公司公布…` 一类文本。这些现象值得检查，但不能直接认定是解析错误：短标题、日期、评级、目标价和项目符号都可能有独立意义。

| 实现位置 | 已确认行为 | 尚需验证的假设 |
|---|---|---|
| [pdf_reader.py](../../plugins/corpus/preparation/readers/pdf_reader.py) 的 `_page_lines` | 保留原生块／行阅读顺序，展平后没有在 `_Line` 中保留 block 身份 | 补充 block 身份是否能改善特定段落的分组 |
| 同文件的 `_merge_lines` | 使用纵向间隙及横向交叠等几何条件，并明确避免全局坐标重排 | 哪些跨行边界确实错误，哪些应保持独立 |
| 同文件的 `_emit_paragraphs` | 原始文本按已有行内容组装 | 符号应随列表项保存还是独立保存，而非是否直接删除 |
| [clean.py](../../plugins/corpus/preparation/clean.py) | `clean_view` 是空白投影；噪声判定包含重复页眉页脚及其他规则 | 是否存在可由新增正向证据安全识别的版面噪声 |
| [chunk.py](../../plugins/corpus/preparation/chunk.py) | 对表格行、标题、列表和问答有专门处理；目标长度不是所有块的硬性下限 | 哪些短块实际降低检索质量，哪些只增加取回调用 |

**原文保护边界：** `raw_text` 及其源映射必须可复核。`ReaderIssue` 只能说明发生过何事，不能让删除的非空白字符重新成为可引用原文。不得以 Unicode 类别、私有区字符范围、短文本长度或“看起来是符号”为理由直接从权威文本剥离字符。

## B0 · 建立消费侧改善后的基线

先完成 [A0–A4](01-table-recovery.md) 中与展示、分页和观测相关的能力，再区分以下情况：

1. **源文本正确，读取麻烦。** 多个短块通过批量取回、保留类型的组合展示已足够使用，不必修改准备产物。
2. **原文或结构错误。** 跨栏误接、正文缺失、表格行列关系丢失、标题归属错误等，可进入 reader／clean／chunk 定位试验。
3. **原文和结构正确，但检索或抽取效果较差。** 用固定查询和事实金标验证是否确由块边界引起，再决定是否调整切块。

建立开发集和独立验证集，覆盖单栏／多栏、短报告、首页价格框、跨页续表、合并单元格、风险提示、列表、问答及特殊符号。历史研报作为开发样本；规则冻结后再运行独立验证集，不用它反复调参，也不读取仓库受保护评测答案。

每份样本保留源文件内容身份、reader 初始提取的文本与版面信息、当前准备产物、关键事实及预期引用范围。记录：

- 非空白字符覆盖、阅读序及关键事实／标题／表格／脚注的保留情况。
- 结构误合并、缺失、重复，以及可追溯映射失败。
- 固定查询下的证据命中、取证调用、送达正文量和模型任务表现。
- 短块比例、符号数量等辅助统计，但不给它们设置“归零”目标。

若主要问题已由 A 组解决，应记录结论并停止对应 B 项。B0 的产出是缺陷清单与归因证据，不是预先确定必须重建所有语料。

## B1 · reader：保留文本，谨慎调整分组

### B1.1 原生 block 是信号，不是语义保证

可以为 `_Line` 保留 block 序号作为候选信号，但不得采用“同一 block 无条件并段”。PDF 原生 block 可能包含多个段落，也可能混有标题、价格框、脚注或多列内容。

合并应综合原生顺序、几何邻接、列归属、字号／样式变化、标题／列表边界和表格归属。只合并具有正向连续性证据的相邻行；条件不充分时保留原分组，并记录可观测原因。

必须保持：

- 原生阅读顺序，不引入全局 `(y, x)` 排序。
- 不跨栏、跨不相邻区域或跨表格／正文边界合并。
- 标题、列表标记、脚注及数字事实的源身份仍可定位。
- 新分组可以改变段边界，不能在字符层面悄悄删减或改写原文。

### B1 执行结果（2026-09-29）

company-004 的第 1 页中，正文行字号为 10.45，页面字号中位数为 6.5；原规则仅以
“高于中位数 15% 且文本不长”判定标题，因而把连续正文逐行发为 `heading`，没有进入段落合并。

reader 现保留原生文本块的行数与字号范围：同一多行块字号基本一致时，按正文处理；相邻的多行
原生块不因几何接近而误合并，单行相邻文本继续沿用既有几何合并。`READER_PDF_REV` 已升为
`reader-pdf-7`。真实样本中“公司发布新一期股权激励……”至“营业收入触发\n值”的六行原文现为
一个 215 字符的 `paragraph`，原始换行保留。

本轮代码修复后经 PDF 回归验证与 B4.1 B1-only 分项对照（2026-09-29，11 改善／0 回归）通过；
仍未构建可发布候选 build、重建语料或切换发布指针；B4 的隔离 build 验证与发布／回滚演练仍是后续门槛。

### B1.2 特殊符号与列表处理

保留 `` 等原始字符。若能可靠识别列表关系，可以在不丢失字符和映射的前提下，将标记与后文关联为列表项，或作为独立原子单元保存并附关系。

对无法解释的符号记录诊断信息，允许展示层弱化，但不从权威原文中移除。负号、百分号、星号脚注、区间符号以及非数字风险提示必须列入保护样本。某一字体中的私有区字形究竟表示什么，需要来源证据，不能由字符类别推断。

### B1.3 验证不能只在改写后的原文内部闭环

只检查“新 chunk 可以映射到新 raw_text”无法发现 reader 已经删除的内容。因此应同时对照：

1. 本轮修改之前保存的初始提取文本、源文件及必要页面核查。
2. 新 reader 的 unit、字符覆盖和阅读序。
3. clean／chunk 到新 unit 的映射结果。

新增删除、重复或顺序变化必须能定位到源片段并解释。初始提取本身也可能漏字，因此不能仅靠字符覆盖宣称对 PDF 完整；关键事实和复杂版面仍需源页面对照。B1 单独通过后，才能进入组合试验。

## B2 · clean：保持空白投影，审慎扩充区域判噪

`clean_view` 继续只做空白投影，保持 `verify_clean_region` 的非空白覆盖要求。噪声判定作用于有来源映射的区域，原始 unit 与判定依据保留；不得借“清洗”在保留区域内部删除一行符号。

新增版面噪声规则应有组合证据，例如稳定的来源模板、确认的页眉页脚位置、跨页一致性和明确的版面身份。单独满足短文本、两页重复、无句末标点或无数字，不足以判定为噪声。

本方案不默认把重复阈值从 3 改为 2。若开发样本表明确有价值，应作为独立候选规则冻结、评估，并报告误删和漏判；证据不足时保持原文。

### 必须保护的内容

- 公司／证券身份、报告日期、评级、目标价及相关适用条件。
- 表头、期间、货币／单位、行标签、合并单元格关系和脚注。
- 风险提示、假设、限制条件；其中很多没有数字，不能依赖数字保护规则覆盖。
- 首页信息框中与研究结论有关的内容。

候选规则应记录位置、模板／重复等依据、保护条件检查及最终 verdict。日志用于解释判定，不能替代原文保留。对已有噪声规则也保留回归样本，避免新增规则改变原判定优先级后出现连带误删。

如果未来确需“隐藏一个 unit 内的局部符号”，须另行设计展示视图及逐段映射协议，明确与 `clean_view` 的区别。本轮不把它混入空白投影契约。

## B3 · chunk：先组合展示，再考虑改变边界

### B3.1 首页短块不直接合并成 body

优先通过 A2 同页返回多个 item，并在展示上组合首页信息。每项保留 kind、locator 和引用身份，既减少往返，又无需重建块边界。

只有在 B0 已证明真实切块影响检索或结论质量时，才试验受约束的相邻合并：同一可信章节／区域、原文连续、语义用途相容、没有结构边界冲突，并满足长度上限。合并后仍须保留各原始 unit 及映射。

不用“标题长度 ≥ 20 字”识别真正章节，不设“所有 body 至少 200 字”。短标题、短风险提示和日期可以独立有效；未能识别章节时应保守保留，不能一律当成首页正文。

### B3.2 结构不变式

- 表格保持表格身份与行／单元格原子性，不为凑长度吸收进 body；跨页续表关系另行保留。
- 标题仍能承担章节定位，列表和问答仍保留各自结构；不因处于首页而统一取消断组。
- `unit_ordinals`、`context_refs`、表头引用和段内源范围仍可校验。
- 不跨风险提示、脚注、表体或不确定章节边界合并。
- 超过限制时使用与类型相容的分片方式，不能对表格套用任意句界切分。

`verify_chunk_result` 通过是必要条件，但覆盖全部 ordinal 仍可能同时发生错误归类或重复拼接，须配合结构和事实金标验证。

### B3.3 回归比较的单位

若 B3 只调整首页，其他区域应保持语义内容、单元分组和结构关系不变。新 build 身份或前部块数变化可能使 locator、编号和哈希改变，不能要求所有非首页序列化产物逐字节一致。

比较应按源内容身份、原始单元和字符范围对齐，分别报告“内容／分组变化”和“仅标识变化”。若同时启用了 B1／B2，则应按组合方案的实际影响范围评估，不能继续承诺只影响首页。

## B4 · 分项验证、版本管理和发布回滚

### B4.1 分项对照之后再组合

| 试验 | 相对同一基线的变化 | 回答的问题 |
|---|---|---|
| B1-only | 仅 reader 候选逻辑 | 分组是否改善，是否出现字符或阅读序损伤 |
| B2-only | 仅 clean 候选逻辑 | 噪声判定是否更准确，关键内容是否误删 |
| B3-only | 仅 chunk 候选逻辑 | 检索与取证是否改善，结构是否保持 |
| 通过项的组合 | 只组合单项通过的候选 | 交互是否引入新错误，综合成本是否值得 |

不要求三个候选全部实施。准备层指标和端到端任务指标一起报告；一个候选若只有块数减少、没有质量或成本收益，可以不采纳。

### B4.1 对照执行（2026-09-29）

B1-only 分项对照已执行，脚本与产物见
[.scratch/b1-comparison-20260929/](../../.scratch/b1-comparison-20260929/)（`b1_comparison.py`／
`report.md`／`b1_comparison.json`）。固定样本同 B0（30 题／99 target／6 来源），仅 reader
候选逻辑变化（`_is_heading` 新增 `uniform_multiline_block`，clean-3／chunk-3 不变）；零模型
（import 陷阱）、PG 只读，新产物由归档副本经 reader-pdf-7 → clean → chunk 纯内存重建，
不写库、不建索引、不发布，符合 B4.3「只读源和新的产物位置」。

**冻结规则**（仍以代码常量表达，本次对照验证后冻结）：

> `uniform_multiline_block`：PDF 原生多行文本块（`block_line_count > 1`）内字号一致
> （`block_max_size − block_min_size ≤ max(0.5, block_max_size × 0.05)`）时，该行**不判为
> 标题**，按正文进入段落装配，无论行字号是否高于页中位数；块内存在明显字号层次时仍走
> 原字号规则。原因：研报页混排小字号表格／页脚拉低页中位数，连续正文每行都「高于中位数」
> 而被误拆为 heading。

**结果（99 target）**：

| 转移 | 数量 |
|---|---|
| `chunking_impact → ok` | **11**（company-004 e1/e2/a-2/a-3、company-005 e1–e5、company-008 a-3/a-5，均来自 dddc7cd0，即 B0 F1 标题误判缺陷本体） |
| `chunking_impact → chunking_impact` | 9（残留，跨 `body`/`table` 边界，属 B3 证据） |
| `ok → ok` | **75** |
| `ok → *非 ok*` | **0（无回归）** |
| `structure_error → structure_error` | 4（F2/F3 未变化，不在 B1 作用面） |

**B1.3 原文保护核验（6/6 来源通过）**：`chars_lost=0`、`chars_gained=0`；旧单元逐字仍是
新文档连续子串（`old_unit_not_contiguous_in_new=[]`）；旧单元序列在新文档中为**有序子序列**
（无跨单元重排）。`old_chunks_broken=98` 属块重分组（单元合并改变块边界），由单元级有序
子序列 + 零字符丢失排除真实阅读序损伤。

**结论**：B1 **单独通过**——分组改善（11/20 标题误判目标恢复单块可取），零字符丢失、零
阅读序损伤，75 个 `ok` 零回归，满足 §B1.3「对照修改前初始提取 + 字符覆盖 + 阅读序」门槛。
残留 9 条（macro-001 e3、macro-002 e4、macro-003 a-2/a-4/e2、company-007 e1/e2、
company-008 a-1/a-2）与 structure_error 4 条分别归 B3 与表格结构通道，不否决 B1。
下一步：由 B4 组合对照（单项通过的候选组合）决定 B3 是否有必要实施；B4.3 的隔离 build
验证与发布／回滚演练仍属发布级事项——本对照为对照验证，未构建可发布 build、未重建语料、
未切换指针。

## 2. 验收与停止条件

| 维度 | 验收要求 |
|---|---|
| 原文保护 | 从修改前的提取结果及必要源页面出发，关键非空白内容无不可解释的丢失、重复或改写 |
| 阅读序 | 多栏、标题／正文、表格／脚注等样本无新增错误拼接 |
| clean 契约 | `verify_clean_region` 等既有约束成立；新增噪声规则无关键事实误删 |
| chunk 契约 | 覆盖与源映射成立，表格／列表／问答／标题结构保持；短而有效的块允许存在 |
| 事实保留 | 日期、评级、价格、期间、单位、风险和脚注金标均可定位、逐字复核 |
| 检索与消费 | 固定任务的关键证据命中及结论正确性不退步，成本收益在同等证据范围下计算 |
| 实验可信度 | 候选逐项比较、规则冻结后独立验证，组合试验能够解释收益及新风险 |
| 发布能力 | 重建范围可说明，新旧 build 不混读，兼容回滚完成演练 |

重要缺陷必须逐例检查；不能用平均准确率提高来掩盖关键事实误删。若缺乏可靠结构依据、独立验证退步、收益主要来自少取证据，或无法保证回滚，则不发布相应准备层变更。

本方案可以以“保留当前准备层，仅上线消费侧改进”作为有效结论。是否值得重建，由 B0 的缺陷证据和 B4 的对照结果决定。
