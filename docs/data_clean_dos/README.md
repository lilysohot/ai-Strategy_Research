## 2. 已确认事实，以及尚未证明的原因

| 已确认事实 | 可以支持的判断 | 不能据此推出的判断 |
|---|---|---|
| 返回的上下文含 36 个 locator，实际取回 10 个 | 存在 26 个未取回的上下文块 | 每个结论都必须读取全部 36 块 |
| 未取回项含 `body:0008–0016`、`heading:0000/0001`、`table:0000–0014` | 15 个表格块没有被逐块取回 | 存在 15 张独立表格，或完全没有取得表格中的信息 |
| `heading:0002` 是“附录：财务预测表”，`heading:0003` 是“资产负债表” | 这两块只有标题，不能证明已读表体 | 标题后的第一张表一定就是对应表体 |
| `body:0005` 的完整返回约 11,300 字符，正文 1,249 字符，正文键约在偏移 9,815 处；发生两次补取 | 元数据挤占返回预算，正文暴露过晚，存在重复取证成本 | 单纯把工具配置成不限长就能保证模型读到全文 |
| `body:0005` 含已摊平的预测表数值、EPS、目标价及风险文字 | 部分财务数据已在正文中取得 | 这些文本足以复原所有表头、合并单元格和脚注 |
| 首页出现 6、23、38 字的短块，正文含 `` 符号行 | 存在可读性和调用效率的优化空间 | 短块都是噪声，私有区字符都没有语义 |

数值纠正：旧稿中的“15,489 字符”对应近期 130 天行情工具结果，不是 `body:0005` 的语料返回。

实现核对还发现：

- `service._selected_context_hits` 汇总同一来源的多个 `SelectedBand`，结果可能不连续，不能用最小起点到最大终点代表实际范围。
- `search_pg._enrich_hits` 的页码和单元格信息来自首个引用单元，不能据其坐标最大值推断整张表的行列数，也不能假定它已覆盖所有邻接块。
- `corpus_fetch` 已有 `kind` 和结构元数据；问题包含信息组织及覆盖不足，不能概括为“完全丢失结构”。
- `corpus_fetch` 的工具级不限长配置之外，ReAct 后处理和单轮聚合仍有独立预算。必须检查最终模型输入。
- 现有 clean 除重复页眉页脚规则外，还包含目录、免责声明等判定；“仅依赖三页重复”不是完整描述。

## 3. 设计原则

1. **原文和映射优先。** 保留可复核的源文本及非空白字符。记录删除日志不能替代保留原文。展示层新增的分隔符不能冒充原文。
2. **结构有依据才声明。** 区分表格块和独立表格；元数据不完整时返回 `partial` 或 `unknown`，不补造行列、归属或标题关系。
3. **范围覆盖与结论充分性分开。** 选定证据范围没有取全，就仍是不完整；明确跳过不能变成完整。但一个有充分原文支持的局部结论，不必因无关附录未读而一律失败。
4. **以送达模型为消费下限。** 分开记录检索提供、实际请求、服务取回和模型收到的内容。送达也不代表模型已理解，或压缩后仍保留全部内容。
5. **先验证质量，再比较成本。** 在相同任务、证据范围和正确性要求下比较调用数、token、延迟。不以少取证据换取“效率提升”。
6. **准备主链保持零模型基线。** 此轮不把 LLM 接入 reader／clean／chunk。Claims／R2 的角色隔离和模型试验独立推进，使用可追溯的原文输入。

## 4. 工作项与优先级

| 编号 | 产出 | 优先级 | 是否需要新语料 build | 主要风险 |
|---|---|---|---|---|
| A0 | 正文优先的紧凑视图与端到端预算约定 | P0 | 通常不需要 | 后处理仍截断正文、分页标记或 JSON |
| A1 | 有来源依据的上下文结构清单 | P0 | 可由既有元数据构造时不需要 | 将局部单元格冒充整表结构 |
| A2 | 单一批量分页接口与固定快照游标 | P0 | 通常不需要 | 游标失效、超大单元、部分失败和聚合截断 |
| A3 | 标题身份及有依据的内容关联 | P1 | 可由既有关系构造时不需要 | 把邻近关系当成确定归属 |
| A4 | 消费账本、结论证据清单及报告校验 | P0，先观测后约束 | 不需要 | 校验没有接入实际 Markdown／最终回复路径 |
| B0 | 消费侧改善后的准备质量基线 | P1，B 组前置 | 不需要 | 把调用界面问题误判为切块缺陷 |
| B1 | 保留原文的 reader 分组改进试验 | 按 B0 证据决定 | reader 语义变化时需要 | 跨栏、跨段、跨表误合并 |
| B2 | 可解释、保守的区域噪声判定试验 | 按 B0 证据决定 | clean 语义变化时需要 | 删除日期、评级、风险、单位或脚注 |
| B3 | 保留类型与关系的切块改进试验 | 按 B0 证据决定 | chunk 语义变化时需要 | 为消除短块而破坏表格／标题／列表 |
| B4 | 分项对照、组合验收及发布回滚演练 | B 组发布前必需 | 按依赖闭包重建 | 无法归因或新旧版本混读 |

A1／A3 缺少底层关系时，应先返回未知并保留原文可取。若后来需要新增准备产物，应另行说明版本和重建范围，不能继续声称“只加接口字段”。

## 5. 实施顺序和决策门槛

```text
A0 正文展示与预算基线
  → A1 结构清单 + A2 批量分页
  → A3 标题关系
  → A4 消费观测 → 报告路径接入 → 启用相应约束
  → 固定任务回放和成本对照
  → B0 判断是否仍存在准备侧缺陷
  → 有必要的 B1／B2／B3 分别试验
  → B4 组合验收、隔离环境发布与回滚演练
```

A4 的观测设计可以提前开展；其阻断逻辑须等范围定义、分页和实际送达记录可用后再启用。不能先强制“必须取全”，却不给模型可靠的分页取证能力。

消费侧若已解决主要问题，可以停止在 A 组；不把 B1–B3 视为必做清单。B 组先各自与同一基线比较，再评估组合效果，避免一次同时修改三层而无法归因。

## 6. 统一验收标准

| 维度 | 必须验证 | 不采用的替代指标 |
|---|---|---|
| 原文送达 | 最终模型消息可解析，正文、定位和续取信息完整；长文按可核验片段送达 | 工具服务返回成功就算读到 |
| 结构真实性 | 块／表身份清楚，字段来源可查，缺失元数据明确未知 | 15 个 table locator 就算 15 张表 |
| 范围覆盖 | 固定 build 和范围内的请求、取回、送达及未解决项可复算 | 声明跳过后把缺失改成完整 |
| 结论证据 | 引文、期间、单位、表头、必要脚注能支持对应结论 | 所有财务结论强制引用 `table:*` |
| 分页可靠性 | 游标可续取、有进展、固定快照；失败可定位；超大单元有确定结果 | 整个范围保证一次调用或常数次调用 |
| 准备质量 | 关键事实、阅读序、结构关系和非空白原文可追溯 | 私有区字符归零或所有 body ≥ 200 字 |
| 成本 | 同等证据质量下比较调用、补取、token 和延迟 | 只比较 chunk 数或返回字符数 |
| 真实接入 | Markdown 报告和最终回复路径实际执行校验 | 仅修改策略卡校验函数 |
| 发布安全 | 新 build 校验、版本一致性和兼容回滚演练通过 | 仅保留旧文件就声称可回滚 |

历史样本用于开发和回归，不能同时充当独立效果证明。应另建受控验证集；不得为调参打开仓库已有受保护评测答案。验收结果须区分静态检查、模拟工作流、隔离库回放和真实模型试验。
