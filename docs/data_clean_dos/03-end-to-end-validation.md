# 03 · 独立研报与模型获取的执行计划

> 2026-09-29。状态：计划已落文档，以下验证尚未执行。承接本次对话对收口条件的修正。
> 主目标见 [总览](README.md#主目标完成判定的唯一依据)。本文统筹 A/B 两侧的后续工作；
> 文档定稿、缺陷登记、隔离发布演练均不等于总任务完成。

## 1. 当前判断与完成边界

保留 A0–A4、B0、B1/B3 和隔离发布演练的已有成果。B1/B3 的结论限于开发样本上的对照，
普遍性和模型实际获取仍待验证。当前总任务继续进行，不按日期或签认文档关闭。

验证链路为：源 PDF → reader → clean → chunk／检索索引 → 模型正常检索与取回 →
最终模型输入 → 有依据的回答。既检查所需内容能否通过工具获取，也检查模型在正常任务中
是否实际取得它。内容已送达但模型答错，仍是端到端失败，归因到使用环节，不能冒充数据通过后
总任务就通过；同样不能据此直接修改清洗规则。

普遍性结论限定于事先声明并实际覆盖的机构、模板、报告类型、版式与运行配置。有限样本
不提供对任意 PDF、任意模型的绝对保证。支持范围内的关键缺口必须处理；范围外或暂不支持
项保留数量、原因与产品可见的缺口提示，不计成功，不在跑后移出分母以达标。

## 3. 样本、证据及清洗契约

- 现有 6 来源／30 题作为开发回归集。独立首批以至少 12 篇未参与调参的研报、至少 3 家
  机构为采集起点，覆盖公司／行业／宏观；每项声明支持的高风险版式至少有两份独立文档。
  数量只是采集起点，覆盖不足不得声称普遍性已验证。模板相同、同报告修订版及重复 PDF
  按同组划分，避免训练式修规则与验证共用近重复来源。
- 核查单栏／多栏、首页信息框、正文与标题混排、单格真实表格、合并表头、跨页续表、单位／
  脚注、风险文字、特殊符号和扫描／图片区域。扫描或图像内容若不能提取，记录支持缺口；
  现有发布放行或人工缺口凭证不等于该内容已可获取。
- 每个目标从源 PDF 页建立：文档内容身份、页码／区域、原文、主体／指标、期间、单位、
  表头／行标签／必要脚注、可接受的证据组合和回答要求。对照源页核查旧提取和新提取，不能
  仅以二者字符数相等判定完整。关键风险／假设即使没有数字也必须进入保护样本。
- 保留权威原文及源映射；clean 的可检索视图不应误排除关键内容；chunk 可跨块提供证据，
  但取回后必须能够复原所需内容与结构关系。`chunking_impact` 暂保留历史统计字段，新增
  实际获取判定：跨块且可正常补齐可通过；不可追溯、不可完整获取、结构失真或不可正确引用
  才构成相应失败。不得重写历史归因记录来制造改善。
- R1 必须验证真实单格表格不会被当正文破坏；R2 必须验证多栏并排标题、不同章节和真正
  连续标题的区别。是否保留规则取决于这些反例和端到端收益，块数下降不构成必要性证明。

## 4. 模型获取如何实测

1. 模型只接收正常用户问题及产品本来提供的上下文，使用正式工具和默认检索流程；评估侧
   不注入正确 locator、证据引文、答案或定制的命中查询。用户本来指定报告的任务可保留
   该报告约束，和跨文档检索任务分别统计。
2. 评分侧保管证据集，执行代理不可经文件、shell 或工具读取评分答案。执行时设置可验证
   的文件访问边界并留记录，仅在提示词中要求“不看答案”不满足隔离要求；受保护评测答案
   继续不参与本任务。样本源 PDF 可用于离线核验，模型实测的取证入口必须是清洗后的语料。
3. 对相同题、相同模型配置和预算，分别运行固定的旧 build 与候选 build；每次独立会话，
   保存版本、真实查询、响应、游标、错误、最终模型请求和回答。不得用检索评分脚本的特殊
   查询替代模型真实行为，也不得以整篇文档计入 offered 来证明目标已被提供。
4. 每个目标分别标记 `source_present`、`extracted`、`clean_retained`、`tool_reachable`、
   `offered`、`requested`、`fetched`、`delivered`、`answer_supported`，附证据引用及失败层。
   `tool_reachable` 可离线定点诊断，但不计成模型自然检索成功。送达须核验目标及必要依赖
   在最终模型输入中的实际内容；账本或 A4 `verified` 不能单独替代评分。
5. 主部署模型／工作流完成完整矩阵，候选每题预先安排 3 次独立运行，以全部运行统计稳定性；
   若声明支持 react 与 agent_team，两条路径分别验收。第二模型／提示变体用于扩展配置范围，
   不能拿跨模型平均值掩盖主部署配置失败。回答判断检查数值、主体、期间、单位和引用依据，
   允许正确释义，不要求答案机械复述整段金标。
6. 留出失败导致修规则时，该批转为开发回归集，另补未参与修改的留出批；保留首次失败结果、
   数据集版本及修改原因。成本报告包含所有尝试的调用、token、延迟和失败，减少 chunk 只能
   作为辅助指标。

## 5. 总任务的收口条件

以下是执行前的质量门槛，E1 将其落实为具体样本字段和机器判定；不得在看完结果后放宽：

1. 范围和矩阵已冻结，各声明支持类型均有独立验证；有可复核的逐题源页证据。
2. 已知关键内容误删、结构损坏和映射失败在支持范围内修复，开发回归无新增关键失败。
3. 独立验证所有预先指定的关键目标及必要依赖，在每次预定运行中均经正常工具完整送达，
   并支持正确回答和可核验引用；超时、未运行、缺数据、unknown 均不计通过。其他目标逐项
   报告，支持范围内尚未解决的获取或正确使用失败仍阻止总任务完成。目标分级只用于排修优先级。
4. E4 的分层判定能解释所有失败；关键事实不存在源页有、清洗产物无、模型仍自信作答的
   未处理情形。没有统计失败不等于对所有研报保证成功，验收报告必须同时写样本量和覆盖范围。
5. 质量达到上述门槛后比较成本和预算，给出基线／候选取舍及生产发布建议；已有隔离回滚
   证据可复用，后续修改影响其契约时补跑。A4 默认阻断是独立产品决策，报告锚点 F3 与行为
   方差 F4 继续跟踪；清单机制的通过不能替代内容获取的通过。

可以记录“计划完成”“开发回归通过”“独立验证未通过”等阶段状态。文档签认、文件存在、
工作移入 backlog 均不满足总任务完成条件；发布执行状态另行记录。
