# 投研工作台前端重构：需求与交互设计

| 项目 | 内容 |
| --- | --- |
| 版本 | 0.1 · 设计基线 |
| 日期 | 2026-09-12 |
| 目标 | 将现有「单栏聊天 + 抽屉详情」升级为面向深度投研的三栏工作台 |
| 参考 | 用户提供的深色研究工作台截图；现有 Web 与 FastAPI 服务端实现 |
| 本文范围 | 信息架构、视觉系统、交互、前后端契约、交付顺序；不改变 Agent 内核或数据隔离策略 |

## 1. 设计结论

推荐采用「**研究导航 / 对话编排 / 研究画布**」三栏桌面工作台：左栏让用户持续管理研究上下文，中栏承载人机协作与 Agent 的执行过程，右栏始终承载可阅读、可下载、可追溯的报告或产物。

它继承参考图的深色、低干扰、高密度阅读体验，但不是复刻：右栏不再是静态 Markdown 阅读器，而是与一次真实 `Run` 绑定的**研究画布**；中栏也不再把工具调用、状态、审批藏进抽屉，而是按任务阶段就地呈现。

### 当前问题

| 现状 | 对投研工作流的影响 | 新设计的处理 |
| --- | --- | --- |
| 顶部横向导航 + 浅色 Element Plus 默认样式 | 研究、对话、报告三种注意力被切散；长报告阅读缺少沉浸感 | 进入应用即落在深色工作台，模型配置收进账户/设置入口 |
| 会话、消息、工具过程、报告/产物分隔很弱 | 用户只能“等回答”，看不到研究正在推进到哪里 | 以一次 Run 为中心显示阶段、工具活动、产物状态与终态理由 |
| 运行详情与产物都在右侧抽屉 | 打开过程会遮挡对话，阅读报告又要反复切换 | 右栏常驻为画布；过程细节按需展开，不抢占阅读区 |
| 输入框只有文本发送 | 上传文件、继续引导、停止、插话和审批的语义不清 | 升级为研究编辑器，明确附件、研究模式、发送、停止、插话与审批状态 |
| 当前页面只呈现“对话” | 服务端已提供的 Run、SSE、Artifacts、Diff、Approval、Steer 能力没有被组织成可理解的研究体验 | UI 逐一映射到现有 REST/SSE 契约，保留服务端为事实来源 |

## 2. 已验证的后端边界

设计以代码现状为准，而非假设新接口。

```text
Session（持续研究主题）
  └── Turn（用户问题 / 助手回答）
        └── Run（一次隔离执行）
              ├── SSE 实时过程 + trajectory 回放
              ├── inputs/ 用户附件（只读）
              ├── ws/outputs/ 产物（可预览、下载）
              └── diff / approval / steer / stop 等可控状态
```

### 2.1 可直接使用的能力

| 用户体验 | 当前契约 / 事实来源 | 工作台中的位置 |
| --- | --- | --- |
| 新建、切换、软删除研究 | `POST/GET/DELETE /api/sessions`；`GET /turns` | 左栏“研究”列表 |
| 发起研究，含附件 | `POST /api/runs`，JSON 或 `multipart/form-data` | 中栏研究编辑器 |
| 实时回答与任务状态 | `GET /api/runs/{id}/events?after=N`；Bearer + SSE cursor | 中栏回答、运行阶段条、活动轨迹 |
| 断线重连与终态核验 | SSE `seq` 游标；`GET /api/runs/{id}` | 页面重载/网络恢复后的运行卡片 |
| 停止、插话、审批 | `control`、`steer`、`approve` 路由 | 阶段条、就地插话框、审批阻塞卡 |
| 过程回放 | `GET /api/runs/{id}/trace` | “过程”可折叠面板 |
| 产物、预览、下载 | artifacts list / preview / download | 右侧研究画布 |
| 文件修改与回滚 | `GET /diff`、`POST /revert` | 画布内“变更”子页，终态后可用 |
| 模型配置 | `/api/models`；密钥只以掩码形式返回 | 账户菜单的“模型与连接”页 |

### 2.2 不应伪装为已具备的能力

| 名称 | 现状 | 产品处理 |
| --- | --- | --- |
| 项目 / 文件夹 / 团队空间 | 后端只有 Session，没有项目实体或成员权限模型 | V1 左栏只称“研究”，不显示可点击但无数据的“项目” |
| 跨全部历史的语义搜索 | 没有对应检索 API | V1 仅在已加载会话列表内做本地标题过滤；全局搜索列为后续接口需求 |
| 结构化来源库与引用图谱 | Agent 输出可能带 Markdown 链接，但没有 source registry | V1 显示报告原有链接/脚注；来源卡片、证据图谱需新增后端模型 |
| 每次运行自由选择模型或 Profile | 当前 Run 使用服务端默认配置与服务器 profile | V1 只显示 run 返回的模型快照；若要可选，新增显式且受控的提交字段与审计 |
| 进行中 Run 的跨会话总览 | sessions list 无 active-run 摘要 | V1 只跟踪当前打开的 Run；跨会话运行台需后端聚合接口 |

这些边界是关键：界面中的“资料库”“环境”“项目”不能仅为好看而做成可操作入口，否则会制造状态错觉。

## 3. 用户与核心任务

**主要用户：** 做宏观、行业、公司或策略研究的个人投资者与投研人员。他们需要长时间阅读、追问、验证与留存报告，而不是一次性问答。

**核心任务：**

1. 新开一项研究，补充主题、时间范围、约束和输入文件。
2. 在 Agent 执行中知道“已做什么、正在等什么、能否安全地干预”。
3. 一边追问一边阅读已有结论，避免在聊天和报告之间来回跳转。
4. 从每条结论回到运行过程、产物或文件变更，形成可审计的研究链。
5. 在失败、停止、审批或网络中断后理解可恢复状态，而不是把状态误认为回答丢失。

## 4. 信息架构与布局

### 4.1 桌面（≥ 1280px）

```text
┌──────────────────────┬──────────────────────────────────────┬──────────────────────────────────────┐
│ A. 研究导航 252px     │ B. 对话编排 min 560px                 │ C. 研究画布 42–48vw                    │
│                      │                                      │                                      │
│ 品牌 / 新建研究       │ 研究标题 · Run 状态 · 可信状态信息     │ 文件名 · 来源 · 下载 / 全屏              │
│ 本地研究搜索          │ ──────────────────────────────────── │ ──────────────────────────────────── │
│ 进行中 / 最近 / 归档  │ 用户问题                              │ 结论 / 证据 / 执行 / 过程                │
│ 会话列表              │ Agent 回答 + 就地活动摘要              │ 可阅读 Markdown / 文本 / 图片预览         │
│                      │ 可展开：计划、工具、思考、错误、审批   │ 目录、引用链接、关联产物                  │
│ 账户 / 模型与连接      │ ──────────────────────────────────── │                                      │
│                      │ 研究编辑器：附件 / 模式 / 发送          │                                      │
└──────────────────────┴──────────────────────────────────────┴──────────────────────────────────────┘
                         合规提示：AI 输出仅供参考，不构成投资建议
```

**可调原则：** 右栏宽度可拖拽；用户也可切换“专注阅读”（隐藏左栏和中栏的非必要部分）。这比固定三栏更适合长报告。

### 4.2 窄屏与移动端

| 宽度 | 行为 |
| --- | --- |
| 1024–1279px | 默认二栏：左栏收窄为 64px 图标/tooltip 导航，研究画布可由顶部按钮展开覆盖中栏。 |
| 768–1023px | 对话为主；研究和画布为左右抽屉，保留底部编辑器与运行状态。 |
| <768px | 单列；会话列表、画布、运行详情依次使用全屏 sheet。长报告默认阅读模式，编辑器固定底部。 |

不在移动端强塞三栏；投研阅读的首要目标是可读性，而不是桌面布局缩小。

## 5. 视觉系统

参考图的价值在于“报告被当作主要内容”，不是某一种黑色。新界面使用温暖近黑、纸感文字与单一芥末黄标记运行中的焦点，避免冷蓝开发者控制台感。

### 5.1 Design tokens

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-app` | `#10110E` | 应用底色 |
| `--bg-rail` | `#0C0D0B` | 左栏、浮层底色 |
| `--bg-raised` | `#181A15` | 编辑器、子面板 |
| `--line` | `#303228` | 真实分隔线，不堆叠卡片 |
| `--text` | `#F0ECDD` | 主文本 |
| `--muted` | `#A5A59B` | 辅助信息 |
| `--quiet` | `#6F7068` | 禁用/低优先级 |
| `--accent` | `#D5C93A` | 当前研究、键盘焦点、进行中状态 |
| `--ok` | `#9BBE87` | 完成/安全 |
| `--warning` | `#E5B466` | 等待、需关注 |
| `--danger` | `#D78778` | 失败、停止、拒绝 |

- UI 字体：`PingFang SC` / `Noto Sans CJK SC` / 系统 sans；报告标题：`Songti SC` / `Source Han Serif SC`；等宽信息：`IBM Plex Mono` 或 `SFMono-Regular`。
- 行高：聊天 1.72；报告正文 1.82；代码与活动事件 1.55。正文最大行宽 720px，报告画布 760px。
- 圆角只用于编辑器、审批/确认这类“可操作物”；静态内容以边线、排版、留白分层。
- 图标使用现有 Element Plus 图标体系，所有图标需配文字或 aria-label；不以装饰性图标填充界面。

### 5.2 状态不能只靠颜色

| 状态 | 视觉 | 文案 |
| --- | --- | --- |
| queued | 空心标记 + 中性文字 | “排队中” |
| running | 芥末黄脉冲点（允许减少动态效果）+ 阶段名称 | “正在检索 2/4” |
| waiting approval | 实线警告边框 + 明确按钮 | “等待你决定” |
| completed | 低调绿色勾 + 完成时间 | “已完成 · 2m 14s” |
| stopped | 暖灰停用标记 + 停止原因 | “已停止 · user_stop；已保留部分结果” |
| failed | 红色边框 + 原因 + 可恢复动作 | “运行失败：连接超时；重试 / 修改模型连接” |

## 6. 详细交互需求

### 6.1 A 栏：研究导航

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| NAV-01 | 顶部提供“新建研究”，创建成功后立即选中并聚焦编辑器。 | 调用 `POST /sessions`，失败不留下空白本地条目。 |
| NAV-02 | 列表按服务端 `updated_at` 顺序展示标题、最后活动时间和本地可见的 turn 数。 | 切换后加载对应 turns；当前项有文本和高对比选中态。 |
| NAV-03 | 搜索仅过滤已加载列表，placeholder 明示“筛选已加载研究”。 | 不承诺全局检索；分页继续沿用 store 的加载逻辑。 |
| NAV-04 | 删除为二次确认，明确“此操作会在当前视图移除研究”。 | 以服务端软删除结果为准；404 显示“研究不可用”。 |
| NAV-05 | 账户菜单收纳“模型与连接”“退出”。 | 复用现有 `models` 路由，API key 始终不在前端缓存/显示。 |

### 6.2 B 栏：对话与执行编排

#### 消息与研究阶段

每个用户问题与其 Run 共同组成一张**研究回合**，而不是一段普通气泡：

```text
用户问题
  ↓
运行阶段条（排队 / 执行 / 等待审批 / 终态）
  ├─ 简明进展：已处理 n 个工具调用、耗时、模型、上下文占用
  ├─ 可展开过程：计划 → 工具 → 思考 → 错误
  └─ 控制：停止；运行中插话；打开画布/过程
  ↓
助手回答（流式 Markdown，最终写入 Session turn）
```

| 编号 | 需求 | 交互与边界 |
| --- | --- | --- |
| CHAT-01 | 已保存消息与正在流式的回答视觉一致，但运行中回答需有“生成中”标记。 | SSE delta 只用于临时展示；终态后重新读取 turns，避免只依赖浏览器内存。 |
| CHAT-02 | 阶段条默认收起冗长过程，只展示阶段、已用时间、模型、工具数量、上下文占用和停/插话入口。 | 每次状态都源自 `Run`/SSE，不根据动画计时伪造。 |
| CHAT-03 | “查看过程”在中栏就地展开，按“计划、活动、轨迹、变更”分组。 | 复用既有 `PlanPanel`、`ActivityPanel`、`RunDetailView`、`DiffPanel`，但从 drawer 移入可折叠区。 |
| CHAT-04 | 停止按钮在 running/queued 状态可见；点击后立即显示“正在请求停止”，直到终态或 409 说明已结束。 | `POST /control {action: stop}`；部分答案与 `stopped_by` 必须保留。 |
| CHAT-05 | “补充方向”仅在运行中显示为插话输入；发送后显示“已排队，下一工具边界生效”。 | `POST /steer`；不能假称即时修改了当前模型输出。 |
| CHAT-06 | 审批请求以就地阻塞卡呈现目标、原因、风险、预览和选择，不只弹窗。 | 仍调用 `/approve`；高风险确认、拒绝替代指令与原安全提示不可省略。 |
| CHAT-07 | 错误和停止明确显示“为什么”及下一步。 | 优先 `GET /runs/{id}` 的 `error`/`stopped_by` 作为权威终态。 |

#### 研究编辑器

编辑器不是普通 textarea；它是一次研究请求的轻量结构化入口。

| 元素 | V1 行为 | 后端约束 |
| --- | --- | --- |
| 主输入 | 多行 Markdown 纯文本；Enter 发送、Shift+Enter 换行；中文输入法 composition 中绝不误发。 | `message` 发送至 `/runs`。 |
| 附件 | 拖拽或文件选择后在输入框上方显示文件名、大小、移除。 | 改用 `FormData`；后端上限 20 个 / 单文件 50 MiB，服务端会扁平化文件名并写入 `inputs/`。 |
| 研究意图 chips | “深度研究”“报告产出”“快速追问”仅帮助用户组织 prompt，可插入可编辑文本模板。 | 不把 chip 虚假映射成不存在的 per-run profile API。 |
| 发送 | 发送后锁定本回合的“新 Run”按钮，但允许同会话后续排队/服务端决定串行。 | 保留现有一次只订阅一个 active stream 的前端模型。 |
| 停止 / 插话 | 运行时将发送按钮替换为停止与“补充方向”。 | 分别使用 `/control` 与 `/steer`。 |
| 快捷命令 | `/report`、`/risk`、`/compare` 等只作为文本模板。 | 不引入客户端命令解释器或绕过 Agent 的工具权限。 |

### 6.3 C 栏：研究画布

画布是“当前研究成果”的可读副本。它与当前 Run 绑定，而非与整个浏览器或最新聊天消息隐式绑定。

| 编号 | 需求 | 规则 |
| --- | --- | --- |
| CANVAS-01 | 顶栏显示内容名、来源类型、生成/更新状态与下载。 | 来源明确标为“本次回答”或“输出文件”，不把二者混为同一份持久化报告。 |
| CANVAS-02 | 有 Markdown 产物时默认优先展示最新 Markdown；无产物时展示 run 的 `final_answer`。 | 终态后查询 artifacts，再用 preview 获取内容；预览失败提供下载。 |
| CANVAS-03 | 子页为“结论 / 证据 / 执行 / 过程”。 | V1 这些是同一 Markdown 的目录锚点、链接与运行摘要；不编造结构化证据数据。 |
| CANVAS-04 | 产物列表支持 Markdown、文本、图片预览；二进制只显示下载。 | 严格使用 server preview 的 `kind` 和截断标记，不在浏览器解析二进制。 |
| CANVAS-05 | 有文件变更时显示“变更”标签，并将回滚标为终态、危险操作。 | `diff` 404 时完全隐藏；仅后端允许的项目可回滚。 |
| CANVAS-06 | 点击回答中的 Markdown 链接只打开外部资源；引用编号不承诺能反查数据库。 | 结构化引用需要后续 source API。 |
| CANVAS-07 | 画布可进入专注阅读与全屏模式，保留 Esc 回到工作台。 | 不能隐藏合规提示；偏好以 localStorage 保存。 |

### 6.4 键盘、辅助功能与动效

- `Ctrl/Cmd + K`：打开工作台命令面板（新建研究、筛选本地会话、打开模型与连接、切换画布）。
- `Ctrl/Cmd + Enter`：发送；`Shift + Enter`：换行；不得在 IME composition 状态下发送。
- `Ctrl/Cmd + Shift + R`：在画布与对话之间切换阅读焦点。
- 所有状态、控制和文件行可用键盘抵达；焦点使用芥末黄 outline，最低 3:1 对比。
- 遵守 `prefers-reduced-motion`：进行中的点从脉冲降级为静态标记；面板无大幅位移动画。
- 阅读区使用语义化 `article`/`nav`/`main`/`aside`；运行过程的更新通过 `aria-live="polite"` 提示。

## 7. 前端状态、SSE 与数据流

### 7.1 事实来源优先级

```text
服务器 Run 行（终态、错误、stopped_by、usage）
          ↑ 终态 / 重连后核验
SSE 实时流（临时 delta、工具生命周期、审批、插话）
          ↑ after=seq 续接
Trajectory / Artifacts（可回放过程与持久化产物）
          ↑
Vue/Pinia 视图状态（只缓存选择、展开、阅读偏好）
```

**禁止：** 将 streaming 文本、运行完成态或产物清单只保存到 localStorage 后当作权威数据。localStorage 仅保存“上次会话”“右栏宽度”“阅读模式”“局部展开状态”。

### 7.2 Run 状态机

| 状态 | 进入事件 | UI 行为 | 退出/恢复 |
| --- | --- | --- | --- |
| queued | `POST /runs` 返回 202 | 显示“排队中”，禁重复提交同一编辑器 | `run_started` 或 `GET /runs` 核验 |
| running | `run_started` / delta / tool event | 流式回答、阶段条、停止和插话可用 | 终态 event / 连接重试 |
| waiting_approval | `approval_requested` | 显示阻塞审批卡，仍显示已完成过程 | `approval_resolved` |
| completed | `run_completed` 或权威 summary | 刷新 turns、artifacts、diff；画布可选报告 | 保留为历史回合 |
| stopped | `run_stopped` 或 summary | 显示部分结果、停止原因；刷新可用产物 | 可继续追问，不把它当失败 |
| failed | `run_failed` 或 summary | 显示安全错误摘要与重试/配置入口 | 重试为新 Run，不复用旧 run_id |

## 9. 验收标准

### 功能

- 新建、切换、分页、软删除研究仍通过现有 Session API，且不会暴露其他用户数据。
- 支持纯文本和附件提交；超文件数/大小时展示服务端错误，不在前端静默丢文件。
- SSE 重连后不会重复渲染已经收到的完整回答；终态会用 `GET /runs/{id}` 核验。
- 停止、插话、审批、回滚都展示真实确认态、失败态与下一步，不将 409 显示成成功。
- 有 Markdown 产物时右栏可预览；预览受截断时可见提示；不可预览文件只提供下载。
- 密钥、Bearer、上传文件物理路径和未脱敏工具内容不被新组件写入日志或持久化到 localStorage。

### 体验

- 1440×900 下三栏无需横向滚动；中央对话文本最大阅读宽度受控；右栏报告标题与正文可连续阅读。
- 1024px 下用户可在对话与画布间一键切换；375px 下任一核心任务可完成。
- 运行中用户不必打开 drawer 就能理解当前阶段、已完成活动、是否等待自己决定。
- 深色模式首屏即生效，不闪白；正文、次级文字与焦点均通过对比度检查。
