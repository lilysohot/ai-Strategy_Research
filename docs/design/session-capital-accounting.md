# 会话规划资金与账户现金联动

入口为 `POST /api/business/sessions/{research_id}/capital-plan`、规划资金的
`allocations` / `reset`，以及 `buy-sell-plans` 的创建、修改、归档接口。
资金计算、账户版本、业务版本、审计与幂等结果在同一数据库事务内提交。

## 金额口径

- `InvestmentAccountRevision.available_capital` 是账户现金余额。
- `CapitalPlan.allocated_capital` 是本会话预算总额，创建、追加与重置都不直接扣减现金。
- 买入现金影响为 `-(price × quantity + fees)`；卖出为 `price × quantity - fees`。
  手续费省略按零处理，乘积按数据库的 10 位小数精度舍入。
- 会话剩余额度为 `allocated_capital + min(已入账净现金流, 0)`。
  卖出补回额度，超过预算的净流入释放到主账户可分配额度。
- 账户预留额度为所有未删除会话剩余额度的非负部分之和。
  可继续分配额度为 `available_capital - reserved_capital`。
- 总资金是用户填写的资产估值；买卖现金流不直接覆盖总资金，也不推算持仓盈亏。

例如账户现金 10000，规划 6000 后，可继续分配 4000。买入 1000、手续费 5 后，
账户现金 8995，会话剩余 4995，可继续分配仍为 4000，不重复扣减。

创建规划时可通过 `account_id` 明确选择资金账户，并在同一事务内同步会话绑定；
省略时使用会话已绑定账户，没有绑定时继承用户默认主账户。选择只影响当前会话，
不修改默认主账户。尚无资金入账的会话可通过
`POST /api/business/capital-plans/{capital_plan_id}/account` 换绑账户，携带
`account_id`、`expected_revision` 和幂等键。换绑原子释放原账户预留、占用新账户
额度并保留版本历史；新账户必须属于本人、未归档、币种一致且额度充足。
一旦发生资金入账（包括之后冲销或归档的记录），账户归属固定。
切换用户默认主账户不会迁移已有会话。账户现金缺失、币种不同、超额规划/买入会返回业务错误。
数量缺失的价格记录可以保存，标记尚未联动，不用于资金变动。

## 更正、归档与历史

`BuySellPlan.cash_effect` 保存该记录已经记入账户的现金影响。修改按新旧差额入账，
归档按反向差额冲销。重复幂等键重放原结果；重复归档不会再次冲销。若冲销卖出导致
现金或会话额度不足，整个操作拒绝。账户现金的手动修改也不能侵占已预留额度。

删除会话只释放尚未使用的预留额度，已发生的成交与现金变动保留，不把实际支出退款。
删除后停止新的资金写入。

迁移 `0025_session_cash_link` 添加现金影响和手续费列，不改写历史账户余额。
存量记录的 `cash_effect=NULL`，读取时计入 `unbooked_count`；归档这种记录不退款。
修改旧记录且提交完整成交数量时会首次入账，因此上线前必须核对这些记录与账户现金
基准是否已经相互包含，不能批量重放旧记录。历史余额对账不属于自动迁移。

## 接口与界面

账户列表与详情返回 `funding.reserved_capital`、`funding.allocatable_capital`。
会话规划返回 `funding.remaining_capital`、`funding.net_cash_flow`、`funding.unbooked_count`。
`account_binding_locked` 表示是否已有记账历史；界面显示所选账户、币种和可分配额度，
创建规划时提交选择；已记账时禁用换绑。
买卖记录返回 `cash_effect` 与 `values.fees`。金额仍以十进制字符串传输。
分析快照冻结会话剩余额度、净现金流与尚未联动记录数，标记为派生值。

前端资金写入后同时刷新账户、会话和买卖记录。同内容的失败请求重试复用幂等键；
提交成功但刷新失败时提示刷新页面，避免把刷新错误误报为提交失败而重复登记。

实际买卖保存成功后，使用本次保存前捕获的会话与资金账户提交 `holding_cost` 分析，
传入实际成交资料，由服务端读取会话规划资金；不再要求历史 `primary_plan_id`，
也不发送旧投资计划引用。此前遗留的主计划判断会导致新会话保存成交后静默跳过分析。
分析提交成功后关闭资金窗口、将消息挂到当前会话并跟踪运行；提交失败保留错误提示，
成交保存本身不回滚。浏览器回归覆盖“无历史主计划 → 保存一次 → 分析一次 → 对话可见”，
后端回归验证分析资料持久化不会重复扣减已记账成交。

写入遵循账户 → 规划资金 → 买卖记录的加锁顺序，与分析读取的账户锁顺序一致。
跨会话额度校验在账户锁内完成。测试覆盖 SQLite 功能回归和独立 PostgreSQL
上的并发分配、并发买入、幂等重试、分析读取交错与迁移。
换绑先锁会话，再按账户 ID 排序锁定新旧账户，最后锁规划资金；普通资金写入若在
等待锁期间发现绑定变更，则返回版本冲突，要求刷新后重试。
