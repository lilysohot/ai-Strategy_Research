## 1. 当前判断与补充目的

2026-11-18 的只读核对中，Super-link 规格仍标记未实现，针对 server、workflows、
frontier_agent 和 tests 的名称检索未发现明确实现；产品基线仍定位为研究系统、不下单。
这是当次检查范围内的观察，不构成完整代码审计，也不是对后续版本的现状断言。

已讨论的协作机制解决研究如何交付、检查、排队与续接，但没有据此证明交易优势。
研究结论有依据、交付合格、工程稳定和策略盈利是不同层面的结果。

建议在既有“研究—交付—监控”链路外补充“事前假设—独立验证—结果归因—保留或淘汰”
的反馈链。目标是在明确风险、成本和比较基准的条件下，持续筛选有证据支持的正期望
策略；允许亏损期、持续观察和当前没有可执行策略。架构与回测均不能保证持续盈利。

本文记录值得继续设计的方向；市场、策略类型、评价阈值、样本要求、实施顺序与实盘
范围仍需具体讨论，不将以下建议自动加入基础规格 SL-01—SL-22 的实施验收。

## 2. 交易假设需要说明优势来源

“研报判断正确”并不意味着交易可以盈利：市场可能已经预期改善，价格可能过高，兑现
时间也可能超过可接受范围。候选对象之外，还应讨论可检验的交易假设：

- 市场可能忽略或错误定价的是什么。
- 本方依据什么识别这种差异，而不只是重复公开观点。
- 什么事件或过程可能促使差异收敛。
- 预期观察时间范围和可核验结果是什么。
- 哪些事实出现时，应否定或修正假设。

这些是建议的研究问题，不冻结成每次交付必须填写的固定表单。没有清晰优势来源的对象
可以继续观察，不强行转为等待交易信号的对象；延续 PRD §2.8 的业务调整空间。

## 3. 跨领域借鉴及其在 Super-link 中的含义

### 3.1 实验科学：事前登记、对照与失败记录

建议在验证前保存假设、策略版本、对象范围、信号、持有与退出逻辑、比较基准和失败
条件。允许修改，但应形成新版本，不根据已知结果改写原实验。失败、被放弃和表现不佳
的尝试也应记录，不能只展示最终选中的赢家。

多次尝试后仅报告成功结果会夸大表现。Deflated Sharpe Ratio 研究讨论了多重检验、选择
偏差和收益非正态性，并提出相应调整方法；这些方法不是盈利认证，也不应不经适用性
检查就设为固定通过阈值。[原始论文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

建议明确三类不同检查，不将其全部交给旁路：

| 检查 | 回答的问题 | 与既有职责的关系 |
|---|---|---|
| 旁路监管 | 是否符合任务、证据是否可用、能否推动下一步 | 保持独立监管职责，不证明盈利 |
| 策略验证 | 相对可执行基准，是否存在可信且可重复的交易价值 | 可由独立计算与评估模块承担，不要求新增 Agent |
| 运行与风险检查 | 数据、资源和适用风险条件是否允许继续执行 | 由相应程序和执行接口落实，不以模型口头判断替代 |

因市场不可任意随机化，策略对照不自动具有实验室随机试验的因果证明能力；结果归因应
说明比较条件和限制。这里借鉴的是事前约定、完整记录与对照方法。

### 3.2 数据溯源：区分事件、信息可得与可行动时点

建议将时间链表达为：事件发生 → 信息公开 → 系统取得 → 判断形成 → 最早可行动。
财报所属期间不等于披露日期；收盘后形成的信号不能直接假设按当天收盘价成交。
排队、研究和核查耗时均属于决策延迟，验证中不能省略。

LLM 还有训练资料带来的历史结果记忆风险：只限制检索日期不能保证模型不知道后来
发生的事情。按时间截断训练语料的研究专门讨论了这一类前视偏差。
[NBER 工作论文摘要](https://www.nber.org/papers/w35247)

建议把历史回测用于筛选、逻辑检查和脆弱性分析，同时开始保存事前预测与决策，使用
随后真实发生的数据前瞻验证。记录模型、提示词、工具和策略版本；实质变化单独归档。
前瞻记录并不自动证明长期有效，但更能避免用今天的模型重新解释过去所产生的污染。

### 3.3 控制系统：反馈延迟、更新节奏与时效

借鉴控制系统对延迟和频繁调整的关注：Team 深度研究、Single 新事实复核和确定性
运行保护可以具有不同节奏，不能要求每个监控事件都触发完整深度研究。

FIFO 保证顺序，不保证及时。信号有效期若短于排队、研究与核查总耗时，可靠执行也
可能没有交易价值。应记录时效并在轮到时复核，过期则留下相应处理结果，不以追赶机会
为由让模型绕过既定队列；具体时效表达及处置仍需设计。

以数日到数周、多份资料交叉核验的假设作为早期试点，是基于当前架构的适配建议，
不是收益结论或固定产品周期。更短周期需以实际延迟和成交条件证明适配性。

宏观环境应成为可检验的条件。建议对比加入宏观过滤与不加入过滤的版本，验证其是否
增加价值，避免把环境标签仅用于事后解释。策略调整也应保留版本和变化原因。

### 3.4 组合管理与资源调度：独立判断与共同资金事实

如果未来多个策略使用同一账户，各方研究判断仍然独立，但必须读取同一权威持仓和
资金事实，并受账户整体风险约束。多个公司可能暴露于同一行业或同一经济假设，逐项
合理不代表组合风险合理。

后续需讨论行业及共同风险暴露、流动性、换手、容量、多策略资金预算占用与增量风险。
账户和组合事实来源不等于双方共享研究状态，不改变 PRD §2.1。只有未来明确进入资金
执行范围时，才实施相应资金控制；本文没有增加下单、仓位修改或资金使用授权。

交易成本会降低异常策略的盈利性和统计显著性，高换手策略更需要评估成本影响。
[Novy-Marx 与 Velikov 的实证研究](https://www.nber.org/papers/w20721)

建议分别评价扣除适用手续费、价差、滑点等交易成本后的表现，以及扣除数据、模型和
基础设施费用后的运行经济性。交易净收益为正不代表整个系统具有经济价值；成本估计
及口径须可追溯，不能根据最终收益反向调整假设。

### 3.5 可靠性工程：影子运行、对照和逐步扩大

Google SRE 的灰度发布实践强调比较新旧版本并分组观察指标，避免总体指标掩盖新版本
问题；对异步处理链路也讨论了质量和端到端耗时的评价。
[Google SRE：Canarying Releases](https://sre.google/workbook/canarying-releases/)

将这一方法迁移到策略验证属于本项目的设计建议，不表示软件灰度发布能够证明金融收益：

| 阶段 | 拟验证内容 | 限制 |
|---|---|---|
| 历史检验 | 时间语义、逻辑、成本与交易约束下是否值得继续 | 防范前视偏差和反复筛选；历史表现不保证未来 |
| 前瞻影子运行 | 事前记录信号，按预设成交假设记账，观察时效与表现 | 不执行真实交易，不能完整模拟真实冲击和成交能力 |
| 简单方案对照 | Super-link 相对 Single 或简单规则的增量价值 | 信息时点、对象范围、风险和成本口径应可比 |
| 后续有限实盘试验 | 模拟与真实成交的差异 | 需另行明确范围与授权，不属于当前实施承诺 |
| 持续复核 | 优势衰减、成本变化及暂停、修改或淘汰理由 | 依据预先约定的评价方式，不只追逐短期结果 |

交易样本可能相互关联，不能把大量重复信号当成同等数量的独立证据。验证周期和样本
要求应按假设确定，不预设“运行固定天数就可宣告盈利”。

### 3.6 多 Agent 的共同失误

独立角色和记录不代表统计意义上的独立判断。Team、Single 和旁路若使用相同模型及
来源，可能共同犯错；投票或相互认可不能代替外部证据。

建议结合不同来源核验、确定性计算及独立评价过程，避免验证被研究方的结论引导。
计算结果和评价记录也应带来源与版本；不自动引入新的总控“大脑”或更多 Agent。

## 4. 建议的第一条验证路径

1. 选择一个市场、对象范围和可解释的机会假设。例如检验“多源证据支持的基本面变化
   是否存在持续一段时间的价格反应”；这只是待证伪问题，不是已发现的策略。
2. Team 提供候选对象及可检验假设；Single 保存后续观测、动作建议及未行动原因。
3. 建立独立评估账本，按版本保存全部实验、事前判断、模拟结果、成本、基准及失败原因，
   不只保留成功案例。具体数据结构与工具待设计。
4. 在可比信息时点和风险条件下比较简单基线与 Super-link，分别考察新增研究、宏观过滤
   和旁路带来的收益、错误减少、时延与费用；避免将所有差异笼统归因于多 Agent。
5. 达到事前约定的证据要求后再讨论扩大范围；缺乏增量价值时，修改假设或缩减流程，
   不依靠增加 Agent 数量掩盖结果。

建议同时观察工程可靠性、研究质量、策略表现和运行经济性，分别解释失效原因。只有
工程通过不能证明策略有效；单次盈利也不能证明工程和研究方法可靠。

## 5. 需要后续明确的事项

- 市场、对象范围、假设类型、观察周期、比较基准及适用成本口径。
- 历史资料的时点可得性、模型训练污染风险及前瞻记录方式。
- 试验登记、全部尝试记录、版本变更、对照、样本相关性和证据要求。
- 验证模块与 Team、Single、旁路之间的接口及记录归属。
- 信号时效、队列延迟和策略调整频率的适配。
- 如未来涉及实际资金，共同账户事实、组合风险与授权执行范围。
- 采用、扩大、暂停、修改和淘汰策略的判断方式；允许没有可执行策略。

本轮仅回填讨论和参考依据，没有实施回测、影子运行、账户控制或实盘试验，也没有
获得收益验证结果。来源支持的是各自研究或工程方法，本项目中的迁移与应用仍需验证。
