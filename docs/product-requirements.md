## 2. 产品目标与边界

FrontierAgent 投研工作台面向个人投资者与投研人员，支持他们围绕一个持续主题进行多轮研究，观察并干预 Agent 执行，从原始资料和市场数据取证，最后得到可下载、可追溯、可复核的报告或策略卡。

产品必须同时满足四个结果：

1. **研究可连续**：研究、消息和运行的关系稳定，多轮上下文不会因页面刷新或运行重启丢失。
2. **过程可控制**：用户能看到运行状态，并能停止、补充方向、处理审批和恢复文件变更。
3. **结论可追溯**：数字与关键事实回到逐字原文或明确的市场调用、时点和口径。
4. **未知可表达**：无数据、数据源故障和不可比较是三种不同结果，系统不得用模型猜测补齐。

当前不把平台定义成自动交易系统。它不下单、不托管资金，也不承诺收益；所有输出均为研究性推演。

### 2.1 研究材料、数据与分析的职责（2026-09-13 用户确认）

| 层次 | 来源与职责 | 禁止混用 |
|---|---|---|
| 研究材料层 | 研报、电话会议、交流纪要、个人交易及复盘；理解观点、论据、视角、条件、风险和行为归属 | 材料数字不能自动成为数据层实际值；作者解释不等于已证明因果 |
| 数据层 | 用户提供/确认的同花顺接口；取得政府统计、行情等结构化观测并执行受控数据计算 | 接口故障不得由材料数字静默填补；实时价格不伪装成历史价格 |
| 分析层 | 按研究问题选用前两层，比较观点、检验论据、关联数据并产生系统分析 | 不覆盖作者原论据；不把系统归纳写成作者原话或供应商事实 |

三者是职责区分，不要求新建三套基础设施或物理数据库。既有证据、版本和取证机制复用，
但来源类别、计算输入和输出归属必须分明。没有接口数据时，仍可完成有出处的材料理解；
没有研报时，也可按数据覆盖完成数据分析。跨层比较是可选用途，不是所有材料的准入条件。

研报中的数字仍需忠实保存，用于解释作者论据；已有来源限定的财务复算属于材料内部一致性核对，
不是数据层的独立统计或行情事实。今后不以“把研报宏观数字接入数据计算主链”作为项目总目标。
M2 官网逐条复核/真实网页验收暂缓，已有实现保留，不构成继续研究材料工作的前置。
同花顺既有行情/历史/财务工具可复用；政府宏观端点、权限、实时性及历史版本覆盖尚需专项确认，
本次需求更新不表示已接通全部政府数据，不采购接口、不重新验证凭据。

### 2.2 当前阶段范围收缩（2026-09-14 用户确认）

本阶段以**公司、行业、宏观三类分析师研报**为主要数据清洗与材料理解对象；包括其中的深度、
专题、点评、周报及书面问答研报。研究领域与材料类型分别判断，不能把纪要标成 industry 后放行。

- 电话会议、会议/交流纪要、业绩会实录不进入本阶段默认清洗、模型抽取、重建活动索引及业务验收。
  这是范围排除，不是删除用户源文档、改写历史结果或宣告该类资料无价值。
- 行业“十问十答”仍可属于研报；标题出现“会议”或正文引用发言不构成整篇排除理由。
  对话实录、混合材料及类型不确定项列入人工准入复核，不静默归入主类目。
- 个人交易、复盘、独立市场评论及其他材料暂不作为主线清洗交付对象；保留已有资料和必要兼容
  回归，不再追加这些类别的模型优化预算。这是本实施方案的默认交付边界，可由后续用户明确调整。
- 本阶段先打通 CLI；Web 后续接入与政府数据官网逐条复核继续暂缓。材料数字仍是来源论据，
  不自动成为供应商观测；已有取证和限定财务复算能力必须保留。

PR-DATA-10 的纪要/个人行为扩展及验收场景 14—15 转为后续范围，不作为本阶段三类研报的共同
放行门。PR-DATA-01/02/09/12、PR-OUT-06/07 在上述缩减范围内继续有效；不能因此宣称完整 R2、
Web 或跨层分析已验收。旧冻结契约保留历史，不追溯改分；下一次试验先冻结新范围与验收契约。

本节优先于本文及旧专项文档中关于近期材料范围、Web 优先级和旧兼容永久保留的表述。
实验数据库和妨碍目标的旧实现可按确切对象重整，保护的是原文追溯、归属与未知表达、取证和计算
能力，不要求全部旧表/旧入口永久不变。具体实施见
[三类研报清洗与 R2 收口方案](plan/research-report-cleaning-scope-plan.md)，当前进度仅在
[统一执行计划](plan/claims-market-closed-loop-plan.md)维护。本次只更新需求与计划，准入过滤尚未落地。

## 3. 核心业务模型

```text
用户
  └─ 研究（Session，持续主题）
       ├─ 消息（Turn 表中的单条 user / assistant 记录）
       └─ 研究回合
            └─ 运行（Run，一条用户指令触发一次）
                 ├─ 输入文件
                 ├─ 实时事件 + 可回放轨迹
                 ├─ 控制与审批
                 ├─ 文件变更
                 └─ 产物
```

关键约束：

- “研究”不是项目或团队空间；当前没有 Project、Tag、Member 领域对象。
- 一条 `turns` 记录是一条消息；“一问一答”是研究回合，不是单条 Turn。
- Run 是执行与审计边界。运行状态、模型快照、用量、轨迹、输入和产物均须归属于该 Run。
- Claim 是离线语料治理对象；当前不能把 Claim 已落库等同于用户运行已能完成“预期 vs 实际”。
- 投资计划不是聊天消息；计划买入价、总资金、风险预算、仓位上限和持有时间窗必须以结构化数据保存。
- 计划买入价、实际成交均价与 Agent 建议价是不同事实，不得共用一个无来源字段或相互覆盖。

统一术语见根目录 [CONTEXT.md](../CONTEXT.md)。

## 5. 端到端业务流程

当前用户可达的通用流程是：

```text
注册/登录 → 配置并预检 LLM → 创建研究 → 提交问题/附件
→ Run 排队与隔离执行 → SSE 查看过程 → 停止/补充方向/审批
→ 最终回答 + 轨迹 + 产物 + 文件变更 → 历史回看/下载/回滚
```

目标投研闭环是：

```text
确认研究问题与用途 → 收集并冻结本次投资约束快照 → 按需探测必要来源覆盖
→ 材料链：语境取证 → 观点/论据/视角及归属、条件、风险
→ 数据链：同花顺结构化观测 → 口径与时点核对 → 确定性计算
→ 分析层：分别引用、按需关联或比较，标明系统分析及限制
→ 材料理解报告 / 数据分析报告 / 综合研究报告；策略卡仅在适用时生成
→ 对应证据及计算校验 → 人工验收/复盘 → 经确认的问题回到对应环节修复
```

两条流程不能混为“均已完成”。第一条已具备；第二条当前只完成了数据源、Claim、基础工具和部分校验，Web 暴露、三态覆盖、精确市场证据与可比较层仍待闭合。详细分支见
[business-process.md](business-process.md)。

## 6. 业务规则

### 6.1 证据纪律

1. 检索只定位；引用必须回到逐字原文或可验证的市场调用。
2. 每个关键数字保留原始表述、单位、来源和适用时点；`null` 不得转成 `0`。
3. 预测、事实陈述、观点、前值及行为状态不得混用；模型摘要可以作为标注归属的派生产物，不得冒充原始证据。
4. 历史判断只允许使用决策时点已经可知的信息，财报以披露日而非报告期末判断是否可用。
5. 算术和市场衍生指标由确定性工具计算并可重算，不能由 LLM 心算后仅补一个 `computed_by` 标签。
6. 材料日期、发言/行为日期、预测目标期间分别保留；缺少精确时点不阻止普通材料理解，但不允许声称支持事件回测。
7. 论据关联以来源表达为依据；系统提出的联系必须单独标为推断。否定、条件、反方观点及失效条件不可在裁切或摘要中丢失。
8. 抽取忠实度与来源内容真伪分开；观点有出处不表示观点正确，个人声称成交不表示系统核验了成交。

### 6.2 覆盖与降级

| 状态 | 含义 | 允许行为 |
|---|---|---|
| `available` | 来源已验证且有足够数据 | 使用该来源，并保留证据与时点 |
| `absent` | 来源已成功查询并确认无数据 | 转向其他来源；必要来源均 absent 时输出“数据不足” |
| `unknown` | 故障、超时、无权限或覆盖未验证 | 报告“覆盖未验证”并给出重试/补数路径，不得写成“没有数据” |

### 6.3 判断依据

每份策略卡或重要结论必须声明实际依据：

| `judgment_basis` | 最低证据 | 不得宣称 |
|---|---|---|
| `analyst_forecast` | 可比较的预测 Claim + 实际观测 | 无 |
| `market_facts` | 公司财务事实 + 行情/估值或确定性统计 | 机构预测、市场一致预期 |
| `industry_context` | 公司市场事实 + 行业/宏观证据 | 公司盈利预测、目标价 |
| `model_scenario` | 可追溯输入 + 受控公式和参数 | 券商预测、市场一致预期 |
| `insufficient_data` | 必要来源均为 `absent` | 倾向性判断 |
| `coverage_unverified` | 关键来源为 `unknown` 且替代证据不足 | “确定无数据”、倾向性判断 |

## 7. 交付优先级

### P0：闭合当前产品基线

1. 修正 Web profile 的金融工具暴露并做 owner/run 隔离的真实端到端验证。
2. 建立结构化投资输入、Run 快照与 `investment_context` 注入，先解决必填数值和事实来源，再让 Agent 推理。
3. 将市场 service、缓存、熔断和 trace 收口到单 Run 上下文，以逻辑调用 ID 精确验证 evidence。
4. 将覆盖探测升级为 `available/absent/unknown`，不再把故障折叠为 `none`。
5. 保持 EvidenceRun 单一正式入口与旧记录只读兼容；材料和数据分工必须先于新的跨层计算或发布。

### P1：形成可比较、可复盘的投研闭环

1. 当前优先冻结包含观点、论据、视角、问答与行为状态的材料样本和最小输出，补齐材料理解链路。
2. 数据链复用既有同花顺工具；按用户接口资料确认政府宏观覆盖，再按用途实现确定性计算。
3. 两层分别验收后，交付受控比较、不可比较原因，以及明确标注的综合分析。
4. 将真实 Run 产物的对应证据、算术和 schema 校验接入发布门禁；用量页、导出与留存治理仍按既有平台计划推进。

### P2：规模化与协作

项目与标签、团队权限、全局研究搜索、跨会话运行中心、按 Run 选模型/工作流、SSO 和计费在 P0/P1 稳定后再进入范围。

## 8. 验收场景

1. 两个用户分别登录后，任何研究、Run、轨迹、附件和产物都无法跨用户枚举或下载。
2. 错误模型连接能在预检阶段给出脱敏、可操作的失败；修正后 Run 快照与实际连接一致。
3. 同一研究连续提交两次时严格串行，第二次获得历史消息；不同研究受 worker 池并行。
4. 页面重载或 SSE 断线后能按游标恢复，并以 Run 终态与持久化消息纠正临时增量。
5. 停止、插话、审批和回滚均显示服务端确认结果；终态冲突不显示假成功。
6. 纯文本、附件、产物预览和下载均受大小、类型与目录边界保护。
7. Web Run 能通过真实工具注册链调用语料、市场与策略工具，而不只是直接构造 service 的测试通过。
8. 数据源超时被标为 `unknown`；已成功查询但无数据才标为 `absent`。
9. 任一市场证据只能解析到本 Run 的指定逻辑调用；错误 ID、跨 Run 或篡改 quote 必须失败。
10. 单位、期间、指标或可知时点不一致的预测与实际返回“不可比较原因”，不输出猜测差值。
11. 策略卡的仓位和市场统计可由相同输入重算，关键数字均可回到证据。
12. 所有界面与产物含固定免责声明，且不会触发交易执行。
13. 无数字但包含有价值解释、条件和风险的材料可产出忠实摘要；不得为满足数值字段编造数字。
14. 电话会议提问不变成管理层承诺，转述保留原表达者；未知发言者不猜姓名。
15. “准备买入”不变成“已买入”，事后复盘不倒填成当时理由，不因记录交易就触发交易执行。
16. 作者明确的视角与系统归纳的视角分别标记；没有证据的观点—数字关系不得写成作者论证。
17. 接口值与材料值不一致时保留双方原值、期间和版本；不能静默替换或把差异直接断言为作者错误。
18. 材料理解、数据计算和综合分析分别报告验收；接口故障不阻断不依赖该接口的材料阅读任务。
19. 用户提交计划买入价和仓位约束后，数据先持久化再启动 Run；回放同一 Run 使用同一版本快照，后续修改产生新版本而不静默改写历史。
20. Web 真实 Run 完整调用 `data_coverage → corpus_search → corpus_fetch`，最终 `evidence.quote` 在取回原文中逐字命中；关闭资料库时不得出现 corpus 工具调用或研报引用。
